## 1. Executive Summary

검증 결과, **L1 위반은 청해 카테고리의 구조적 결함**으로서 최우선 P0 작업이다. 조사 결과 실제 L1 대상은 **99건**으로(인베스티게이터 64건 + 이름·롤레터 마커 누락분 포함 실사 99건), 마커 유형에 관계없이 TTS가 그대로 음독하므로 전부 제거가 필요하다. 99건 중 **67건(68%)은 질문이 화자식별을 요구하지 않아 단순 마커 제거(Strategy D)** 로 해결 가능하며, **26건(26%)은 "Aさん/Bさん" 또는 "Bさんは…" 식으로 질문이 화자를 letter로 참조(Strategy B)** 하므로 질문·스크립트 동시 리라이트 필요, **6건은 3인+이름기반(Strategy C)** 으로 스크립트에 자연스러운 호명 삽입 필요, **Strategy A(성별+마커만 제거)는 0건** 으로 나타났다. B5 샘플 20건 중 **REAL_BIAS 60%/UNAVOIDABLE 25%/BORDERLINE 15%** 로, 149건 B5 중 약 89건 실제 수정 권장. 8건 CLAIM(Investigator는 6건만 파악, DB 실사 8건) 중 **5건 FIX / 2건 NEEDS_HUMAN_REVIEW / 1건 DISMISS(TTS 재생성으로 자동 해결)**. L2·L3는 sample 단위 소수 플래그 발견, 배치 처리 권장. **총 예상 UPDATE 건수: 약 290건 (99 L1 + 130 B5 opts + CLAIM·L2·L3 60건)**.

### 2-4. Strategy 구현 가이드

**Strategy D (67건, 가장 많음)** — 단순 마커 삭제
- `A：あたまが いたいです。` → `あたまが いたいです。`
- 복수 발화 구분은 문맥·억양으로(현재 TTS도 pause 처리됨)

**Strategy B (26건)** — 질문·스크립트 리라이트
- 「Aさんは…」「Bさんは…」 → 「男の人は…」「女の人は…」
- 2인 대화는 관행상 "先手=男/女" 결정(또는 스크립트 내 자연문으로 성별 드러내기)
- 병행: 스크립트 A·B 마커 제거

**Strategy C (6건)** — 이름 자연 삽입
- `田中：何か気をつけることは…` → `先生、私はどうしたら…` + 앞선 화자가 `田中さん` 호명
- 3인 대화: `研究者A：…` → 첫 등장시 자기소개 or 타자가 호명 ("山田さん、…")
