# 종합시험 문제 품질 Rubric

**버전**: Draft v1 (2026-04-05)
**목적**: 4개 도메인 종합시험(生活日本語/ビジネス日本語/CS知識/開発実務) 문제·선택지 품질을 일관된 기준으로 감사·개선하기 위한 공통 Rubric.
**적용 대상**: `quiz_questions` + `quiz_question_options` 의 모든 레코드 (DB 직접 조회 결과 기준).
**권한 범위**: 본 Rubric 기반 수정은 **UPDATE만** 허용. 문제 수량/ID/difficulty/category 불변.

## A. 문제 본문 (question_text) 기준

### A1. 학습목표 범위 준수
- **원칙**: 문제가 요구하는 지식은 해당 카테고리/lesson의 학습 범위 내에 한정되어야 함.
- **근거**: `docs/cs-comprehensive-overhaul-instruction.md:69-74`, `docs/cs-question-review-sheet.md:34`
- **판정 방법**: 범위 밖 세부 암기·하드웨어 트리비아·실무 외 지식 요구 여부 확인.
- **위반 예**: N5 문법 카테고리 문제가 N2 어휘 지식 없이 풀 수 없음 / 네트워크 기초 문제가 특정 벤더 장비 모델명 요구 / 비즈니스 일본어에 일본어를 읽어서 푸는 문제가 아닌 기술지식이 없으면 풀 수 없는 문제가 있음음 

### A2. 답안 누설 금지
- **원칙**: 문제 본문에 정답 선택지의 핵심 키워드가 그대로 포함되지 않아야 함.
- **근거**: `supabase/migrations/00084_fix_grammar_reading_quality.sql` 수정 패턴
- **판정 방법**: 본문 토큰과 각 선택지 토큰 교집합 검사. 정답 선택지만 높은 유사도면 위반.
- **위반 예**: 본문 "HTTPSは暗号化通信です。HTTPSの用途は？" + 정답 "暗号化された通信".

- **⚠️ 예외 (A2-exempt)**: 다음 유형의 문제는 본문-정답 겹침이 **문제 구조상 필연적**이므로 답안누설 아님:

  | 유형 | 판별 패턴 (본문에 포함) | 예시 |
  |------|------------------------|------|
  | **활용형 문제** | `〜形`, `活用`, `〜て形`, `〜た形`, `ます形`, `辞書形`, `受身`, `使役`, `可能形`, `命令形`, `意向形`, `仮定形` | 「食べる」の丁寧形は？ → 「食べます」 |
  | **변환 문제** | `〜に変える`, `〜に変換`, `〜に直す`, `言い換え` | 「行く」を尊敬語に変えると？ → 「いらっしゃる」 |
  | **경어 변환** | `尊敬語`, `謙譲語`, `丁寧語`, `敬語に` | 「する」の謙譲語は？ → 「いたす」 |
  | **읽기/한자** | `読み方`, `ふりがな`, `漢字`, `読み` | 「食事」の読み方は？ → 「しょくじ」 |
  | **의미/유의/반의** | `意味`, `類義語`, `対義語`, `反対語`, `同じ意味`, `近い意味` | 「美しい」の類義語は？ → 「綺麗」 |
  | **괄호 빈칸 채우기 (助詞/語彙)** | 본문에 `（　）` 또는 `＿＿` 있음 + 나머지 문장 문맥 제공 | 「私はコーヒー（　）飲みます」→「を」 |
  | **문형 변환** | `〜に直しなさい`, `〜にしなさい`, `書き換え` | 次の文を受身に書き換えなさい |

- **판정 로직 (자동 감지 시)**:
  1. 본문에 A2-exempt 키워드 패턴이 포함되어 있으면 A2 검사 **스킵**
  2. **빈칸 문제 + 구조 분리 판정**: question_text를 `「」`로 quote 문장 vs question 프레임 분리
     - **정답이 question 프레임에 등장** → **진짜 A2 위반** (예: `「...（　）がある。」傾向を表す正しいものは？` + 정답 "傾向")
     - **정답이 quote 문장에만 등장** → 복합어 체크:
       - 빈칸 직전 1~2자 + 정답 조합이 본문 다른 곳에 실재하면 위반 (예: `予想（　）` + 본문 다른 곳에 `予想通り`)
       - 없으면 **우연적 중첩(coincidental)** → A2-exempt (예: 정답 `通り` + 본문 `予定通り` 은 다른 복합어)
  3. 예외 적용 여부는 리포트에 `A2-exempt: <유형>` 또는 `A2-exempt: coincidental` 로 명시

- **유지되는 A2 위반 패턴**:
  - 독해/청해에서 본문에 직접 정답 문장이 쓰여 있는 경우
  - 어휘 의미를 묻지만 본문에 정답 단어의 뜻풀이가 그대로 나온 경우
  - 보기 중 정답만 본문 핵심 명사와 독점적으로 겹치는 경우
  - 빈칸문제에서 정답이 question 프레임(지시문)에 언급된 경우

### A3. 단일 정답 보장
- **원칙**: 문맥상 정답으로 성립 가능한 선택지는 정확히 1개.
- **근거**: `docs/cs-question-review-sheet.md` 재작성 원칙
- **판정 방법**: 각 오답을 "이 선택지가 정답이 되는 맥락이 존재하는가" 검사.
- **위반 예**: "日本の首都は？" 에 「東京」「東京都」가 모두 정답인 경우.

## B. 선택지 (quiz_question_options) 기준

### B4. 오답지 학습범위 내 구성
- **원칙**: 오답 선택지도 해당 lesson의 학습 범위 내 개념을 사용.
- **근거**: `docs/cs-question-review-sheet.md:34` — "distractors stay lesson-bounded"
- **위반 예**: 변수/상수 단원 문제의 오답으로 "Java 제네릭 와일드카드" 등장.

### B5. 선택지 길이 균등
- **원칙**: 정답 선택지가 최장/최단이 아니어야 함. 이상 목표: 전 선택지 길이가 평균의 ±20% 이내.
- **근거**: `supabase/migrations/00095_fix_option_length_bias.sql`, `00096_fix_bj_pattern_expression_length_bias.sql`
- **판정 방법**: 4개 선택지 글자수 측정 → max/min 비율이 1.5배 초과 시 Medium 이슈.
- **위반 예**: 정답 "顧客に丁寧な言葉遣いで説明を行うことが重要です" (26자) + 오답 3개 (6~10자).

### B6. 선택지 상호 배타
- **원칙**: 선택지 간 동의어, 포함관계, 슬래시(/) 병기 금지.
- **근거**: `supabase/migrations/00085_fix_vocab_quiz_ambiguous_options.sql`, `00091_vocab_option_slash_cleanup.sql`
- **위반 예**:
  - 동의어: 「すぐに」 vs 「即座に」
  - 포함관계: 「プログラム」 vs 「コンピュータプログラム」
  - 슬래시: 「はい/ええ」

### B7. 4지선다 + 정답 위치 랜덤
- **원칙**: 선택지는 정확히 4개, 정답 1개. 정답 위치는 런타임 셔플되므로 sort_order 고정 가능.
- **근거**: `docs/content_strategy.md:112`
- **위반 예**: 3지선다 / 5지선다 / 복수정답.

### B8. 선택지 언어 일관성
- **원칙**: 일본어 퀴즈는 전 선택지 일본어. 한국어 혼재 금지. (Phase 5-E 기준 이후 표준)
- **근거**: MEMORY.md Phase 5-E (커밋 7827cc8)
- **위반 예**: JLPT 문법 문제 선택지에 한국어 "~입니다" 병기.

## C. 해설 (explanation) 기준

### C9. 해설 필수 + 언어 기준
- **원칙**: 모든 문제는 해설 필수. 일본어로 작성하며 문법·어휘 보충 포함.
- **근거**: `docs/content_strategy.md:113`
- **권장 길이**: 최소 1문장 (30자 이상).
- **위반 예**: explanation 필드 NULL / 공백 / "정답은 2번".

## L. 청해(listening) 전용 기준 ★ 추가 (2026-04-05)

> ⚠️ 청해 카테고리 문제는 TTS로 음성화되므로 일반 Rubric 외에 **음성 전환 품질**을 추가 검토.
> 유저 클레임 사례: (1) 화자 식별 불가 (2) TTS 한자 오독

### L1. 화자 식별성
- **원칙**: 화자 식별은 **질문 포맷**으로 해결. 스크립트 본문에는 절대 `A：`, `B：`, `男：`, `女：` 같은 **마커 금지** (TTS가 그대로 읽어버림).
- **구분 규칙**:
  - **2인 대화**: 질문이 `女の人は何と言いましたか？` / `男の人は最後に何と言いましたか？` 식으로 성별 명시
  - **3인 이상 + 화자 식별 요구**: 스크립트 내에서 **이름 언급**으로 구분 (예: `田中さん、今日の会議は…` / `山田さんの意見も聞きたいんですが…`)
  - **3인 이상 + 화자 식별 불요**: 이름 언급 불필요
- **위반 예**:
  - 스크립트에 `A：今日は暑いですね。 B：そうですね。` → TTS가 "에이" "비" 를 읽음
  - 3인 대화에서 이름 언급 없이 "男の人は何と言いましたか？" 라고 물음 → 어느 男인지 불명
- **수정 방향**:
  - 2인: 스크립트에서 마커 제거 + 질문에 `女の人は/男の人は` 명시
  - 3인+화자식별: 스크립트에 이름 자연스럽게 삽입 (호칭/호명 형태)

### L2. TTS 한자 적합성
- **원칙**: TTS 엔진이 오독 위험 있는 한자는 히라가나로 치환하거나 문맥으로 읽기 보강.
- **판정 방법**: 동음이의어 한자 및 다독 한자 블랙리스트 기반 감지.
- **오독 패턴**:
  - `行く` (いく vs おこなう) / `生` (せい/なま/いき/き) / `上` (うえ/じょう/あ/のぼ) / `下` (した/げ/お/くだ)
  - `日` (ひ/にち/じつ/か) / `人` (ひと/じん/にん) / `一人` (ひとり) — 숫자+人 조합
  - 고유명사 읽기 오류
- **수정 방향**: 오독 위험 한자를 히라가나로 치환 (예: `行きました` → `いきました`)

### L3. 청취 난이도 적정성
- **원칙**: 한 발화가 과도하게 길면 청취 중 집중력 분산. 난이도별 문장 길이 제한 권장.
- **기준 (권장)**:
  - N5/N4: 한 발화당 30자 이내
  - N3: 50자 이내
  - N2/N1: 80자 이내
- **위반 예**: N5 청해 문제에 100자 긴 단일 문장

## D. 거버넌스 규칙 (문제 텍스트 외 메타데이터)

> ⚠️ 본 개선 프로젝트 범위는 **UPDATE만 허용**이므로 D 항목은 **감지 및 리포트만** 하고 수정은 별도 마이그레이션으로 처리.

### D-a. 난이도 명시 필수
- **원칙**: difficulty 컬럼 NULL 금지. 도메인별 값 체계 준수.
  - Step1 (JLPT): N5 / N4 / N3 / N2 / N1
  - Step2 (BJ): 初級 / 中級 / 上級
  - Step3 (CS), Step4 (Dev): easy / medium / hard
- **근거**: `docs/cs-question-governance-spec.md:44-49`, MEMORY.md Phase 5-E

### D-b. 카테고리 매핑 고정
- **원칙**: category 컬럼은 도메인별 정의된 enum 값만 사용.
  - Step1: grammar / reading / listening
  - Step2: vocabulary / sentence_pattern / business_expression / keigo / reading
  - Step3: algorithm / data_structure / basic_theory / computer_architecture / database / network / os / security
  - Step4 Java: java / spring_boot / sql
  - Step4 JS: javascript / react / sql
- **근거**: `docs/cs-comprehensive-overhaul-instruction.md:19-27`, `src/lib/assessment-config.ts`

## 자동 감지 가능한 이슈 (정량 기준)

Investigator 에이전트가 DB 조회 후 자동 플래그:

| 항목 | 자동 감지 규칙 |
|------|----------------|
| B5 길이편향 | `max(length) / min(length) > 1.5` 또는 정답이 `max` / `min` |
| B6 슬래시 | `option_text LIKE '%/%'` |
| B8 언어혼재 | 일본어 퀴즈에서 한글(AC00-D7A3) 유니코드 포함 |

| D-a 난이도 NULL | `difficulty IS NULL` |
| Claim | `question_claims.question_id` JOIN 매치 |
| A2 답안누설 | 정답 `option_text`의 2-gram 중 question_text 포함 비율 > 50% **AND** 본문에 A2-exempt 패턴 없음 (활용형/변환/경어/읽기/유의반의/문형변환 키워드) |
