## 1. 機能概要

### 1.1 目的

登録済み利用者が、メールアドレスとパスワードを入力してシステムへ認証ログインするための画面である。本システムは**招待制（Invite-only）**であり、利用者自身による新規登録（サインアップ）機能は提供しない。アカウントは管理者が発行する。

### 1.2 業務範囲

| No | 業務 | 対応可否 |
|---|---|---|
| 1 | メールアドレス／パスワードによるログイン認証 | ○ |
| 2 | パスワードリセット（リカバリーリンクからの遷移） | ○ |
| 3 | 認証済みユーザーの自動リダイレクト | ○ |
| 4 | 新規利用者登録（セルフサインアップ） | ×（管理者が発行） |
| 5 | ソーシャルログイン（OAuth等） | ×（対象外） |

### 1.3 対象利用者（ロール）

| ロール | 説明 |
|---|---|
| admin | 管理者。アカウント発行・コンテンツ管理・全社員照会 |
| mentor | メンター。学習状況照会・コードレビュー・フィードバック |
| mentee | 受講者。学習・試験受験・本人の点数／ランキング確認 |

※ ログイン画面自体は全ロール共通。ログイン成功後の遷移先・権限はロールにより制御される（後述ミドルウェアにて）。

            ┌─────────────────────────────────┼─────────────────────────────┐

## 5. メッセージ定義

| No | メッセージID | 区分 | メッセージ内容 | 発生条件 |
|---|---|---|---|---|
| 1 | MSG-AUTH-E01 | エラー | 有効なメールアドレスを入力してください | メールアドレス形式不正（Zod検証） |
| 2 | MSG-AUTH-E02 | エラー | パスワードは6文字以上必要です | パスワードが6文字未満（Zod検証） |
| 3 | MSG-AUTH-E03 | エラー | メールアドレスまたはパスワードが正しくありません | 認証失敗（Supabase Auth エラー） |
| 4 | MSG-AUTH-I01 | 情報 | ログイン中... | ログイン処理実行中（ボタンラベル） |

※ セキュリティ上、認証失敗時はメール・パスワードのどちらが誤りかを区別しない統一メッセージとする。

## 6. 処理概要

### 6.1 ログイン処理フロー（業務観点）

```
利用者                ログイン画面            サーバ（認証）
  │  メール/PW入力        │                       │
  │─────────────────────►│                       │
  │  「ログイン」押下      │                       │
  │─────────────────────►│ 入力値検証             │
  │                      │──────────────────────►│ メール形式/PW長 検証
  │                      │                       │ NG→エラー返却
  │                      │◄──────────────────────│
  │                      │ Supabase認証要求       │
  │                      │──────────────────────►│ 認証実行
  │                      │                       │ NG→エラー返却
  │                      │◄──────────────────────│
  │                      │ 成功→セッション確立     │
  │                      │ /dashboard へ遷移      │
  │◄─────────────────────│                       │
```

### 6.2 主要処理説明

| No | 処理 | 概要 |
|---|---|---|
| 1 | 入力検証 | メールアドレス形式・パスワード長（6文字以上）をサーバ側で検証 |
| 2 | 認証 | Supabase Auth（メール＋パスワード）で認証 |
| 3 | セッション確立 | 認証成功時、セッションCookieを発行しレイアウトを再検証 |
| 4 | リダイレクト | `/dashboard` へ遷移。未オンボーディング時はミドルウェアが `/onboarding` へ再誘導 |
| 5 | リカバリー検知 | URLハッシュに `type=recovery` を含む場合、`/reset-password` へ即時遷移 |

## 7. 非機能要件

| 項目 | 要件 |
|---|---|
| 認証方式 | Supabase Auth（JWT＋HTTP-Only Cookie によるセッション管理） |
| セキュリティ | パスワードはマスク入力。認証失敗メッセージは情報を区別しない。CSRF対策はServer Action標準機構に準拠 |
| アクセス制御 | ミドルウェアにて未認証ユーザーを全保護ページからログイン画面へ強制リダイレクト |
| ブラウザ対応 | モダンブラウザ（Chrome/Edge/Safari/Firefox 最新） |
| 多言語 | UI文言は日本語固定 |
| 可用性 | Supabase 認証基盤の可用性に準拠 |
