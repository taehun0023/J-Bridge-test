### 2.2 依存関係図

```
AuthLayout (背景・中央配置)
   └─ LoginPage (Client)
         ├─ useState: error, loading
         ├─ useEffect: recovery hash 検知
         └─ form action ──► signIn (Server Action)
                               ├─ loginSchema.safeParse()
                               ├─ createClient() ──► Supabase Auth
                               │     └─ signInWithPassword()
                               ├─ revalidatePath('/', 'layout')
                               └─ redirect('/dashboard')

middleware ──► 全リクエストをインターセプト
   ├─ supabase.auth.getUser()
   ├─ 未認証 → /login へ redirect
   ├─ 認証済 & authページ → /dashboard へ redirect
   ├─ 未オンボーディング → /onboarding へ redirect
   └─ RBAC（/admin, /ranking）
```

## 3. 画面コンポーネント詳細（LoginPage）

### 3.1 状態（State）定義

| No | 変数名 | 型 | 初期値 | 用途 |
|---|---|---|---|---|
| 1 | `error` | `string \| null` | `null` | エラーメッセージ保持・表示制御 |
| 2 | `loading` | `boolean` | `false` | 送信中フラグ。ボタン非活性／ラベル切替 |

### 3.2 ライフサイクル処理（useEffect）

**目的：** パスワードリカバリーリンク経由のアクセスを検知し、リセット画面へ転送する。

```
処理: recovery ハッシュ検知（マウント時1回）
─────────────────────────────────────────
1. window.location.hash を取得
2. ハッシュが存在し、かつ "type=recovery" を含むか判定
3. 含む場合:
   - window.location.href = '/reset-password' + hash
   - （ハッシュ部を保持したまま遷移し、reset-password側の
      Supabaseクライアントが #access_token を処理できるようにする）
4. 含まない場合: 何もしない
```

> 設計意図：Supabase のリカバリーメールリンクは `/login#...type=recovery&access_token=...` の形式で着地するため、ログイン画面で検知してハッシュ付きでリセット画面へ橋渡しする。

### 3.3 イベント処理（handleSubmit）

```
処理: handleSubmit(formData: FormData)
─────────────────────────────────────────
1. loading ← true
2. error  ← null
3. signIn(formData) を await 実行
4. 戻り値判定:
   - result?.error が存在する場合（認証/検証失敗）:
       error   ← result.error
       loading ← false
       （※成功時はServer Action内でredirectされるため
          本関数に制御は戻らない）
```

> 補足：`signIn` は成功時に `redirect('/dashboard')` を実行するため、成功ケースでは戻り値が返らず `setLoading(false)` も呼ばれない（画面遷移により破棄）。失敗時のみ戻り値で制御。

### 3.4 描画仕様（主要 DOM 構造）

| 要素 | 属性 | 値・備考 |
|---|---|---|
| `<form>` | `action` | `handleSubmit`（React 19 form action） |
| `<input id="email">` | `type` / `required` | `email` / 必須 |
| `<input id="password">` | `type` / `required` | `password` / 必須 |
| エラー `<p>` | 条件 | `error &&` で条件描画。`text-red-400` |
| `<button type="submit">` | `disabled` | `loading` 時 `true`。ラベルは三項演算で切替 |

## 4. サーバアクション詳細（signIn）

### 4.1 シグネチャ

| 項目 | 内容 |
|---|---|
| 関数名 | `signIn` |
| ディレクティブ | `'use server'` |
| 引数 | `formData: FormData` |
| 戻り値 | `{ error: string }`（失敗時）／ 成功時は `redirect` により返却なし |

### 4.2 処理フロー

```
処理: signIn(formData)
─────────────────────────────────────────
1. createClient() で Supabase サーバクライアント生成
   （CookieStore 経由でセッション読み書き）

2. 入力値抽出・検証
   loginSchema.safeParse({
     email:    formData.get('email'),
     password: formData.get('password'),
   })
   ├─ 検証NG（parsed.success === false）:
   │     return { error: parsed.error.issues[0].message }
   │     （先頭エラーメッセージのみ返却）
   └─ 検証OK: parsed.data を後続へ

3. 認証実行
   supabase.auth.signInWithPassword(parsed.data)
   ├─ エラーあり:
   │     return { error: 'メールアドレスまたはパスワードが正しくありません' }
   │     （※Supabaseの詳細エラーは秘匿し、統一文言を返す）
   └─ 成功: セッションCookie発行

4. revalidatePath('/', 'layout')
   （レイアウト全体のキャッシュを無効化し、認証状態を反映）

5. redirect('/dashboard')
   （ダッシュボードへサーバサイドリダイレクト）
```

### 4.3 入力検証仕様（loginSchema）

| フィールド | ルール | 違反時メッセージ |
|---|---|---|
| `email` | `z.string().email()` | 有効なメールアドレスを入力してください |
| `password` | `z.string().min(6)` | パスワードは6文字以上必要です |

```typescript
export const loginSchema = z.object({
  email: z.string().email('有効なメールアドレスを入力してください'),
  password: z.string().min(6, 'パスワードは6文字以上必要です'),
})
```

## 5. 認証ガード詳細（middleware）

### 5.1 適用範囲（matcher）

静的アセット（`_next/static`, `_next/image`, `favicon.ico`, 画像ファイル）を除く全リクエストに適用。

```
matcher: '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)'
```

### 5.2 処理ロジック

```
処理: middleware(request)
─────────────────────────────────────────
1. Supabaseクライアント生成（Cookieのget/setをリクエストへ紐付け）
2. user ← supabase.auth.getUser()
3. 判定フラグ算出:
   - isAuthPage  = path が /login | /signup | /reset-password で開始
   - isApiRoute  = path が /api/ で開始

【ガード①：未認証ブロック】
4. if (!user && !isAuthPage && !isApiRoute && !path.startsWith('/auth'))
      → /login へリダイレクト

【ガード②：認証済みの認証ページ回避】
5. if (user && isAuthPage)
      → /dashboard へリダイレクト

【ガード③：オンボーディング誘導 ＆ RBAC】
6. if (user && !isAuthPage && !isOnboardingPage):
      profiles から is_onboarded, role を取得
      a. is_onboarded === false → /onboarding へリダイレクト
      b. RBAC（/ranking）:
           role === 'mentee' → /dashboard へリダイレクト
      c. RBAC（/admin）:
           - /admin/users|courses|mentors → admin のみ許可
           - /admin/tasks|reports        → admin + mentor 許可（mentee不可）
           - その他 /admin/*              → admin のみ許可
           違反時 → /dashboard へリダイレクト

7. return supabaseResponse（更新済みCookie付与）
```

> 注意：middleware では `getUser()` を使用（`getSession()` ではない）。`getUser()` はトークンをSupabaseサーバで検証するため、Cookie改ざんに対し安全。

## 6. 認証コールバック詳細（/auth/callback）

| 項目 | 内容 |
|---|---|
| メソッド | `GET` |
| 用途 | メールリンク／OAuthの認可コードをセッションへ交換 |

```
処理: GET(request)
─────────────────────────────────────────
1. URLから code, next（既定 '/dashboard'）を取得
2. code が存在する場合:
   - createClient()
   - supabase.auth.exchangeCodeForSession(code)
   - エラー無し → ${origin}${next} へリダイレクト
3. 失敗時 → /login?error=auth_failed へリダイレクト
```

## 8. 例外・エラー処理一覧

| No | 発生箇所 | 条件 | 処理 | 利用者への表示 |
|---|---|---|---|---|
| 1 | signIn / Zod | メール形式不正 | `{ error }` 返却 | 有効なメールアドレスを入力してください |
| 2 | signIn / Zod | パスワード6文字未満 | `{ error }` 返却 | パスワードは6文字以上必要です |
| 3 | signIn / Supabase | 認証失敗（資格情報誤り） | 統一文言を `{ error }` 返却 | メールアドレスまたはパスワードが正しくありません |
| 4 | callback | コード交換失敗 | `/login?error=auth_failed` | （ログイン画面へ戻る） |
| 5 | LoginPage | 送信処理中 | `loading=true`、二重送信防止（ボタン非活性） | ログイン中... |

> セキュリティ方針：認証失敗（No.3）はアカウント存在有無・パスワード誤りを区別しない統一メッセージとし、列挙攻撃（user enumeration）を防止する。
