## 1) 요점 정리 (5줄)

- **GROUP BY**는 지정한 열의 값이 같은 행을 그룹으로 묶어, 집약 함수와 조합하여 집계를 수행한다.
- 복수 열을 GROUP BY에 지정하면, 모든 열 값의 조합 단위로 그룹이 생성된다.
- **HAVING**은 GROUP BY 이후의 그룹에 대한 조건 필터링이며, WHERE와는 평가 시점이 다르다.
- WHERE는 행 레벨, HAVING은 그룹 레벨의 필터이다. WHERE에는 집약 함수를 사용할 수 없다.
- GROUP BY와 JOIN을 조합하면, 결합 후 데이터에 대한 집계 분석이 가능해진다.

## 2) 개념

### GROUP BY의 기본

✅ 결론: GROUP BY는 "같은 값을 가진 행을 묶어 하나의 행으로 만드는" 구문이다.

GROUP BY를 사용하는 경우, SELECT 절에는 **GROUP BY에 지정한 열** 또는 **집약 함수(COUNT, SUM, AVG, MIN, MAX)** 만 기술할 수 있다. 이것은 ANSI SQL 규칙이며, 위반 시 오류가 발생한다.

```sql
-- 부서별 직원 수
SELECT department_id, COUNT(*) AS emp_count
FROM employees
GROUP BY department_id;
```

| department_id | emp_count |
|---|---|
| 1 | 5 |
| 2 | 3 |
| 3 | 7 |

### 복수 열의 GROUP BY

2개 이상의 열을 GROUP BY에 지정하면, **모든 열 값의 조합** 마다 그룹이 형성된다.

```sql
SELECT department_id, city, COUNT(*) AS cnt
FROM employees
GROUP BY department_id, city;
```

이 경우 `department_id = 1, city = 'Tokyo'`와 `department_id = 1, city = 'Osaka'`는 별도의 그룹이 된다.

### HAVING 절 — 그룹에 대한 조건

✅ 결론: HAVING은 그룹화 이후의 결과에 대해 조건을 지정하는 절이며, 집약 함수를 조건에 사용할 수 있는 유일한 위치이다.

```sql
SELECT department_id, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 50000;
```

### WHERE와 HAVING의 차이

SQL의 **논리적 평가 순서**를 이해하면, 두 가지의 차이가 명확해진다.

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
```

| 항목 | WHERE | HAVING |
|---|---|---|
| 대상 | 개별 행 | 그룹 |
| 평가 시점 | GROUP BY 전 | GROUP BY 후 |
| 집약 함수 | 사용 불가 | 사용 가능 |

```sql
-- WHERE와 HAVING의 병용
SELECT department_id, SUM(salary) AS total_salary
FROM employees
WHERE hire_date >= '2023-01-01'     -- 행 필터
GROUP BY department_id
HAVING SUM(salary) > 100000;        -- 그룹 필터
```

이 예제에서는 먼저 WHERE로 2023년 이후 입사 직원만 필터링하고, 그 후 GROUP BY로 그룹화한 뒤, HAVING으로 합계 급여가 10만을 초과하는 부서만 남긴다.

### GROUP BY와 JOIN의 조합

✅ 결론: JOIN으로 테이블을 결합한 후 GROUP BY로 집계하면, 다른 테이블의 열 이름을 표시하면서 집계 결과를 얻을 수 있다.

```sql
SELECT d.name AS dept_name, COUNT(e.id) AS emp_count, AVG(e.salary) AS avg_salary
FROM departments d
JOIN employees e ON d.id = e.department_id
GROUP BY d.name;
```

JOIN + GROUP BY는 실무에서 가장 자주 사용되는 패턴 중 하나이다.

### COUNT(*)와 COUNT(열이름)의 차이

- `COUNT(*)`는 그룹 내 **전체 행 수**를 반환한다(NULL 포함).
- `COUNT(열이름)`은 해당 열이 **NULL이 아닌 행의 수**를 반환한다.

```sql
SELECT department_id,
       COUNT(*) AS total_rows,
       COUNT(email) AS has_email
FROM employees
GROUP BY department_id;
```

## 3) 예제 (2개)

### 예제 1: 고객별 주문 분석

도시별로 고객 수와 평균 주문 금액을 구하고, 고객 수가 2명 이상인 도시만 표시한다.

```sql
SELECT c.city,
       COUNT(DISTINCT c.id) AS customer_count,
       AVG(o.total_amount) AS avg_order_amount
FROM customers c
JOIN orders o ON c.id = o.customer_id
GROUP BY c.city
HAVING COUNT(DISTINCT c.id) >= 2
ORDER BY avg_order_amount DESC;
```

포인트: `COUNT(DISTINCT c.id)`를 사용하면, 같은 고객이 여러 번 주문해도 중복 카운트되지 않는다.

### 예제 2: 상품 카테고리별 매출 집계

카테고리별 총 매출액과 평균 단가를 구하고, 총 매출액이 상위인 카테고리를 표시한다.

```sql
SELECT p.category,
       SUM(oi.quantity * oi.unit_price) AS total_revenue,
       AVG(p.price) AS avg_price,
       COUNT(DISTINCT o.id) AS order_count
FROM products p
JOIN order_items oi ON p.id = oi.product_id
JOIN orders o ON oi.order_id = o.id
GROUP BY p.category
HAVING SUM(oi.quantity * oi.unit_price) > 10000
ORDER BY total_revenue DESC;
```

포인트: 3개 테이블을 결합하고, GROUP BY와 HAVING으로 집계와 필터링을 동시에 수행하고 있다.

## 4) 흔한 실수 / 함정 (5개)

⚠️ **실수 1**: SELECT에 GROUP BY 대상이 아닌 비집약 열을 작성함
→ **대책**: SELECT 절에는 GROUP BY에 포함한 열 또는 집약 함수만 기술한다.

⚠️ **실수 2**: WHERE 절에 집약 함수를 작성하여 오류 발생 (예: `WHERE COUNT(*) > 3`)
→ **대책**: 집약 함수의 조건은 HAVING 절에 작성한다. WHERE는 GROUP BY보다 먼저 평가되므로 집약 함수를 사용할 수 없다.

⚠️ **실수 3**: COUNT(*)와 COUNT(열이름)을 혼동하여 NULL을 포함하는 행의 카운트가 어긋남
→ **대책**: NULL을 포함하려면 `COUNT(*)`, NULL을 제외하려면 `COUNT(열이름)`을 구분하여 사용한다.

⚠️ **실수 4**: HAVING과 WHERE의 사용 구분을 잘못하여 성능이 저하됨
→ **대책**: 행 레벨에서 필터링 가능한 조건은 WHERE에 작성하여, 초기 단계에서 데이터를 줄여 그룹화 부하를 낮춘다.

⚠️ **실수 5**: JOIN + GROUP BY에서 의도치 않은 행 증가(중복)를 인지하지 못함
→ **대책**: JOIN 결과의 행 수를 사전에 확인하고, 필요에 따라 `COUNT(DISTINCT ...)`을 사용한다.

## 5) 체크리스트

- [ ] GROUP BY에 지정한 열 이외가 SELECT에 포함되어 있지 않은지 확인했다
- [ ] 집약 함수의 조건은 WHERE가 아닌 HAVING에 작성하고 있다
- [ ] COUNT(*)와 COUNT(열이름)의 차이를 이해하고, 용도에 맞게 구분하여 사용하고 있다
- [ ] WHERE와 HAVING의 평가 순서를 이해하고 있다
- [ ] JOIN + GROUP BY에서 중복 행이 발생하지 않는지 확인했다
- [ ] ORDER BY로 집계 결과의 정렬을 지정하고 있다
