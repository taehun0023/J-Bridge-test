## 1) 要点まとめ（5行）

- **SELECT** 句で取得したい列を指定し、**FROM** 句でデータソースとなるテーブルを指定する。
- `SELECT *` は全列取得の省略記法だが、本番コードでは列名を明示的に書くのが推奨される。
- **AS** キーワードで列に別名（alias）を付けると、結果セットのヘッダーが分かりやすくなる。
- **DISTINCT** は SELECT の直後に置き、結果セットから重複行を除去する。
- SQL のキーワードは大文字・小文字を区別しないが、大文字で書く慣例が広く使われている。

## 2) 概念

### SELECT 文の基本構造

✅ 結論: SQL でデータを取得するには、最低限 `SELECT` と `FROM` の 2 つの句が必要である。

SQL（Structured Query Language）は、リレーショナルデータベースを操作するための標準言語である。データを「問い合わせる」（クエリする）際に最も基本となるのが SELECT 文だ。

```sql
SELECT 列名1, 列名2, ...
FROM テーブル名;
```

この構文は「どのテーブルから（FROM）、どの列を（SELECT）取得するか」を宣言的に記述する。SQL はプログラミング言語のように「手順」を書くのではなく、「何が欲しいか」を記述する宣言型言語である。

| 句 | 役割 | 必須 |
|---|---|---|
| SELECT | 取得する列を指定 | はい |
| FROM | データソースのテーブルを指定 | はい |

### 全列取得（SELECT *）

✅ 結論: `SELECT *` は手軽だが、本番環境では必要な列のみ指定するべきである。

```sql
SELECT * FROM employees;
```

`*`（アスタリスク）は「テーブルの全列」を意味する。開発中の探索やデバッグには便利だが、以下の理由から本番コードでは避けるべきである。

1. テーブルに列が追加されると、予期しないデータが返される。
2. 不要な列のデータ転送でパフォーマンスが低下する。
3. コードの可読性が下がり、どの列を使っているか分かりにくい。

### 列の指定

✅ 結論: 必要な列だけをカンマ区切りで指定すると、効率的で保守しやすいクエリになる。

```sql
SELECT name, salary, hire_date
FROM employees;
```

SELECT 句にはカンマ（,）で区切って複数の列を並べられる。列の順序はテーブル定義の順序と一致する必要はなく、自由に指定できる。

### 列別名（AS）

✅ 結論: AS で列に分かりやすい別名を付けると、結果セットの可読性が向上する。

```sql
SELECT name AS 社員名, salary AS 月給
FROM employees;
```

AS キーワードは省略可能で、以下のように書くこともできる。

```sql
SELECT name 社員名, salary 月給
FROM employees;
```

ただし、可読性の観点から AS を明記する方が推奨される。別名にスペースや予約語を含める場合は、二重引用符で囲む必要がある。

```sql
SELECT name AS "Employee Name"
FROM employees;
```

| 記法 | 例 | 備考 |
|---|---|---|
| AS あり | `salary AS monthly_pay` | 推奨 |
| AS 省略 | `salary monthly_pay` | 省略可能 |
| 二重引用符 | `salary AS "Monthly Pay"` | スペースを含む場合 |

### DISTINCT — 重複行の除去

✅ 結論: DISTINCT は SELECT 句で指定した全列の組み合わせに対して重複判定を行い、一意な行のみ返す。

```sql
SELECT DISTINCT department_id
FROM employees;
```

DISTINCT は SELECT の直後に 1 回だけ記述する。複数列を指定した場合は、それら全列の値の「組み合わせ」で重複を判定する。

```sql
-- department_id と salary の組み合わせで重複を判定
SELECT DISTINCT department_id, salary
FROM employees;
```

DISTINCT は内部的にソートやハッシュ処理を行うため、大量データに対してはパフォーマンスコストがある点に注意する。

### SQL 文の書き方の慣例

SQL キーワード（SELECT、FROM、AS、DISTINCT など）は大文字・小文字を区別しない。以下は全て同じ結果を返す。

```sql
SELECT name FROM employees;
select name from employees;
Select Name From Employees;
```

ただし、業界の慣例として「キーワードは大文字、テーブル名・列名は小文字」で書くことが多い。また、文の末尾にはセミコロン（`;`）を付けるのが標準である。

## 3) 例（2つ）

### 例1: 社員の名前と給与を別名付きで取得する

```sql
SELECT
    name   AS employee_name,
    salary AS monthly_salary
FROM employees;
```

| employee_name | monthly_salary |
|---|---|
| 田中太郎 | 450000 |
| 佐藤花子 | 380000 |
| 鈴木一郎 | 520000 |

この例では、`name` 列に `employee_name`、`salary` 列に `monthly_salary` という別名を付けている。元のテーブルのスキーマは変更されず、結果セットの表示名だけが変わる。

### 例2: 部署 ID の一覧を重複なしで取得する

```sql
SELECT DISTINCT department_id
FROM employees;
```

| department_id |
|---|
| 1 |
| 2 |
| 3 |

社員テーブルには複数の社員が同じ部署に所属しているが、DISTINCT を使うことで部署 ID の一覧を一意に取得できる。部署テーブルがない状況でも、どの部署が存在するかを調べる際に便利なテクニックである。

## 4) よくあるミス／落とし穴（5つ）

⚠️ **ミス1**: `SELECT * FROM` を本番コードに使う → **対策**: 必要な列名を明示的に列挙する。テーブル変更時の影響範囲が明確になる。

⚠️ **ミス2**: 列別名にスペースを含むのに引用符を付けない → **対策**: `AS "Column Name"` のように二重引用符で囲む。

⚠️ **ミス3**: DISTINCT を列ごとに書こうとする（`SELECT DISTINCT name, DISTINCT salary`） → **対策**: DISTINCT は SELECT の直後に 1 回のみ記述する。全列の組み合わせに適用される。

⚠️ **ミス4**: SQL 文の末尾にセミコロンを忘れる → **対策**: 習慣としてセミコロンを必ず付ける。複数文を実行する場合は必須。

⚠️ **ミス5**: 大量データに対して意味なく DISTINCT を付ける → **対策**: 本当に重複除去が必要か確認してから使う。不要な DISTINCT はパフォーマンスを低下させる。
