## 1) 要点まとめ（5行）

- 集約関数（**COUNT**, **SUM**, **AVG**, **MIN**, **MAX**）は複数行の値を 1 つの結果に集約する。
- **COUNT(*)** は NULL を含む全行を数え、**COUNT(列名)** は NULL を除いた行数を返す。
- **GROUP BY** で指定した列の値ごとにグループを作り、各グループに集約関数を適用する。
- **HAVING** は GROUP BY で作ったグループに対する条件フィルタであり、集約結果に条件を付ける。
- SQL の論理処理順序は FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY である。

## 2) 概念

### 集約関数とは

✅ 結論: 集約関数は複数の行を入力として受け取り、1 つの値を返す関数である。

リレーショナルデータベースの強みの 1 つは、大量のデータから統計情報を即座に得られることだ。集約関数（aggregate functions）を使えば、合計・平均・最大値・最小値・件数をクエリ 1 つで計算できる。

| 関数 | 説明 | NULL の扱い |
|---|---|---|
| `COUNT(*)` | 全行数 | NULL を含む |
| `COUNT(列)` | 指定列が NULL でない行数 | NULL を除外 |
| `SUM(列)` | 合計 | NULL を無視 |
| `AVG(列)` | 平均 | NULL を無視 |
| `MIN(列)` | 最小値 | NULL を無視 |
| `MAX(列)` | 最大値 | NULL を無視 |

### COUNT — 行数を数える

✅ 結論: COUNT(*) と COUNT(列名) は NULL の扱いが異なるため、目的に応じて使い分ける。

```sql
-- 全社員数（NULL 関係なく全行カウント）
SELECT COUNT(*) AS total_employees
FROM employees;

-- メールアドレスが設定されている社員数
SELECT COUNT(email) AS has_email
FROM employees;
```

`COUNT(*)` はテーブルの全行数を返す。一方、`COUNT(email)` は email 列が NULL でない行のみカウントする。

```sql
-- 両者を並べて比較
SELECT
    COUNT(*)     AS total_rows,
    COUNT(email) AS non_null_email
FROM employees;
```

| total_rows | non_null_email |
|---|---|
| 10 | 8 |

上記の場合、2 名の社員のメールアドレスが NULL であることが分かる。

### SUM と AVG — 合計と平均

✅ 結論: SUM と AVG は数値型の列に対して使い、NULL 値は計算から除外される。

```sql
SELECT
    SUM(salary) AS total_salary,
    AVG(salary) AS avg_salary
FROM employees;
```

| total_salary | avg_salary |
|---|---|
| 4200000 | 420000 |

**AVG と NULL の注意点**: AVG は NULL を分母にも分子にも含めない。例えば 10 行中 2 行が NULL の場合、AVG は 8 行分の合計を 8 で割る（10 で割るのではない）。

```sql
-- 例: salary が [300000, 400000, NULL, 500000] の場合
-- AVG = (300000 + 400000 + 500000) / 3 = 400000
-- NULL 行は分母からも除外される
```

### MIN と MAX — 最小値と最大値

✅ 結論: MIN と MAX は数値だけでなく、文字列や日付にも使える。

```sql
-- 数値の MIN / MAX
SELECT
    MIN(salary) AS min_salary,
    MAX(salary) AS max_salary
FROM employees;

-- 日付の MIN / MAX
SELECT
    MIN(hire_date) AS earliest_hire,
    MAX(hire_date) AS latest_hire
FROM employees;
```

文字列の場合はアルファベット順（照合順序に依存）で比較される。

### GROUP BY — グループ化

✅ 結論: GROUP BY は指定列の値が同じ行をグループ化し、グループごとに集約関数を適用する。

```sql
SELECT department_id, COUNT(*) AS emp_count, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id;
```

| department_id | emp_count | avg_salary |
|---|---|---|
| 1 | 3 | 456667 |
| 2 | 4 | 387500 |
| 3 | 3 | 410000 |

**重要なルール**: GROUP BY を使う場合、SELECT 句には以下のいずれかしか記述できない。

1. GROUP BY で指定した列
2. 集約関数

```sql
-- NG: name は GROUP BY に含まれず、集約関数でもない
SELECT department_id, name, COUNT(*)
FROM employees
GROUP BY department_id;
-- → エラー（DBMS によっては不定の値を返す場合もある）

-- OK: GROUP BY の列と集約関数のみ
SELECT department_id, COUNT(*), MAX(name)
FROM employees
GROUP BY department_id;
```

### HAVING — グループへの条件フィルタ

✅ 結論: HAVING は集約結果に対するフィルタであり、WHERE（行レベル）とは対象が異なる。

```sql
-- 社員数が 3 人以上の部署のみ
SELECT department_id, COUNT(*) AS emp_count
FROM employees
GROUP BY department_id
HAVING COUNT(*) >= 3;
```

| WHERE と HAVING の違い |
|---|

| 句 | フィルタ対象 | 集約関数の使用 | 評価タイミング |
|---|---|---|---|
| WHERE | 個々の行 | 不可 | GROUP BY の前 |
| HAVING | グループ | 可能 | GROUP BY の後 |

```sql
-- WHERE + GROUP BY + HAVING の組み合わせ
SELECT department_id, COUNT(*) AS emp_count, AVG(salary) AS avg_salary
FROM employees
WHERE hire_date >= '2022-01-01'     -- ① 行レベルフィルタ
GROUP BY department_id              -- ② グループ化
HAVING AVG(salary) >= 400000        -- ③ グループフィルタ
ORDER BY avg_salary DESC;           -- ④ ソート
```

上記の処理順序は:
1. FROM: employees テーブルを読み込む
2. WHERE: 2022 年以降入社の社員に絞る
3. GROUP BY: 部署ごとにグループ化
4. HAVING: 平均給与 40 万以上のグループに絞る
5. SELECT: 列と集約結果を計算
6. ORDER BY: 平均給与の降順で並び替え

### COUNT(DISTINCT)

✅ 結論: 集約関数内で DISTINCT を使うと、重複を除いた値に対して集約が行われる。

```sql
-- 何種類の部署があるか
SELECT COUNT(DISTINCT department_id) AS dept_count
FROM employees;
```

## 3) 例（2つ）

### 例1: 部署別の統計情報を取得する

```sql
SELECT
    department_id,
    COUNT(*)       AS emp_count,
    SUM(salary)    AS total_salary,
    AVG(salary)    AS avg_salary,
    MIN(salary)    AS min_salary,
    MAX(salary)    AS max_salary
FROM employees
GROUP BY department_id
ORDER BY avg_salary DESC;
```

| department_id | emp_count | total_salary | avg_salary | min_salary | max_salary |
|---|---|---|---|---|---|
| 1 | 3 | 1370000 | 456667 | 350000 | 520000 |
| 3 | 3 | 1230000 | 410000 | 370000 | 450000 |
| 2 | 4 | 1550000 | 387500 | 300000 | 480000 |

全 5 つの集約関数を部署別に適用した例。GROUP BY で部署ごとにグループ化し、ORDER BY で平均給与の降順に並べている。

### 例2: HAVING で条件を付けた集計

```sql
SELECT
    department_id,
    COUNT(*) AS emp_count,
    AVG(salary) AS avg_salary
FROM employees
WHERE salary >= 300000
GROUP BY department_id
HAVING COUNT(*) >= 2
ORDER BY emp_count DESC;
```

| department_id | emp_count | avg_salary |
|---|---|---|
| 2 | 3 | 420000 |
| 1 | 3 | 456667 |

WHERE で給与 30 万以上の社員に絞った後、部署ごとにグループ化し、HAVING で 2 名以上の部署のみを残している。

## 4) よくあるミス／落とし穴（5つ）

⚠️ **ミス1**: COUNT(*) と COUNT(列名) の違いを理解していない → **対策**: COUNT(*) は全行、COUNT(列名) は NULL を除いた行数。目的に応じて使い分ける。

⚠️ **ミス2**: GROUP BY に含まない非集約列を SELECT に書く → **対策**: SELECT 句には GROUP BY の列か集約関数だけを書く。

⚠️ **ミス3**: WHERE 句で集約関数を使おうとする → **対策**: 集約結果に条件を付けるには HAVING を使う。WHERE は GROUP BY の前に評価される。

⚠️ **ミス4**: AVG の NULL 除外を忘れて平均値がずれる → **対策**: NULL を 0 として計算したい場合は COALESCE(列, 0) を使ってから AVG を適用する。

⚠️ **ミス5**: GROUP BY の処理順序を誤解する → **対策**: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY の順序を覚える。
