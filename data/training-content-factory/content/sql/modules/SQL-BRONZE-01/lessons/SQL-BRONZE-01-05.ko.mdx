## 1) 요점 정리 (5줄)

- **JOIN**은 여러 테이블을 결합 조건에 기반하여 하나의 결과 세트로 합치는 SQL 기능이다.
- **INNER JOIN**은 양쪽 테이블에서 조건에 일치하는 행만 반환한다. 일치하지 않는 행은 결과에 포함되지 않는다.
- **LEFT JOIN**은 왼쪽 테이블의 모든 행을 반환하며, 오른쪽 테이블에 일치가 없으면 NULL로 채운다.
- **ON** 절에서 결합 조건(보통은 기본키와 외래키의 등가 비교)을 지정한다.
- 테이블 별칭(alias)을 사용하면 여러 테이블의 열을 간결하게 참조할 수 있고, 쿼리의 가독성이 향상된다.

## 2) 개념

### JOIN이 필요한 이유

✅ 결론: 관계형 데이터베이스에서는 데이터를 여러 테이블에 정규화하여 저장하므로, JOIN으로 관련 데이터를 결합하여 조회해야 한다.

관계형 데이터베이스 설계에서는 데이터의 중복을 피하기 위해 테이블을 분리한다(정규화). 예를 들어, 사원 테이블에 부서명을 직접 갖지 않고, 부서 테이블을 별도로 생성하여 `department_id`로 연관시킨다.

```
employees 테이블            departments 테이블
+----+--------+----+      +----+--------+--------+
| id | name   |d_id|      | id | name   |location|
+----+--------+----+      +----+--------+--------+
|  1 | 田中   |  1 |      |  1 | 開発部 | 東京   |
|  2 | 佐藤   |  2 |      |  2 | 営業部 | 大阪   |
|  3 | 鈴木   |  1 |      |  3 | 人事部 | 東京   |
+----+--------+----+      +----+--------+--------+
```

"田中 씨는 어느 부서?"를 알기 위해서는, 양쪽 테이블을 `department_id`로 결합해야 한다.

### JOIN의 기본 구문

✅ 결론: JOIN은 FROM 절 안에서 테이블끼리 결합하며, ON 절에서 결합 조건을 지정한다.

```sql
SELECT 열이름
FROM 테이블A
JOIN 테이블B ON 테이블A.열 = 테이블B.열;
```

### INNER JOIN — 일치하는 행만

✅ 결론: INNER JOIN은 양쪽 테이블에서 결합 조건을 만족하는 행의 조합만 반환한다.

```sql
SELECT e.name, d.name AS department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;
```

| name | department_name |
|---|---|
| 田中太郎 | 開発部 |
| 佐藤花子 | 営業部 |
| 鈴木一郎 | 開発部 |

INNER JOIN의 동작을 그림으로 나타내면:

```
employees                departments
+------+------+          +------+------+
| 田中 | d=1  |---+  +---| id=1 | 開発 |
| 佐藤 | d=2  |---+--+---| id=2 | 営業 |
| 鈴木 | d=1  |---+  |   | id=3 | 人事 |
| 木村 | d=99 |  (불일치) +------+------+
+------+------+

결과: 田中-開発, 佐藤-営業, 鈴木-開発
(木村은 d=99에 일치하는 부서가 없으므로 제외)
(人事部는 소속 사원이 없으므로 제외)
```

`INNER` 키워드는 생략 가능하며, `JOIN`만으로도 INNER JOIN과 같은 동작을 한다.

```sql
-- 아래 두 쿼리는 동일
SELECT e.name, d.name FROM employees e JOIN departments d ON e.department_id = d.id;
SELECT e.name, d.name FROM employees e INNER JOIN departments d ON e.department_id = d.id;
```

### LEFT JOIN — 왼쪽 테이블 기준으로 결합

✅ 결론: LEFT JOIN은 왼쪽 테이블의 모든 행을 반드시 반환하며, 오른쪽 테이블에 일치가 없는 경우 NULL로 채운다.

```sql
SELECT e.name, d.name AS department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id;
```

| name | department_name |
|---|---|
| 田中太郎 | 開発部 |
| 佐藤花子 | 営業部 |
| 鈴木一郎 | 開発部 |
| 木村五郎 | NULL |

LEFT JOIN의 동작을 그림으로 나타내면:

```
employees (왼쪽)          departments (오른쪽)
+------+------+          +------+------+
| 田中 | d=1  |--------->| id=1 | 開発 |  ✓
| 佐藤 | d=2  |--------->| id=2 | 営業 |  ✓
| 鈴木 | d=1  |--------->| id=1 | 開発 |  ✓
| 木村 | d=99 |--> NULL  | id=3 | 人事 |
+------+------+          +------+------+

결과: 田中-開発, 佐藤-営業, 鈴木-開発, 木村-NULL
(木村은 오른쪽 테이블에 일치 없음 → NULL로 채움)
```

`LEFT JOIN`은 정식으로는 `LEFT OUTER JOIN`이라고 쓴다. `OUTER`는 생략 가능하다.

### LEFT JOIN으로 불일치 데이터 추출하기

✅ 결론: LEFT JOIN + WHERE 오른쪽 테이블 IS NULL로 "왼쪽에 있고 오른쪽에 없는 데이터"를 추출할 수 있다.

```sql
-- 유효한 부서에 소속되지 않은 사원 찾기
SELECT e.name, e.department_id
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id
WHERE d.id IS NULL;
```

| name | department_id |
|---|---|
| 木村五郎 | 99 |

이 패턴은 "고립 데이터" 탐지에 매우 유용하며, 데이터 품질 점검에 자주 사용된다.

### 테이블 별칭 (alias)

✅ 결론: 테이블 별칭을 사용하면 쿼리가 간결해지고, 동명 열의 모호성을 해소할 수 있다.

```sql
-- AS 있음 (생략 가능)
SELECT e.name, d.name AS department_name
FROM employees AS e
INNER JOIN departments AS d ON e.department_id = d.id;

-- AS 생략
SELECT e.name, d.name AS department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;
```

테이블 별칭을 사용하는 이유:
1. **간결함**: `employees.name`보다 `e.name`이 짧다.
2. **모호성 해소**: 양쪽 테이블에 `name` 열이 있는 경우, `e.name`과 `d.name`으로 구분한다.
3. **필수인 경우**: 같은 테이블을 2회 결합하는 경우(자기 결합).

동명 열을 별칭 없이 참조하면 "모호한 열 참조" 에러가 발생한다.

```sql
-- NG: name이 employees에도 departments에도 있어 모호
SELECT name FROM employees e JOIN departments d ON e.department_id = d.id;

-- OK: 테이블 별칭으로 수식
SELECT e.name FROM employees e JOIN departments d ON e.department_id = d.id;
```

### 3개 이상 테이블 결합

✅ 결론: JOIN을 연쇄적으로 기술하여, 3개 이상의 테이블을 결합할 수 있다.

```sql
SELECT
    e.name       AS employee_name,
    d.name       AS department_name,
    p.name       AS project_name,
    pa.role      AS project_role
FROM employees e
INNER JOIN departments d ON e.department_id = d.id
INNER JOIN project_assignments pa ON e.id = pa.employee_id
INNER JOIN projects p ON pa.project_id = p.id;
```

| employee_name | department_name | project_name | project_role |
|---|---|---|---|
| 田中太郎 | 開発部 | Webリニューアル | リーダー |
| 鈴木一郎 | 開発部 | Webリニューアル | メンバー |
| 佐藤花子 | 営業部 | 営業支援システム | メンバー |

이 예제에서는 4개의 테이블(employees, departments, project_assignments, projects)을 결합하고 있다. `project_assignments`는 사원과 프로젝트의 다대다 관계를 관리하는 중간 테이블이다.

### INNER JOIN과 LEFT JOIN의 사용 구분

| 상황 | 권장 JOIN |
|---|---|
| 양쪽 모두에 데이터가 있는 행만 필요 | INNER JOIN |
| 왼쪽 테이블의 모든 행을 유지하고 싶다 | LEFT JOIN |
| 불일치(고립) 데이터를 찾고 싶다 | LEFT JOIN + WHERE IS NULL |

RIGHT JOIN은 LEFT JOIN의 좌우를 바꾼 것과 동일하지만, 실무에서는 LEFT JOIN으로 통일하는 관습이 널리 보급되어 있다.

## 3) 예제 (2개)

### 예제 1: 사원과 그 부서 정보 조회하기 (불일치 포함)

```sql
SELECT
    e.id,
    e.name       AS employee_name,
    e.salary,
    d.name       AS department_name,
    d.location
FROM employees e
LEFT JOIN departments d ON e.department_id = d.id
ORDER BY e.id;
```

| id | employee_name | salary | department_name | location |
|---|---|---|---|---|
| 1 | 田中太郎 | 450000 | 開発部 | 東京 |
| 2 | 佐藤花子 | 380000 | 営業部 | 大阪 |
| 3 | 鈴木一郎 | 520000 | 開発部 | 東京 |
| 4 | 木村五郎 | 300000 | NULL | NULL |

LEFT JOIN을 사용하여, 유효한 부서에 소속되지 않은 木村五郎도 결과에 포함된다. INNER JOIN의 경우 木村五郎은 제외된다.

### 예제 2: 사원의 프로젝트 참가 현황 확인하기

```sql
SELECT
    e.name       AS employee_name,
    p.name       AS project_name,
    pa.role
FROM employees e
LEFT JOIN project_assignments pa ON e.id = pa.employee_id
LEFT JOIN projects p ON pa.project_id = p.id
ORDER BY e.name;
```

| employee_name | project_name | role |
|---|---|---|
| 佐藤花子 | 営業支援システム | メンバー |
| 鈴木一郎 | Webリニューアル | メンバー |
| 田中太郎 | Webリニューアル | リーダー |
| 木村五郎 | NULL | NULL |

LEFT JOIN을 2번 사용하여, 프로젝트에 참가하지 않은 木村五郎도 결과에 포함된다.

## 4) 흔한 실수 / 함정 (5개)

⚠️ **실수 1**: ON 절의 결합 조건을 잘못 지정하여 크로스 조인이 됨 → **대책**: ON 절에는 반드시 올바른 기본키/외래키의 등가 조건을 작성한다. ON을 빠뜨리면 구문 에러 또는 크로스 조인(모든 행의 조합)이 된다.

⚠️ **실수 2**: INNER JOIN과 LEFT JOIN을 혼동 → **대책**: "일치 데이터만 필요한가" "왼쪽 테이블의 모든 행이 필요한가"로 구분하여 사용한다.

⚠️ **실수 3**: 동명 열을 테이블명으로 수식하지 않음 → **대책**: JOIN 사용 시 모든 열을 테이블 별칭으로 수식하는 습관을 들인다.

⚠️ **실수 4**: LEFT JOIN 후 WHERE에서 오른쪽 테이블의 열을 조건으로 하여 INNER JOIN과 동일하게 됨 → **대책**: 오른쪽 테이블의 조건은 ON 절에 포함하거나, IS NULL 체크를 의도하는 경우에만 WHERE에 작성한다.

⚠️ **실수 5**: 결합을 너무 많이 늘려 쿼리가 복잡해짐 → **대책**: 테이블을 4개 이상 결합하는 경우에는 서브쿼리나 WITH 절(CTE)을 검토한다.
