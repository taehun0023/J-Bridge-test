## 1) 핵심 요약 (5줄)

1. **DML(Data Manipulation Language)**은 테이블 내 데이터를 조작하는 SQL 문의 총칭으로, INSERT / UPDATE / DELETE / SELECT가 포함된다. DDL과 달리 트랜잭션 내에서 실행되어 COMMIT / ROLLBACK으로 확정 및 취소가 가능하다.
2. **INSERT INTO ... VALUES**는 1행 또는 여러 행의 데이터를 명시적으로 삽입한다. 여러 행을 한 번에 기술하면 1행씩 INSERT하는 것보다 빠르다.
3. **UPDATE SET WHERE**는 조건에 일치하는 행의 열 값을 변경한다. WHERE 절을 생략하면 **전체 행이 갱신되므로** 운영 환경에서는 매우 위험하다.
4. **DELETE FROM WHERE**는 조건에 일치하는 행을 삭제한다. DELETE는 행 단위로 로그를 기록하므로 롤백 가능하지만 TRUNCATE보다 느리다.
5. **MERGE 문**(SQL:2003 표준)은 대상 테이블과 소스를 결합하여 일치 행은 UPDATE, 불일치 행은 INSERT를 수행하는 UPSERT 작업을 단일 문으로 실현한다. PostgreSQL에서는 INSERT ... ON CONFLICT DO UPDATE가 동일 기능을 제공한다.

## 2) 개념

### DML이란 무엇인가

DML은 SQL 중에서 테이블 내 **데이터 자체를 조작하는 문**의 총칭이다. DDL이 테이블의 구조(그릇)를 정의하는 것에 반해, DML은 그 그릇의 내용물을 조작한다.

중요한 특징으로, DML 문은 **트랜잭션 내에서 실행된다**. 즉, `BEGIN TRANSACTION`으로 시작하고 결과를 확인한 후 `COMMIT`(확정) 또는 `ROLLBACK`(취소)이 가능하다. 이는 DDL의 많은 부분이 자동 커밋되는 것과 대조적이다.

### INSERT -- 데이터 삽입

#### 기본적인 INSERT

```sql
-- 열 리스트를 명시하여 1행 삽입
INSERT INTO employees (id, name, department_id, salary, hire_date)
VALUES (11, 'Morimoto', 1, 620000, '2025-06-01');
```

열 리스트를 생략하면 테이블 정의의 모든 열에 데이터를 지정해야 한다. **항상 열 리스트를 명시해야 한다.** 열이 추가되었을 때, 열 리스트 없는 INSERT는 조용히 깨진다.

#### 복수 행 INSERT

```sql
INSERT INTO employees (id, name, department_id, salary, hire_date)
VALUES
    (11, 'Morimoto', 1, 620000, '2025-06-01'),
    (12, 'Fujita',   2, 580000, '2025-06-01'),
    (13, 'Ogawa',    3, 510000, '2025-06-15');
```

1행씩 INSERT하는 것보다 네트워크 왕복이 줄어 대폭 빨라진다. 대량 데이터의 배치 INSERT나 벌크 로드도 같은 이유로 권장된다.

#### INSERT INTO ... SELECT

```sql
-- 다른 테이블의 결과 세트를 그대로 삽입
INSERT INTO employee_archive (id, name, department_id, salary, hire_date)
SELECT id, name, department_id, salary, hire_date
FROM employees
WHERE hire_date < '2020-01-01';
```

열 수와 데이터 타입이 일치해야 한다. 테이블 간 데이터 이관이나 백업에 자주 사용된다.

### UPDATE -- 데이터 갱신

#### 기본적인 UPDATE

```sql
UPDATE employees
SET salary = 700000, job_title = 'Senior Engineer'
WHERE id = 2;
```

**WHERE 절을 생략하면 전체 행이 갱신된다.** 이것은 운영 환경에서 가장 위험한 실수 중 하나이다.

#### 서브쿼리를 사용한 UPDATE

다른 테이블의 값을 참조하여 갱신하는 "상관 서브쿼리 UPDATE"는 실무에서 자주 등장한다.

```sql
-- 각 부서의 평균 급여를 기준으로 급여를 조정
UPDATE employees e
SET salary = salary * 1.1
WHERE salary < (
    SELECT AVG(salary)
    FROM employees e2
    WHERE e2.department_id = e.department_id
);
```

### DELETE -- 데이터 삭제

```sql
-- 조건에 일치하는 행을 삭제
DELETE FROM employees
WHERE id = 13;
```

WHERE 절을 생략하면 **전체 행이 삭제된다**. DELETE는 행 단위로 트랜잭션 로그를 기록하므로 롤백 가능하지만, 대량 삭제는 느리다.

#### TRUNCATE TABLE과의 차이

```sql
-- 전체 행을 고속으로 삭제 (대부분의 RDBMS에서 롤백 불가)
TRUNCATE TABLE temp_data;
```

| 특징 | DELETE | TRUNCATE |
|---|---|---|
| WHERE 절 | 사용 가능 | 불가 (전체 행만) |
| 롤백 | 가능 | 대부분의 RDBMS에서 불가 |
| 트리거 | 발동함 | 발동하지 않음 |
| 속도 | 느림 (행 로그) | 빠름 (최소 로그) |

### MERGE -- UPSERT 작업

MERGE 문(SQL:2003 표준)은 대상 테이블과 소스를 결합하여 일치하는 행은 UPDATE, 일치하지 않는 행은 INSERT를 수행한다.

```sql
-- 표준 SQL의 MERGE
MERGE INTO products AS target
USING new_products AS source
ON target.id = source.id
WHEN MATCHED THEN
    UPDATE SET
        target.name = source.name,
        target.price = source.price
WHEN NOT MATCHED THEN
    INSERT (id, name, price)
    VALUES (source.id, source.name, source.price);
```

#### PostgreSQL의 UPSERT

PostgreSQL은 MERGE 대신 `INSERT ... ON CONFLICT DO UPDATE`를 제공한다.

```sql
INSERT INTO products (id, name, price)
VALUES (1, 'Widget', 1500)
ON CONFLICT (id) DO UPDATE
SET name = EXCLUDED.name,
    price = EXCLUDED.price;
```

`EXCLUDED`는 삽입하려 했던 행을 참조하는 특수한 테이블명이다. MySQL에서는 `INSERT ... ON DUPLICATE KEY UPDATE`가 동일한 기능을 수행한다.

### RETURNING 절

PostgreSQL이나 Oracle에서는 INSERT / UPDATE / DELETE의 결과 행을 즉시 반환할 수 있다.

```sql
-- 삽입한 행의 자동 생성 ID를 취득
INSERT INTO employees (name, department_id, salary, hire_date)
VALUES ('Morimoto', 1, 620000, '2025-06-01')
RETURNING id, name;

-- 갱신 전후의 급여를 반환
UPDATE employees
SET salary = salary * 1.1
WHERE department_id = 1
RETURNING id, name, salary;
```

애플리케이션 측에서 "INSERT 후 SELECT로 조회"라는 2회 왕복을 1회로 줄일 수 있어, 성능과 코드 간결성 양면에서 유익하다.

## 3) 예제

### 예제 1: 신입 사원 일괄 등록과 부서 이동

신년도에 입사한 3명을 일괄 등록하고, 기존 사원 1명을 이동시킨다.

```sql
-- 복수 행 INSERT로 일괄 등록
INSERT INTO employees (id, name, department_id, salary, hire_date, job_title)
VALUES
    (11, 'Morimoto', 1, 620000, '2025-04-01', 'Engineer'),
    (12, 'Fujita',   2, 580000, '2025-04-01', 'Sales Rep'),
    (13, 'Ogawa',    3, 510000, '2025-04-01', 'HR Staff');

-- 기존 사원의 부서 이동 (Engineering → Sales)
UPDATE employees
SET department_id = 2, job_title = 'Sales Engineer'
WHERE id = 3 AND department_id = 1;
```

UPDATE의 WHERE 절에 `department_id = 1`을 추가하여 이미 이동 완료된 경우의 중복 갱신을 방지하고 있다.

### 예제 2: 상품 테이블의 UPSERT와 재고 관리

외부 데이터 소스에서 상품 정보를 동기화한다. 기존 상품은 가격을 갱신하고, 신상품은 삽입한다.

```sql
-- PostgreSQL: INSERT ... ON CONFLICT를 이용한 UPSERT
INSERT INTO products (id, name, price, stock_quantity)
VALUES
    (101, 'Keyboard', 8500, 50),
    (102, 'Mouse', 3200, 100),
    (201, 'Monitor', 45000, 20)
ON CONFLICT (id) DO UPDATE
SET name = EXCLUDED.name,
    price = EXCLUDED.price,
    stock_quantity = products.stock_quantity + EXCLUDED.stock_quantity;

-- 재고 소진 상품을 삭제하고, 삭제된 상품명을 확인
DELETE FROM products
WHERE stock_quantity = 0
RETURNING id, name;
```

ON CONFLICT의 SET 절에서 `products.stock_quantity + EXCLUDED.stock_quantity`로 한 점에 주목하자. 기존 재고에 입고분을 더하는 비즈니스 로직을 SQL 1문으로 표현하고 있다.

## 4) 자주 하는 실수 / 함정 (5가지)

### 함정 1: UPDATE / DELETE에서 WHERE 절을 잊는 것

WHERE 절 없는 UPDATE는 전체 행을 갱신하고, DELETE는 전체 행을 삭제한다. 운영 환경에서 가장 심각한 데이터 사고의 원인이다. **먼저 SELECT로 대상 행을 확인한 후 UPDATE / DELETE로 변경하는 것**이 모범 사례이다.

```sql
-- 먼저 확인
SELECT * FROM employees WHERE department_id = 3;

-- 대상을 확인한 후 삭제
DELETE FROM employees WHERE department_id = 3;
```

### 함정 2: INSERT 시 열 리스트를 생략하는 것

열 리스트를 생략하면 테이블의 모든 열에 올바른 순서로 값을 지정해야 한다. 나중에 테이블에 열이 추가되면 기존 INSERT 문이 의도치 않은 열에 데이터를 넣거나 에러가 발생한다.

```sql
-- NG: 열 리스트 생략
INSERT INTO employees VALUES (11, 'Morimoto', 1, 620000, '2025-06-01', ...);

-- OK: 열 리스트 명시
INSERT INTO employees (id, name, department_id, salary, hire_date)
VALUES (11, 'Morimoto', 1, 620000, '2025-06-01');
```

### 함정 3: 대량 INSERT를 1행씩 실행하는 것

1행씩 INSERT하면 각 INSERT마다 네트워크 왕복, 파싱, 트랜잭션 로그 기록이 발생한다. **복수 행 INSERT나 벌크 로드를 사용**하면 성능이 대폭 개선된다.

### 함정 4: TRUNCATE를 DELETE와 같은 감각으로 사용하는 것

TRUNCATE는 빠르지만, 대부분의 RDBMS에서 롤백이 불가능하고 트리거도 발동하지 않는다. "나중에 ROLLBACK하면 되지"라고 생각하고 TRUNCATE를 사용하면 데이터가 완전히 사라진다.

### 함정 5: 트랜잭션 없이 UPDATE / DELETE를 실행하는 것

UPDATE / DELETE는 실행 전에 `BEGIN TRANSACTION`으로 명시적으로 트랜잭션을 시작하고, 결과를 확인한 후 `COMMIT`하는 것이 안전한 패턴이다. 자동 커밋 모드에서 잘못된 UPDATE를 실행하면 즉시 확정되어 버린다.

```sql
BEGIN TRANSACTION;
UPDATE employees SET salary = salary * 1.1 WHERE department_id = 1;
-- 결과를 확인
SELECT * FROM employees WHERE department_id = 1;
-- 문제 없으면 확정, 문제 있으면 취소
COMMIT;  -- 또는 ROLLBACK;
```
