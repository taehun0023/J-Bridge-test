## 1) 学習目標

- コールバックパターンの仕組みとコールバック地獄の問題点を説明できる。
- Promiseの3つの状態（pending, fulfilled, rejected）と遷移を説明できる。
- async/awaitの実行順序をイベントループの観点から追跡できる。
- 非同期処理のエラーハンドリングパターンを3つ使い分けられる。

## 2) 業務コンテキスト

Webアプリケーション開発では、API呼び出し、ファイル読み込み、データベースクエリなど非同期処理が頻繁に発生する。非同期処理の実行順序を正確に追跡できなければ、「なぜこのデータがundefinedになるのか」「なぜAPIレスポンスが処理される前にUIが更新されるのか」といった問題の原因を特定できない。実務プロジェクトではPromiseとasync/awaitが主流であり、既存コードを読む際に実行順序を正しく理解することが不可欠である。

## 3) 要点解説

### コールバックパターン

最も古い非同期パターン。関数を引数として渡し、処理完了時に呼び出す。

```javascript
function fetchUser(userId, callback) {
  setTimeout(() => {
    callback(null, { id: userId, name: "田中" });
  }, 1000);
}

fetchUser(1, (error, user) => {
  if (error) {
    console.error(error);
    return;
  }
  console.log(user.name);
});
```

問題点：ネストが深くなる（コールバック地獄）。エラーハンドリングが各コールバックに分散する。

### Promise

Promiseは非同期処理の結果を表すオブジェクトである。3つの状態を持つ。

- **pending**: 処理中
- **fulfilled**: 成功（`.then`で値を受け取る）
- **rejected**: 失敗（`.catch`でエラーを受け取る）

```javascript
function fetchUser(userId) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (userId <= 0) {
        reject(new Error("Invalid ID"));
      }
      resolve({ id: userId, name: "田中" });
    }, 1000);
  });
}

fetchUser(1)
  .then(user => console.log(user.name))
  .catch(error => console.error(error.message));
```

Promiseチェーンにより、ネストを避けてフラットに書ける。`.then`の戻り値が次の`.then`に渡される。

### async/await

async/awaitはPromiseの構文糖衣である。非同期処理を同期的な見た目で書ける。

```javascript
async function getUser(userId) {
  try {
    const user = await fetchUser(userId);
    console.log(user.name);
    return user;
  } catch (error) {
    console.error("取得失敗:", error.message);
    throw error;
  }
}
```

**重要な実行順序のルール:**

```javascript
console.log("1: 開始");

async function process() {
  console.log("2: async関数内、awaitの前");
  const result = await Promise.resolve("データ");
  console.log("4: awaitの後");
  return result;
}

process();
console.log("3: async関数呼び出し後");
```

出力順序は`1 → 2 → 3 → 4`である。`await`はその行で一旦制御を呼び出し元に返し、Promiseが解決した後にマイクロタスクとして残りを実行する。

### エラーハンドリングの比較

```javascript
// 1. Promiseチェーン
fetchData()
  .then(process)
  .catch(handleError);

// 2. async/await + try-catch
async function run() {
  try {
    const data = await fetchData();
    await process(data);
  } catch (error) {
    handleError(error);
  }
}

// 3. 個別のawaitでのエラー処理
async function run() {
  const data = await fetchData().catch(e => defaultData);
  await process(data);
}
```

## 4) 実務解釈シナリオ

### シナリオ A
```javascript
async function loadDashboard() {
  const [user, orders, notifications] = await Promise.all([
    fetchUser(),
    fetchOrders(),
    fetchNotifications()
  ]);
  renderDashboard(user, orders, notifications);
}
```
- 読み取りポイント:
  - `Promise.all`は3つのAPI呼び出しを並列に実行する。
  - すべてが完了するまで待ち、結果を分割代入で受け取る。
  - 1つでも失敗すると全体がrejectされる。独立して処理したい場合は`Promise.allSettled`を使う。

### シナリオ B
```javascript
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// 出力: A → D → C → B
```
- 解釈:
  - 同期コード（A, D）が先に実行される。
  - マイクロタスク（Promise.then → C）がマクロタスク（setTimeout → B）より優先される。
  - この順序を知らないと、非同期処理のタイミング問題を理解できない。

## 5) よくあるミス

1. `await`を付け忘れてPromiseオブジェクトそのものを使用する。
`const data = fetchUser()`とすると、`data`はPromiseオブジェクトであり、ユーザーデータではない。

2. async関数の戻り値が常にPromiseであることを忘れる。
`async function f() { return 1; }`の戻り値は`1`ではなく`Promise<1>`である。

3. `Promise.all`で1つの失敗が全体を止めることを考慮しない。
独立した処理には`Promise.allSettled`を検討すべき。

4. forループ内でawaitを直列実行してしまう。
`for (const id of ids) { await fetch(id); }`は1つずつ順次実行される。並列化するなら`Promise.all(ids.map(id => fetch(id)))`を使う。

5. catchを付けないPromiseの拒否がUnhandled Rejectionになる。
Node.jsではプロセスが終了する原因になる。

## 7) 出題抽出メモ

- 事実型候補: Promiseの3状態、マイクロタスク vs マクロタスクの優先順位
- 判断型候補: Promise.all vs Promise.allSettled の選択、直列 vs 並列の判断
- シナリオ型候補: console.logの出力順序を追跡する、async/awaitの実行フローを読む
- 誤答誘導ポイント: awaitなしのPromise参照を値として扱う、setTimeout(0)がPromise.thenより先に実行されると誤認
