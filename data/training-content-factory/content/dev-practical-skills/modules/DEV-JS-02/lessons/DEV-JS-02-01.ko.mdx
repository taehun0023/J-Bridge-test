## 1) 학습 목표

- 콜백 패턴의 구조와 콜백 지옥의 문제점을 설명할 수 있다.
- Promise의 3가지 상태(pending, fulfilled, rejected)와 전이를 설명할 수 있다.
- async/await의 실행 순서를 이벤트 루프 관점에서 추적할 수 있다.
- 비동기 처리의 에러 핸들링 패턴을 3가지 구분해서 사용할 수 있다.

## 2) 업무 맥락

웹 애플리케이션 개발에서는 API 호출, 파일 읽기, 데이터베이스 쿼리 등 비동기 처리가 빈번하게 발생한다. 비동기 처리의 실행 순서를 정확히 추적하지 못하면 "왜 이 데이터가 undefined인지", "왜 API 응답이 처리되기 전에 UI가 갱신되는지" 같은 문제의 원인을 특정할 수 없다. 실무 프로젝트에서는 Promise와 async/await가 주류이며, 기존 코드를 읽을 때 실행 순서를 올바르게 이해하는 것이 필수다.

## 3) 핵심 설명

### 콜백 패턴

가장 오래된 비동기 패턴이다. 함수를 인수로 전달하고 처리 완료 시 호출한다.

```javascript
function fetchUser(userId, callback) {
  setTimeout(() => {
    callback(null, { id: userId, name: "다나카" });
  }, 1000);
}

fetchUser(1, (error, user) => {
  if (error) {
    console.error(error);
    return;
  }
  console.log(user.name);
});
```

문제점: 중첩이 깊어진다(콜백 지옥). 에러 핸들링이 각 콜백에 분산된다.

### Promise

Promise는 비동기 처리의 결과를 나타내는 객체다. 3가지 상태를 가진다.

- **pending**: 처리 중
- **fulfilled**: 성공 (`.then`으로 값을 받음)
- **rejected**: 실패 (`.catch`로 에러를 받음)

```javascript
function fetchUser(userId) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (userId <= 0) {
        reject(new Error("Invalid ID"));
      }
      resolve({ id: userId, name: "다나카" });
    }, 1000);
  });
}

fetchUser(1)
  .then(user => console.log(user.name))
  .catch(error => console.error(error.message));
```

Promise 체이닝으로 중첩 없이 평탄하게 작성할 수 있다. `.then`의 반환값이 다음 `.then`에 전달된다.

### async/await

async/await는 Promise의 문법적 설탕이다. 비동기 처리를 동기적 형태로 작성할 수 있다.

```javascript
async function getUser(userId) {
  try {
    const user = await fetchUser(userId);
    console.log(user.name);
    return user;
  } catch (error) {
    console.error("조회 실패:", error.message);
    throw error;
  }
}
```

**중요한 실행 순서 규칙:**

```javascript
console.log("1: 시작");

async function process() {
  console.log("2: async 함수 내, await 이전");
  const result = await Promise.resolve("데이터");
  console.log("4: await 이후");
  return result;
}

process();
console.log("3: async 함수 호출 후");
```

출력 순서는 `1 → 2 → 3 → 4`이다. `await`는 해당 줄에서 일단 제어를 호출부로 반환하고, Promise가 해결된 후 마이크로태스크로 나머지를 실행한다.

### 에러 핸들링 비교

```javascript
// 1. Promise 체이닝
fetchData()
  .then(process)
  .catch(handleError);

// 2. async/await + try-catch
async function run() {
  try {
    const data = await fetchData();
    await process(data);
  } catch (error) {
    handleError(error);
  }
}

// 3. 개별 await에서의 에러 처리
async function run() {
  const data = await fetchData().catch(e => defaultData);
  await process(data);
}
```

## 4) 실무 해석 시나리오

### 시나리오 A
```javascript
async function loadDashboard() {
  const [user, orders, notifications] = await Promise.all([
    fetchUser(),
    fetchOrders(),
    fetchNotifications()
  ]);
  renderDashboard(user, orders, notifications);
}
```
- 읽기 포인트:
  - `Promise.all`은 3개의 API 호출을 병렬로 실행한다.
  - 모두 완료될 때까지 기다리고 결과를 구조 분해 할당으로 받는다.
  - 하나라도 실패하면 전체가 reject된다. 독립적으로 처리하려면 `Promise.allSettled`를 사용한다.

### 시나리오 B
```javascript
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// 출력: A → D → C → B
```
- 해석:
  - 동기 코드(A, D)가 먼저 실행된다.
  - 마이크로태스크(Promise.then → C)가 매크로태스크(setTimeout → B)보다 우선한다.
  - 이 순서를 모르면 비동기 처리의 타이밍 문제를 이해할 수 없다.

## 5) 자주 하는 실수

1. `await`를 빼먹고 Promise 객체 자체를 사용한다.
`const data = fetchUser()`로 하면 `data`는 Promise 객체이지 사용자 데이터가 아니다.

2. async 함수의 반환값이 항상 Promise임을 잊는다.
`async function f() { return 1; }`의 반환값은 `1`이 아니라 `Promise<1>`이다.

3. `Promise.all`에서 하나의 실패가 전체를 중단시키는 것을 고려하지 않는다.
독립적인 처리에는 `Promise.allSettled`를 검토해야 한다.

4. for 루프 안에서 await를 직렬 실행해 버린다.
`for (const id of ids) { await fetch(id); }`는 하나씩 순차 실행된다. 병렬화하려면 `Promise.all(ids.map(id => fetch(id)))`을 사용한다.

5. catch를 붙이지 않은 Promise 거부가 Unhandled Rejection이 된다.
Node.js에서는 프로세스 종료 원인이 된다.
