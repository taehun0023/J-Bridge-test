## 1) 학습 목표

- React 컴포넌트가 무엇이고 왜 UI를 컴포넌트로 나누는지 설명할 수 있다.
- 함수형 컴포넌트의 기본 구조를 읽고 이해할 수 있다.
- JSX 문법이 HTML과 다른 점을 구분할 수 있다.
- 컴포넌트를 분리하는 기준을 설명할 수 있다.

## 2) 업무 맥락

프론트엔드 프로젝트에 투입되면 수십~수백 개의 컴포넌트 파일을 마주하게 된다. 각 컴포넌트가 화면의 어떤 부분을 담당하는지 빠르게 파악하려면 "UI를 독립적인 조각으로 나누는 사고방식"을 이해해야 한다. 컴포넌트 분리의 원리를 모르면 어디서 어떤 코드를 수정해야 할지 찾기 어렵다.

## 3) 핵심 설명

React 컴포넌트는 **UI의 독립적인 조각**이다. 각 컴포넌트는 자신이 담당하는 화면 영역을 정의하고, 재사용할 수 있다.

함수형 컴포넌트의 기본 형태는 다음과 같다:

```jsx
function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
}
```

이 함수는 `name`이라는 데이터를 받아서 UI를 반환한다. React에서는 이것이 곧 컴포넌트다.

**JSX**는 JavaScript 안에서 HTML과 비슷한 문법을 쓸 수 있게 하는 확장이다. 하지만 몇 가지 차이가 있다:
- HTML의 `class`는 JSX에서 `className`이다.
- HTML의 `for`는 JSX에서 `htmlFor`다.
- JSX에서는 모든 태그를 닫아야 한다. `<img>`는 `<img />`로 써야 한다.
- JavaScript 표현식은 `{}`로 감싼다. `{name}`, `{count + 1}` 등.

**컴포넌트 분리 기준**:
- 반복되는 UI 패턴이 보이면 별도 컴포넌트로 추출한다.
- 독립적으로 변경될 수 있는 영역은 분리한다.
- 하나의 컴포넌트가 너무 많은 역할을 하면 분리를 고려한다.
- 재사용성보다 **가독성과 유지보수성**이 분리의 첫 번째 이유다.

## 4) 실무 해석 시나리오

### 시나리오 A
```jsx
function UserCard({ user }) {
  return (
    <div className="card">
      <img src={user.avatar} alt={user.name} />
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
}

function UserList({ users }) {
  return (
    <div>
      {users.map(user => (
        <UserCard key={user.id} user={user} />
      ))}
    </div>
  );
}
```
- 읽기 포인트:
  - `UserCard`는 사용자 한 명의 정보를 표시하는 컴포넌트다.
  - `UserList`는 `UserCard`를 반복 렌더링한다.
  - `key={user.id}`는 React가 리스트의 각 항목을 식별하기 위해 필요하다.
  - 데이터(`user`)는 부모에서 자식으로 props를 통해 전달된다.

### 시나리오 B
```jsx
// 분리 전: 하나의 컴포넌트가 모든 것을 처리
function Dashboard() {
  return (
    <div>
      <header><h1>Dashboard</h1><nav>...</nav></header>
      <main>
        <div className="stats">...</div>
        <div className="chart">...</div>
        <div className="table">...</div>
      </main>
      <footer>...</footer>
    </div>
  );
}
```
- 해석:
  - header, stats, chart, table, footer가 모두 한 컴포넌트에 있다.
  - 각각 독립적으로 변경될 수 있으므로 별도 컴포넌트로 분리하면 유지보수가 쉬워진다.
  - 분리 후: `<Header />`, `<StatsPanel />`, `<ChartSection />`, `<DataTable />`, `<Footer />`

## 5) 자주 하는 실수

1. JSX에서 `class`를 그대로 사용한다.
JSX에서는 `className`을 사용해야 한다. `class`는 JavaScript 예약어이기 때문이다.

2. 리스트 렌더링에서 `key`를 빠뜨리거나 인덱스를 key로 사용한다.
`key`가 없으면 React가 항목을 효율적으로 업데이트할 수 없다. 인덱스 대신 고유 ID를 사용해야 한다.

3. 하나의 컴포넌트에 너무 많은 역할을 넣는다.
200줄이 넘는 컴포넌트는 분리를 고려해야 한다. 단, 무조건 작게 나누는 것이 답은 아니다.

4. 컴포넌트 이름을 소문자로 시작한다.
React는 소문자로 시작하는 태그를 HTML 요소로 인식한다. 컴포넌트는 반드시 대문자로 시작해야 한다.
