## 1) 学習目標

- `useEffect` の実行タイミングと依存配列の関係を説明できる。
- 依存配列が空 `[]`、指定あり `[dep]`、省略の3パターンの違いを説明できる。
- クリーンアップ関数の目的と実行タイミングを説明できる。
- `useEffect` 内で非同期処理を扱うパターンを説明できる。

## 2) 業務コンテキスト

フロントエンド開発では、コンポーネントのマウント時にAPIを呼ぶ、特定の値が変化したらデータを再取得する、アンマウント時にリスナーを解除するなど、副作用の管理が必要になる。`useEffect` の依存配列を正しく設定しないと、無限ループや古いデータの表示、メモリリークといった問題が発生する。

## 3) 要点解説

### useEffectの基本

`useEffect` はレンダリング後に副作用を実行するフックだ。

```tsx
import { useState, useEffect } from "react";

function UserProfile({ userId }: { userId: string }) {
  const [user, setUser] = useState<User | null>(null);

  useEffect(() => {
    // 副作用: APIからデータ取得
    fetchUser(userId).then(data => setUser(data));
  }, [userId]); // userIdが変わったときだけ実行

  if (!user) return <p>読み込み中...</p>;
  return <p>{user.name}</p>;
}
```

### 依存配列の3パターン

```tsx
// パターン1: 依存配列あり → 指定した値が変わったときに実行
useEffect(() => {
  console.log("userIdが変わった:", userId);
}, [userId]);

// パターン2: 空配列 → マウント時に1回だけ実行
useEffect(() => {
  console.log("コンポーネントがマウントされた");
}, []);

// パターン3: 依存配列なし → 毎回のレンダリング後に実行（通常は非推奨）
useEffect(() => {
  console.log("毎回実行される");
});
```

**依存配列の判断基準:** Effect内で参照している外部の値（state、props、関数など）はすべて依存配列に含めるべきだ。ESLintの `react-hooks/exhaustive-deps` ルールがこれを検出する。

### クリーンアップ関数

`useEffect` からreturnする関数がクリーンアップ関数だ。次のEffect実行前とアンマウント時に呼ばれる。

```tsx
function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setSeconds(prev => prev + 1);
    }, 1000);

    // クリーンアップ: アンマウント時にインターバルを解除
    return () => clearInterval(id);
  }, []); // マウント時に1回セットアップ

  return <p>{seconds}秒</p>;
}
```

クリーンアップを忘れると、アンマウント後もインターバルやイベントリスナーが動き続け、メモリリークやエラーの原因になる。

```tsx
function WindowSize() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handleResize);

    return () => window.removeEventListener("resize", handleResize);
  }, []);

  return <p>幅: {width}px</p>;
}
```

### 非同期処理のパターン

`useEffect` のコールバック自体を `async` にすることはできない。内部で非同期関数を定義して呼び出す。

```tsx
useEffect(() => {
  // NG: useEffect(() => async () => { ... })
  // OK: 内部でasync関数を定義
  const fetchData = async () => {
    try {
      const response = await fetch(`/api/users/${userId}`);
      const data = await response.json();
      setUser(data);
    } catch (error) {
      setError("取得に失敗しました");
    }
  };

  fetchData();
}, [userId]);
```

### 競合状態（Race Condition）への対処

依存値が短時間に連続変更されると、古いリクエストの結果が新しいリクエストの結果を上書きする可能性がある。

```tsx
useEffect(() => {
  let cancelled = false;

  const fetchData = async () => {
    const data = await fetchUser(userId);
    if (!cancelled) {
      setUser(data);  // キャンセルされていない場合のみ更新
    }
  };

  fetchData();
  return () => { cancelled = true; };  // 次のEffect実行時にキャンセル
}, [userId]);
```

## 4) 実務解釈シナリオ

### シナリオ A

```tsx
function NotificationBell() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const ws = new WebSocket("wss://api.example.com/notifications");
    ws.onmessage = () => setCount(prev => prev + 1);
    return () => ws.close();
  }, []);

  return <span>🔔 {count}</span>;
}
```

- 読み取り:
  - マウント時にWebSocket接続を確立し、メッセージ受信のたびにカウントを増やす。
  - 空の依存配列 `[]` により、接続は1回だけ行われる。
  - クリーンアップで `ws.close()` を呼ぶことで、アンマウント時に接続を確実に切断する。

### シナリオ B

```tsx
function SearchResults({ query }: { query: string }) {
  const [results, setResults] = useState<Item[]>([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    if (!query) {
      setResults([]);
      return;
    }

    let cancelled = false;
    setLoading(true);

    searchItems(query).then(data => {
      if (!cancelled) {
        setResults(data);
        setLoading(false);
      }
    });

    return () => { cancelled = true; };
  }, [query]);

  if (loading) return <p>検索中...</p>;
  return <ResultList items={results} />;
}
```

- 解釈:
  - `query` が変わるたびに検索が実行される。
  - `cancelled` フラグで古いリクエストの結果を破棄し、競合状態を防いでいる。
  - `query` が空の場合は早期リターンで不要なAPIコールを避けている。

## 5) よくあるミス

1. 依存配列にEffect内で使用している値を含めない。
古い値（stale closure）が参照され、意図しない動作になる。ESLintルールに従うべきだ。

2. 依存配列を省略して毎レンダリングで実行される。
API呼び出しが毎レンダリングで発生し、無限ループになる可能性がある。

3. クリーンアップ関数を書き忘れてメモリリークする。
タイマー、イベントリスナー、WebSocket接続は必ずクリーンアップが必要だ。

4. `useEffect` のコールバックを直接 `async` にする。
`useEffect(() => async () => { ... })` はPromiseを返してしまいクリーンアップが正常に動作しない。

5. 競合状態を考慮せずに非同期データを取得する。
依存値の急速な変化で古い結果が新しい結果を上書きするバグが発生する。

## 7) 出題抽出メモ

- 事実型候補: 依存配列の3パターンと実行タイミング、クリーンアップ関数の呼び出しタイミング
- 判断型候補: 依存配列に何を含めるべきかの判断、クリーンアップが必要な副作用の識別
- シナリオ型候補: 依存配列省略による無限ループ、クリーンアップ忘れによるメモリリーク
- 誤答誘導ポイント: useEffectコールバックをasyncにできると誤認、空配列は毎回実行されると誤認
