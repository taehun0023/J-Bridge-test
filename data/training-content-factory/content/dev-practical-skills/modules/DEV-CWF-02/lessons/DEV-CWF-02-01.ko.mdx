## 1) 학습 목표

- Git의 기본 명령(add, commit, push, pull)이 각각 어떤 역할을 하는지 설명할 수 있다.
- 커밋 메시지에서 변경 의도와 영향 범위를 읽어낼 수 있다.
- 브랜치의 개념과 기본 브랜치 전략(feature branch)을 설명할 수 있다.
- 충돌(conflict)이 발생하는 원인을 설명할 수 있다.

## 2) 업무 맥락

실무에서 코드를 작성하는 시간보다 다른 사람의 변경 사항을 읽고 이해하는 시간이 더 길 때가 많다. Git 로그와 커밋 메시지는 "누가, 왜, 무엇을 변경했는가"를 추적하는 핵심 수단이다. 커밋 메시지를 제대로 읽지 못하면 코드 변경의 맥락을 놓치고, 이미 해결된 문제를 다시 조사하거나 의도하지 않은 충돌을 일으킬 수 있다.

## 3) 핵심 설명

Git은 파일의 변경 이력을 추적하는 분산 버전 관리 시스템이다. 핵심 흐름은 다음과 같다.

첫째, `git add`는 변경된 파일을 스테이징 영역에 올린다. 이 단계에서 "이번 커밋에 포함할 파일"을 선택한다.

둘째, `git commit`은 스테이징된 변경 사항을 하나의 스냅샷으로 저장한다. 이때 커밋 메시지를 작성한다. 좋은 커밋 메시지는 "무엇을 왜 변경했는가"를 한 줄로 요약한다.

셋째, `git push`는 로컬 커밋을 원격 저장소에 전송한다. 팀원이 변경 사항을 볼 수 있게 된다.

넷째, `git pull`은 원격 저장소의 최신 변경 사항을 로컬에 가져와 병합한다. 작업 시작 전에 pull을 하지 않으면 충돌 가능성이 높아진다.

브랜치는 독립적인 작업 공간이다. `main` 브랜치는 안정된 코드를 유지하고, 새 기능이나 버그 수정은 별도의 feature 브랜치에서 작업한 뒤 병합한다. 이렇게 하면 불완전한 코드가 안정 브랜치에 섞이는 것을 방지할 수 있다.

커밋 메시지를 읽을 때는 세 가지를 확인한다. 첫째, 접두사(feat, fix, refactor 등)로 변경 종류를 파악한다. 둘째, 요약 줄에서 변경의 핵심 의도를 읽는다. 셋째, 본문이 있다면 왜 이 변경이 필요했는지 배경을 확인한다.

## 4) 실무 해석 시나리오

### 시나리오 A
- 커밋 메시지: `"수정"`
- 문제점:
  - 무엇을 수정했는지 알 수 없다.
  - 관련 이슈나 배경 정보가 없다.
  - 나중에 이 변경을 추적할 때 로그가 무의미해진다.

### 시나리오 B
- 커밋 메시지: `"fix: 회원가입 이메일 인증 토큰 만료 시간을 30분에서 60분으로 변경 (#142)"`
- 해석:
  - `fix` 접두사로 버그 수정임을 알 수 있다.
  - 변경 내용(토큰 만료 시간 변경)과 구체적 수치가 명확하다.
  - `#142`로 관련 이슈를 추적할 수 있다.

## 5) 자주 하는 실수

1. pull 없이 작업을 시작한다.
원격 저장소의 최신 변경 사항을 반영하지 않으면 불필요한 충돌이 발생한다.

2. 커밋 메시지를 "수정", "업데이트" 같은 모호한 단어로 작성한다.
나중에 변경 이력을 추적할 때 아무런 정보를 얻을 수 없다.

3. 여러 변경 사항을 하나의 커밋에 몰아서 넣는다.
논리적으로 분리된 변경은 별도의 커밋으로 나누어야 리뷰와 롤백이 쉽다.

4. main 브랜치에서 직접 작업한다.
feature 브랜치를 사용하지 않으면 불완전한 코드가 안정 브랜치에 섞일 수 있다.

5. 충돌이 발생하면 상대방의 변경 사항을 무조건 덮어쓴다.
충돌 해결 시 양쪽 변경의 의도를 모두 이해한 뒤 병합해야 한다.

## 6) 확인 질문

1. `git add`와 `git commit`의 역할 차이는 무엇인가?
2. 커밋 메시지에서 가장 먼저 확인해야 할 정보는 무엇인가?
3. feature 브랜치를 사용하는 이유는 무엇인가?
4. pull을 하지 않고 작업하면 어떤 문제가 발생할 수 있는가?
5. "수정"이라는 커밋 메시지가 왜 좋지 않은가?

## 7) 문항 발췌 메모

- 사실형 후보: Git 기본 명령의 역할, 스테이징 영역의 목적
- 판단형 후보: 좋은 커밋 메시지와 나쁜 커밋 메시지 비교
- 시나리오형 후보: 충돌 상황에서 올바른 대처 방법
- 오답 유도 포인트: add와 commit 혼동, 브랜치 없이 작업하는 것을 정상으로 오인
