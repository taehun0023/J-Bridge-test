## 1) 学習目標

- Stateの役割と `useState` の基本構文を説明できる。
- Propsの役割と親子間のデータ受け渡しを説明できる。
- 単方向データフローの原則を説明できる。
- State変更がコンポーネントの再レンダリングを引き起こす仕組みを説明できる。

## 2) 業務コンテキスト

Reactアプリケーションでは、ユーザーの入力やAPIの応答などの動的なデータを管理する必要がある。StateとPropsの違いを正しく理解しないと、データの流れが複雑化し、予期しないUIの挙動やバグの原因になる。実務では「どのコンポーネントがStateを持つべきか」という設計判断が、アプリの保守性を左右する。

## 3) 要点解説

### Stateとは

Stateはコンポーネントが内部で管理する変更可能なデータだ。`useState` フックでStateを宣言する。

```tsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>カウント: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
```

**重要なルール:**
- Stateは直接変更してはいけない。必ず `set関数` を使う。
- `set関数` を呼ぶとコンポーネントが再レンダリングされる。
- Stateの更新は非同期的に処理される（バッチ処理）。

```tsx
// 間違い: 直接変更（UIが更新されない）
count = count + 1;

// 正しい: set関数を使用
setCount(count + 1);

// 前の値に基づく更新（推奨パターン）
setCount(prev => prev + 1);
```

### Propsとは

Propsは親コンポーネントから子コンポーネントに渡されるデータだ。子側では読み取り専用で、変更できない。

```tsx
// 親コンポーネント
function App() {
  const [userName, setUserName] = useState("田中");
  return <Greeting name={userName} />;
}

// 子コンポーネント
function Greeting({ name }: { name: string }) {
  return <h1>こんにちは、{name}さん</h1>;
}
```

### 単方向データフロー

Reactのデータは親から子へ一方向に流れる。子から親にデータを伝えるには、コールバック関数をPropsとして渡す。

```tsx
function Parent() {
  const [items, setItems] = useState<string[]>([]);

  const handleAdd = (item: string) => {
    setItems(prev => [...prev, item]);
  };

  return (
    <div>
      <ItemInput onAdd={handleAdd} />
      <ItemList items={items} />
    </div>
  );
}

function ItemInput({ onAdd }: { onAdd: (item: string) => void }) {
  const [text, setText] = useState("");

  return (
    <div>
      <input value={text} onChange={e => setText(e.target.value)} />
      <button onClick={() => { onAdd(text); setText(""); }}>追加</button>
    </div>
  );
}

function ItemList({ items }: { items: string[] }) {
  return (
    <ul>
      {items.map((item, i) => <li key={i}>{item}</li>)}
    </ul>
  );
}
```

### State変更と再レンダリング

Stateが変更されると、そのコンポーネントとすべての子コンポーネントが再レンダリングされる。

```
Parent (state変更) → 再レンダリング
  ├── ItemInput → 再レンダリング（Propsが変わらなくても）
  └── ItemList  → 再レンダリング（Propsが変わらなくても）
```

これはパフォーマンス上の問題になりうるが、まず正しく動作するコードを書き、問題が発生してから最適化するのがReactの基本方針だ。

## 4) 実務解釈シナリオ

### シナリオ A

```tsx
function SearchPage() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState<Item[]>([]);

  const handleSearch = async () => {
    const data = await fetchItems(query);
    setResults(data);
  };

  return (
    <div>
      <SearchBar query={query} onChange={setQuery} onSearch={handleSearch} />
      <ResultList results={results} />
    </div>
  );
}
```

- 読み取り:
  - `query` と `results` の2つのStateを `SearchPage` が管理している。
  - `SearchBar` はPropsとして現在のクエリ、変更ハンドラ、検索ハンドラを受け取る。
  - Stateの「持ち上げ」パターン: 複数の子コンポーネントが同じデータを共有する場合、共通の親にStateを置く。

### シナリオ B

```tsx
function TodoApp() {
  const [todos, setTodos] = useState([
    { id: 1, text: "設計書作成", done: false },
    { id: 2, text: "コードレビュー", done: true },
  ]);

  const toggleTodo = (id: number) => {
    setTodos(prev =>
      prev.map(todo =>
        todo.id === id ? { ...todo, done: !todo.done } : todo
      )
    );
  };

  return <TodoList todos={todos} onToggle={toggleTodo} />;
}
```

- 解釈:
  - State更新時に `map` と スプレッド構文 `{ ...todo, done: !todo.done }` で新しい配列・オブジェクトを生成している。
  - 直接変更（`todo.done = !todo.done`）は、Reactが変更を検知できないため禁止だ。
  - イミュータブルな更新パターンはReactの基本原則だ。

## 5) よくあるミス

1. Stateを直接変更する（`state.value = newValue`）。
Reactは参照の変化で再レンダリングを判断するため、直接変更するとUIが更新されない。

2. PropsをState変数に毎回コピーする。
`const [localName, setLocalName] = useState(props.name)` は初回しか反映されない。Propsはそのまま使うのが原則だ。

3. Stateの更新が非同期であることを忘れて、更新直後の値を参照する。
`setCount(count + 1); console.log(count)` のcountは更新前の値だ。

4. 子から親にデータを返すためにPropsを変更しようとする。
Propsは読み取り専用だ。コールバック関数を使って親にデータを伝える。

5. Stateの配置場所を誤り、必要のないコンポーネントまで再レンダリングされる。
Stateはそれを必要とするコンポーネントの最も近い共通親に置くべきだ。

## 7) 出題抽出メモ

- 事実型候補: StateとPropsの読み書き特性、useState の返り値の構造
