## 1) 学習目標

- application.ymlとapplication.propertiesの構造と読み方を説明できる。
- プロファイル（dev/staging/prod）による設定の分離方式を理解できる。
- @Valueと@ConfigurationPropertiesの違いと使い分けを説明できる。
- 設定値の優先順位（コマンドライン引数 > 環境変数 > ファイル）を把握できる。

## 2) 業務コンテキスト

日本のIT現場では、開発・ステージング・本番の3環境以上を運用するケースが標準的である。環境ごとにDB接続先やAPIキーが異なるため、設定ファイルの管理は日常業務で頻繁に触れる部分である。デプロイ時に「なぜ接続エラーが出るのか」の原因がプロファイル設定の誤りであることも多い。新しいプロジェクトに参加した際、まず設定ファイルを読んで環境構成を理解するのが最初のステップとなる。

## 3) 要点解説

Spring Bootの設定ファイルは`src/main/resources/`に配置する。YAML形式（.yml）とProperties形式（.properties）の2種類があり、現在はYAMLが主流である。

**application.ymlの基本構造：**

```yaml
# application.yml — 全プロファイル共通設定
server:
  port: 8080

spring:
  application:
    name: order-service
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver

logging:
  level:
    root: INFO
    com.example: DEBUG
```

**プロファイル別設定ファイル：**

環境ごとに設定を分離するには、`application-{profile}.yml`を作成する。

```yaml
# application-dev.yml — 開発環境
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/order_dev
    username: dev_user
    password: dev_pass
  jpa:
    show-sql: true
    hibernate:
      ddl-auto: update

logging:
  level:
    com.example: DEBUG
```

```yaml
# application-prod.yml — 本番環境
spring:
  datasource:
    url: jdbc:mysql://prod-db.internal:3306/order_prod
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  jpa:
    show-sql: false
    hibernate:
      ddl-auto: validate

logging:
  level:
    com.example: WARN
```

プロファイルの有効化は起動時に指定する。

```bash
# コマンドライン引数
java -jar app.jar --spring.profiles.active=prod

# 環境変数
export SPRING_PROFILES_ACTIVE=prod
```

**設定値の読み取り方：**

```java
// 方法1: @Value — 単一の値を注入
@Component
public class NotificationConfig {
    @Value("${notification.retry-count:3}")
    private int retryCount;  // デフォルト値は3

    @Value("${notification.enabled}")
    private boolean enabled;
}

// 方法2: @ConfigurationProperties — 構造化された設定をバインド
@Component
@ConfigurationProperties(prefix = "notification")
public class NotificationProperties {
    private boolean enabled;
    private int retryCount;
    private Duration timeout;
    // getter/setter
}
```

対応するYAML：
```yaml
notification:
  enabled: true
  retry-count: 5
  timeout: 30s
```

**@Value vs @ConfigurationProperties：**
- `@Value`は個別の値を注入する場合に使用する。設定項目が少ない場合に適する。
- `@ConfigurationProperties`は関連する設定をグループとしてバインドする。型安全で、IDEの補完が効き、バリデーションも適用できるため、設定項目が多い場合に推奨される。

**設定値の優先順位（高い順）：**
1. コマンドライン引数（`--server.port=9090`）
2. 環境変数（`SERVER_PORT=9090`）
3. `application-{profile}.yml`
4. `application.yml`

## 4) 実務解釈シナリオ

### シナリオ A
```yaml
# application.yml
spring:
  profiles:
    active: dev

---
# application-dev.yml が存在し、以下の内容
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/mydb
```
しかし本番デプロイ時に以下のコマンドで起動する：
```bash
java -jar app.jar --spring.profiles.active=prod
```
- 解釈：コマンドライン引数がapplication.yml内の`spring.profiles.active: dev`を上書きする。したがって`application-prod.yml`の設定が適用される。application.ymlのデフォルト値は、prod用ファイルで上書きされていない項目についてのみ適用される。

### シナリオ B
```java
@Component
@ConfigurationProperties(prefix = "mail")
public class MailProperties {
    private String host;
    private int port;
    private String from;
}
```
```yaml
mail:
  host: smtp.example.com
  port: 587
  from: noreply@example.com
```
- 解釈：`mail`プレフィックス以下のYAML設定が自動的にJavaオブジェクトにバインドされる。フィールド名とYAMLキーが対応する（kebab-caseとcamelCaseは自動変換される）。この方式ならIDEで型チェックが効き、設定漏れをコンパイル時に検出できる。

## 5) よくあるミス

1. 本番環境でパスワードをYAMLファイルに直接記述する。
本番のシークレットは環境変数（`${DB_PASSWORD}`）やSecret Managerで管理し、ファイルにはプレースホルダのみを記述する。

2. プロファイルを指定せずにデプロイする。
`spring.profiles.active`を指定しないとデフォルトプロファイルが適用される。開発設定のまま本番で動くリスクがある。

3. @Valueにデフォルト値を設定しない。
`@Value("${some.key}")`で該当キーが存在しないと起動時にエラーとなる。`@Value("${some.key:default}")`でデフォルト値を設定する。

4. YAMLのインデント誤り。
YAMLはインデントで階層を表す。スペースの数が合わないと異なる設定として解釈される。タブは使用できない。

5. application.ymlとapplication.propertiesを混在させる。
同じ設定がYAMLとPropertiesの両方に存在すると、どちらが適用されるか混乱する。プロジェクト内で1つの形式に統一する。

## 7) 出題抽出メモ

- 事実型候補：設定値の優先順位、プロファイル別ファイル命名規則
- 判断型候補：@Value vs @ConfigurationProperties の選択、シークレット管理方法
- シナリオ型候補：プロファイル指定とファイルの優先順位が異なる場合の適用設定の判断、YAML構造からバインドされるJavaオブジェクトの値推測
- 誤答誘導ポイント：application.ymlが常にすべてのプロファイルで無視されると誤認、環境変数よりファイル設定が優先されると誤認
