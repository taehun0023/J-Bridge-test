## 1) 학습 목표

- application.yml과 application.properties의 구조와 읽는 방법을 설명할 수 있다.
- 프로필(dev/staging/prod)을 통한 설정 분리 방식을 이해할 수 있다.
- @Value와 @ConfigurationProperties의 차이와 사용 구분을 설명할 수 있다.
- 설정값의 우선순위(커맨드라인 인수 > 환경변수 > 파일)를 파악할 수 있다.

## 2) 업무 맥락

일본 IT 현장에서는 개발, 스테이징, 운영의 3환경 이상을 운용하는 것이 표준이다. 환경마다 DB 접속 정보나 API 키가 다르기 때문에, 설정 파일 관리는 일상 업무에서 빈번히 다루는 부분이다. 배포 시 "왜 접속 에러가 나는가"의 원인이 프로필 설정 오류인 경우도 많다. 새로운 프로젝트에 참여하면 가장 먼저 설정 파일을 읽어 환경 구성을 파악하는 것이 첫 단계가 된다.

## 3) 핵심 설명

Spring Boot의 설정 파일은 `src/main/resources/`에 배치한다. YAML 형식(.yml)과 Properties 형식(.properties) 두 종류가 있으며, 현재는 YAML이 주류이다.

**application.yml 기본 구조:**

```yaml
# application.yml — 모든 프로필 공통 설정
server:
  port: 8080

spring:
  application:
    name: order-service
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver

logging:
  level:
    root: INFO
    com.example: DEBUG
```

**프로필별 설정 파일:**

환경별로 설정을 분리하려면 `application-{profile}.yml`을 생성한다.

```yaml
# application-dev.yml — 개발 환경
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/order_dev
    username: dev_user
    password: dev_pass
  jpa:
    show-sql: true
    hibernate:
      ddl-auto: update

logging:
  level:
    com.example: DEBUG
```

```yaml
# application-prod.yml — 운영 환경
spring:
  datasource:
    url: jdbc:mysql://prod-db.internal:3306/order_prod
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  jpa:
    show-sql: false
    hibernate:
      ddl-auto: validate

logging:
  level:
    com.example: WARN
```

프로필 활성화는 기동 시 지정한다.

```bash
# 커맨드라인 인수
java -jar app.jar --spring.profiles.active=prod

# 환경변수
export SPRING_PROFILES_ACTIVE=prod
```

**설정값 읽기 방법:**

```java
// 방법1: @Value — 단일 값 주입
@Component
public class NotificationConfig {
    @Value("${notification.retry-count:3}")
    private int retryCount;  // 기본값 3

    @Value("${notification.enabled}")
    private boolean enabled;
}

// 방법2: @ConfigurationProperties — 구조화된 설정 바인딩
@Component
@ConfigurationProperties(prefix = "notification")
public class NotificationProperties {
    private boolean enabled;
    private int retryCount;
    private Duration timeout;
    // getter/setter
}
```

대응하는 YAML:
```yaml
notification:
  enabled: true
  retry-count: 5
  timeout: 30s
```

**@Value vs @ConfigurationProperties:**
- `@Value`는 개별 값을 주입할 때 사용한다. 설정 항목이 적을 때 적합하다.
- `@ConfigurationProperties`는 관련 설정을 그룹으로 바인딩한다. 타입 안전하고 IDE 자동완성이 되며 검증도 적용할 수 있어, 설정 항목이 많을 때 권장된다.

**설정값의 우선순위 (높은 순):**
1. 커맨드라인 인수 (`--server.port=9090`)
2. 환경변수 (`SERVER_PORT=9090`)
3. `application-{profile}.yml`
4. `application.yml`

## 4) 실무 해석 시나리오

### 시나리오 A
```yaml
# application.yml
spring:
  profiles:
    active: dev

---
# application-dev.yml이 존재하며, 다음 내용 포함
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/mydb
```
그런데 운영 배포 시 다음 커맨드로 기동한다:
```bash
java -jar app.jar --spring.profiles.active=prod
```
- 해석: 커맨드라인 인수가 application.yml 내의 `spring.profiles.active: dev`를 덮어쓴다. 따라서 `application-prod.yml`의 설정이 적용된다. application.yml의 기본값은 prod 파일에서 덮어쓰지 않은 항목에 대해서만 적용된다.

### 시나리오 B
```java
@Component
@ConfigurationProperties(prefix = "mail")
public class MailProperties {
    private String host;
    private int port;
    private String from;
}
```
```yaml
mail:
  host: smtp.example.com
  port: 587
  from: noreply@example.com
```
- 해석: `mail` 접두사 하위의 YAML 설정이 자동으로 Java 객체에 바인딩된다. 필드명과 YAML 키가 대응한다(kebab-case와 camelCase는 자동 변환됨). 이 방식이면 IDE에서 타입 체크가 가능하고, 설정 누락을 컴파일 시에 감지할 수 있다.

## 5) 자주 하는 실수

1. 운영 환경에서 비밀번호를 YAML 파일에 직접 기입한다.
운영 시크릿은 환경변수(`${DB_PASSWORD}`)나 Secret Manager로 관리하고, 파일에는 플레이스홀더만 기술한다.

2. 프로필을 지정하지 않고 배포한다.
`spring.profiles.active`를 지정하지 않으면 기본 프로필이 적용된다. 개발 설정 그대로 운영에서 동작할 위험이 있다.

3. @Value에 기본값을 설정하지 않는다.
`@Value("${some.key}")`에서 해당 키가 없으면 기동 시 에러가 발생한다. `@Value("${some.key:default}")`로 기본값을 설정한다.

4. YAML 인덴트 오류.
YAML은 인덴트로 계층을 표현한다. 스페이스 수가 맞지 않으면 다른 설정으로 해석된다. 탭은 사용할 수 없다.

5. application.yml과 application.properties를 혼용한다.
같은 설정이 YAML과 Properties 양쪽에 존재하면 어느 쪽이 적용되는지 혼란이 생긴다. 프로젝트 내에서 하나의 형식으로 통일한다.

## 7) 문항 발췌 메모

- 사실형 후보: 설정값 우선순위, 프로필별 파일 명명 규칙
- 판단형 후보: @Value vs @ConfigurationProperties 선택, 시크릿 관리 방법
- 시나리오형 후보: 프로필 지정과 파일 우선순위가 다른 경우 적용 설정 판단, YAML 구조에서 바인딩되는 Java 객체 값 추측
- 오답 유도 포인트: application.yml이 항상 모든 프로필에서 무시된다고 오인, 환경변수보다 파일 설정이 우선된다고 오인
