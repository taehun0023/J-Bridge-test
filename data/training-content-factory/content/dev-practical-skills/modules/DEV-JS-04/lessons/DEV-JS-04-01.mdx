## 1) 学習目標

- ES ModulesとCommonJSの違いと使い分け基準を説明できる。
- クロージャの原理を説明し、実務での活用パターンを3つ以上挙げられる。
- `this`バインディングの4つのルールを説明し、コード内でどの値になるかを追跡できる。
- アロー関数と通常関数の`this`の違いを説明できる。

## 2) 業務コンテキスト

モダンなJavaScriptプロジェクトでは、コードをモジュールに分割して管理するのが標準である。Node.jsのCommonJSとブラウザ/バンドラーのES Modulesが混在するプロジェクトも多い。また、クロージャと`this`バインディングは、コールバック、イベントハンドラ、クラスメソッドなど至る所に登場する。これらを正しく理解できなければ、「なぜこの変数が保持されているのか」「なぜthisがundefinedなのか」といった問題を解決できない。

## 3) 要点解説

### モジュールシステム

**ES Modules（ESM）** — ブラウザとNode.js両方で使用可能な標準仕様。

```javascript
// math.js — 名前付きエクスポート
export function add(a, b) { return a + b; }
export const PI = 3.14159;

// main.js — 名前付きインポート
import { add, PI } from "./math.js";

// デフォルトエクスポート/インポート
export default class Calculator { /* ... */ }
import Calculator from "./calculator.js";
```

**CommonJS（CJS）** — Node.jsの従来の仕組み。

```javascript
// math.js
function add(a, b) { return a + b; }
module.exports = { add };

// main.js
const { add } = require("./math");
```

主な違い：ESMは静的解析が可能（Tree Shakingに有利）、CJSは動的にrequireできる。ESMの`import`はファイル先頭でのみ使用でき、CJSの`require`はどこでも呼べる。

### クロージャの原理

クロージャとは、関数がその**定義時のスコープ**にある変数を参照し続ける仕組みである。

```javascript
function createCounter() {
  let count = 0; // クロージャにより保持される
  return {
    increment() { return ++count; },
    getCount() { return count; }
  };
}

const counter = createCounter();
counter.increment(); // 1
counter.increment(); // 2
counter.getCount();  // 2
// countに外部から直接アクセスはできない
```

実務での活用パターン：

1. **データの隠蔽**：上記のように内部状態を外部から隠す。
2. **関数ファクトリ**：パラメータを記憶した関数を生成する。

```javascript
function createMultiplier(factor) {
  return (num) => num * factor;
}
const double = createMultiplier(2);
double(5); // 10
```

3. **イベントハンドラでの状態保持**：ループ内でリスナーを登録する際に各反復の値を保持する。

### thisバインディングの4つのルール

`this`の値は**関数の呼び出し方法**によって決まる。

```javascript
// 1. デフォルトバインディング — グローバルオブジェクト（strictモードではundefined）
function show() { console.log(this); }
show(); // window (non-strict) / undefined (strict)

// 2. 暗黙的バインディング — ドット左側のオブジェクト
const obj = {
  name: "田中",
  greet() { console.log(this.name); }
};
obj.greet(); // "田中"

// 3. 明示的バインディング — call, apply, bind
function greet() { console.log(this.name); }
greet.call({ name: "佐藤" }); // "佐藤"

// 4. newバインディング — コンストラクタ呼び出し
function User(name) { this.name = name; }
const u = new User("鈴木"); // this → 新しいオブジェクト
```

### アロー関数のthis

アロー関数は自身の`this`を持たない。**定義時のスコープの`this`**をそのまま引き継ぐ（レキシカルthis）。

```javascript
class Timer {
  constructor() {
    this.seconds = 0;
  }
  start() {
    // アロー関数 → thisはTimerインスタンス
    setInterval(() => {
      this.seconds++;
      console.log(this.seconds);
    }, 1000);
  }
}

// 通常関数だとthisはグローバル（またはundefined）になる
class BrokenTimer {
  constructor() { this.seconds = 0; }
  start() {
    setInterval(function() {
      this.seconds++; // thisはTimerインスタンスではない！
    }, 1000);
  }
}
```

## 4) 実務解釈シナリオ

### シナリオ A
```javascript
// api.js
const BASE_URL = "https://api.example.com";

export function createClient(token) {
  return {
    get(path) {
      return fetch(`${BASE_URL}${path}`, {
        headers: { Authorization: `Bearer ${token}` }
      });
    }
  };
}
```
- 読み取りポイント:
  - クロージャにより`token`が`get`メソッド内で保持されている。
  - 一度クライアントを作成すれば、毎回tokenを渡す必要がない。
  - ES Modulesの名前付きエクスポートで外部に公開している。

### シナリオ B
```javascript
class EventEmitter {
  constructor() {
    this.listeners = {};
  }

  on(event, callback) {
    (this.listeners[event] ??= []).push(callback);
  }

  emit(event, ...args) {
    this.listeners[event]?.forEach(cb => cb(...args));
  }
}

const emitter = new EventEmitter();
const handler = emitter.emit.bind(emitter);
setTimeout(() => handler("tick"), 1000);
```
- 解釈:
  - `bind(emitter)`で`emit`の`this`をemitterに固定している。
  - `bind`がないと、`setTimeout`内で`this`がグローバルになり、`this.listeners`がundefinedでエラーになる。
  - `??=`（論理Nullish代入）は`this.listeners[event]`がnull/undefinedの場合のみ空配列を代入する。

## 5) よくあるミス

1. コールバック内で`this`が期待通りのオブジェクトを指さない。
`setTimeout(obj.method, 100)`とすると`this`はオブジェクトではなくグローバルになる。`bind`またはアロー関数で解決する。

2. forループ内で`var`を使いクロージャが最終値を参照する。
`var`はブロックスコープを持たないため、ループ終了後の値が全てのクロージャで共有される。`let`を使えばブロックスコープで各反復の値が保持される。

3. ESMとCJSを混在させてインポートエラーが発生する。
`require`はESMファイル内で使えない。`import`はCJSファイル内で使えない（動的importを除く）。

4. アロー関数にbind/call/applyを使用しようとする。
アロー関数の`this`はレキシカルに固定されており、bind等で変更できない。

5. モジュールの循環依存に気づかない。
A→B→Aの循環importは、片方がundefinedになる原因である。
