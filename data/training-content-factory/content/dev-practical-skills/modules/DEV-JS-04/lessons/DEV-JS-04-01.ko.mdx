## 1) 학습 목표

- ES Modules와 CommonJS의 차이와 사용 기준을 설명할 수 있다.
- 클로저의 원리를 설명하고 실무에서의 활용 패턴을 3가지 이상 들 수 있다.
- `this` 바인딩의 4가지 규칙을 설명하고, 코드에서 어떤 값이 되는지 추적할 수 있다.
- 화살표 함수와 일반 함수의 `this` 차이를 설명할 수 있다.

## 2) 업무 맥락

모던 JavaScript 프로젝트에서는 코드를 모듈로 분할해 관리하는 것이 표준이다. Node.js의 CommonJS와 브라우저/번들러의 ES Modules가 혼재하는 프로젝트도 많다. 또한 클로저와 `this` 바인딩은 콜백, 이벤트 핸들러, 클래스 메서드 등 곳곳에서 등장한다. 이것들을 올바르게 이해하지 못하면 "왜 이 변수가 유지되는지", "왜 this가 undefined인지" 같은 문제를 해결할 수 없다.

## 3) 핵심 설명

### 모듈 시스템

**ES Modules(ESM)** — 브라우저와 Node.js 양쪽에서 사용 가능한 표준 사양.

```javascript
// math.js — 이름 붙인 내보내기
export function add(a, b) { return a + b; }
export const PI = 3.14159;

// main.js — 이름 붙인 가져오기
import { add, PI } from "./math.js";

// 기본 내보내기/가져오기
export default class Calculator { /* ... */ }
import Calculator from "./calculator.js";
```

**CommonJS(CJS)** — Node.js의 기존 방식.

```javascript
// math.js
function add(a, b) { return a + b; }
module.exports = { add };

// main.js
const { add } = require("./math");
```

주요 차이: ESM은 정적 분석이 가능(Tree Shaking에 유리), CJS는 동적으로 require할 수 있다. ESM의 `import`는 파일 최상단에서만 사용할 수 있고, CJS의 `require`는 어디서든 호출 가능하다.

### 클로저의 원리

클로저란 함수가 **정의 시점의 스코프**에 있는 변수를 계속 참조하는 구조다.

```javascript
function createCounter() {
  let count = 0; // 클로저에 의해 유지됨
  return {
    increment() { return ++count; },
    getCount() { return count; }
  };
}

const counter = createCounter();
counter.increment(); // 1
counter.increment(); // 2
counter.getCount();  // 2
// count에 외부에서 직접 접근 불가
```

실무 활용 패턴:

1. **데이터 은닉**: 위와 같이 내부 상태를 외부로부터 숨긴다.
2. **함수 팩토리**: 매개변수를 기억하는 함수를 생성한다.

```javascript
function createMultiplier(factor) {
  return (num) => num * factor;
}
const double = createMultiplier(2);
double(5); // 10
```

3. **이벤트 핸들러에서의 상태 유지**: 루프 안에서 리스너를 등록할 때 각 반복의 값을 유지한다.

### this 바인딩의 4가지 규칙

`this`의 값은 **함수 호출 방법**에 의해 결정된다.

```javascript
// 1. 기본 바인딩 — 전역 객체 (strict 모드에서는 undefined)
function show() { console.log(this); }
show(); // window (non-strict) / undefined (strict)

// 2. 암묵적 바인딩 — 점 왼쪽의 객체
const obj = {
  name: "다나카",
  greet() { console.log(this.name); }
};
obj.greet(); // "다나카"

// 3. 명시적 바인딩 — call, apply, bind
function greet() { console.log(this.name); }
greet.call({ name: "사토" }); // "사토"

// 4. new 바인딩 — 생성자 호출
function User(name) { this.name = name; }
const u = new User("스즈키"); // this → 새 객체
```

### 화살표 함수의 this

화살표 함수는 자체 `this`를 가지지 않는다. **정의 시점 스코프의 `this`**를 그대로 물려받는다(렉시컬 this).

```javascript
class Timer {
  constructor() {
    this.seconds = 0;
  }
  start() {
    // 화살표 함수 → this는 Timer 인스턴스
    setInterval(() => {
      this.seconds++;
      console.log(this.seconds);
    }, 1000);
  }
}

// 일반 함수라면 this가 전역(또는 undefined)이 됨
class BrokenTimer {
  constructor() { this.seconds = 0; }
  start() {
    setInterval(function() {
      this.seconds++; // this는 Timer 인스턴스가 아님!
    }, 1000);
  }
}
```

## 4) 실무 해석 시나리오

### 시나리오 A
```javascript
// api.js
const BASE_URL = "https://api.example.com";

export function createClient(token) {
  return {
    get(path) {
      return fetch(`${BASE_URL}${path}`, {
        headers: { Authorization: `Bearer ${token}` }
      });
    }
  };
}
```
- 읽기 포인트:
  - 클로저에 의해 `token`이 `get` 메서드 안에서 유지되고 있다.
  - 한 번 클라이언트를 생성하면 매번 token을 전달할 필요가 없다.
  - ES Modules의 이름 붙인 내보내기로 외부에 공개하고 있다.

### 시나리오 B
```javascript
class EventEmitter {
  constructor() {
    this.listeners = {};
  }

  on(event, callback) {
    (this.listeners[event] ??= []).push(callback);
  }

  emit(event, ...args) {
    this.listeners[event]?.forEach(cb => cb(...args));
  }
}

const emitter = new EventEmitter();
const handler = emitter.emit.bind(emitter);
setTimeout(() => handler("tick"), 1000);
```
- 해석:
  - `bind(emitter)`로 `emit`의 `this`를 emitter에 고정하고 있다.
  - `bind`가 없으면 `setTimeout` 안에서 `this`가 전역이 되어 `this.listeners`가 undefined로 에러가 난다.
  - `??=`(논리 Nullish 할당)는 `this.listeners[event]`가 null/undefined인 경우에만 빈 배열을 할당한다.

## 5) 자주 하는 실수

1. 콜백 안에서 `this`가 기대하는 객체를 가리키지 않는다.
`setTimeout(obj.method, 100)`으로 하면 `this`는 객체가 아니라 전역이 된다. `bind` 또는 화살표 함수로 해결한다.

2. for 루프 안에서 `var`를 사용해 클로저가 최종값을 참조한다.
`var`는 블록 스코프가 없으므로 루프 종료 후의 값이 모든 클로저에서 공유된다. `let`을 사용하면 블록 스코프로 각 반복의 값이 유지된다.

3. ESM과 CJS를 혼재시켜 임포트 에러가 발생한다.
`require`는 ESM 파일 안에서 사용할 수 없다. `import`는 CJS 파일 안에서 사용할 수 없다(동적 import 제외).

4. 화살표 함수에 bind/call/apply를 사용하려 한다.
화살표 함수의 `this`는 렉시컬하게 고정되어 bind 등으로 변경할 수 없다.

5. 모듈의 순환 의존을 인지하지 못한다.
A→B→A의 순환 import는 한쪽이 undefined가 되는 원인이다.
