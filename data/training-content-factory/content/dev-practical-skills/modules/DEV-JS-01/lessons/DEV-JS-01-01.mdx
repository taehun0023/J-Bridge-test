## 1) 学習目標

- var, let, constのスコープの違いを説明できる。
- ホイスティングが変数宣言に与える影響を説明できる。
- JavaScriptの暗黙的型変換が引き起こす予期しない結果を説明できる。
- ブラウザとNode.js実行環境の違いを説明できる。

## 2) 業務コンテキスト

JavaScriptはフロントエンドとバックエンドの両方で使用される言語である。実務で他の人が書いたJavaScriptコードを読む際、変数のスコープとホイスティングのルールを知らなければ、コードの実行順序を誤って予測してしまう。特にレガシーコードで`var`と`let`が混在している場合、動作の違いを理解していないとバグの再現や修正が困難になる。

## 3) 要点解説

JavaScriptで変数を宣言する3つのキーワードがある。

`var`は関数スコープを持つ。ブロック（`{}`）の中で宣言しても関数全体からアクセスできる。またホイスティングにより宣言が関数の先頭に引き上げられるが、値の代入は元の位置で実行される。

`let`はブロックスコープを持つ。宣言されたブロック内でのみアクセスできる。ホイスティングはされるが、宣言前にアクセスすると`ReferenceError`が発生する（TDZ, Temporal Dead Zone）。

`const`は`let`と同じブロックスコープを持つが、再代入が不可能である。ただし、オブジェクトや配列の場合、内部プロパティは変更できる。

暗黙的型変換はJavaScriptの代表的な落とし穴である。`"5" + 3`は`"53"`（文字列連結）になり、`"5" - 3`は`2`（数値演算）になる。このような動作は意図しないバグの原因となる。比較演算でも`==`は型変換後に比較し、`===`は型まで厳密に比較する。

実行環境による違いもある。ブラウザではグローバルオブジェクトが`window`であり、Node.jsでは`global`である。`console.log`、`setTimeout`のようなAPIは両方で使用可能だが、`document`や`require`は環境によって異なる。

## 4) 実務解釈シナリオ

### シナリオ A
```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 出力: 3, 3, 3
```
- 解釈:
  - `var`は関数スコープであるため、`i`はループ全体で一つの変数である。
  - `setTimeout`コールバックが実行される時点でループはすでに終了しており、`i`は3である。
  - `let`に変更すると各反復ごとに別の`i`が生成され、0, 1, 2が出力される。

### シナリオ B
```javascript
console.log(x); // undefined（ホイスティング）
console.log(y); // ReferenceError（TDZ）
var x = 10;
let y = 20;
```
- 解釈:
  - `var x`はホイスティングされ、宣言は引き上げられるが値は代入前のため`undefined`である。
  - `let y`もホイスティングされるが、TDZにより宣言前のアクセス時にエラーが発生する。

## 5) よくあるミス

1. `var`と`let`のスコープの違いを無視して置き換える。
単純に`var`を`let`に変えると、ブロックスコープのために以前アクセスできていた変数にアクセスできなくなる場合がある。

2. `==`と`===`を区別しない。
`0 == false`は`true`だが、`0 === false`は`false`である。実務では`===`を基本として使用すべきである。

3. `const`オブジェクトのプロパティを変更できないと思い込む。
`const obj = {a: 1}`で`obj.a = 2`は可能である。`const`は再代入のみを防ぐ。

4. 暗黙的型変換を意図的に活用する。
`"5" + 3`が`"53"`になるように予測が困難な変換は、明示的変換（`Number("5")`）に置き換えるべきである。
