## 1) 학습 목표

- var, let, const의 스코프 차이를 설명할 수 있다.
- 호이스팅이 변수 선언에 미치는 영향을 설명할 수 있다.
- JavaScript의 암묵적 타입 변환이 일으키는 예상치 못한 결과를 설명할 수 있다.
- 브라우저와 Node.js 실행 환경의 차이를 설명할 수 있다.

## 2) 업무 맥락

JavaScript는 프론트엔드와 백엔드 양쪽에서 사용되는 언어다. 실무에서 다른 사람이 작성한 JavaScript 코드를 읽을 때, 변수의 스코프와 호이스팅 규칙을 모르면 코드의 실행 순서를 잘못 예측하게 된다. 특히 레거시 코드에서 `var`와 `let`이 혼용된 경우 동작 차이를 이해하지 못하면 버그를 재현하거나 수정하기 어렵다.

## 3) 핵심 설명

JavaScript에서 변수를 선언하는 세 가지 키워드가 있다.

`var`는 함수 스코프를 가진다. 블록(`{}`) 안에서 선언해도 함수 전체에서 접근할 수 있다. 또한 호이스팅에 의해 선언이 함수 상단으로 끌어올려지지만 값 할당은 원래 위치에서 실행된다.

`let`은 블록 스코프를 가진다. 선언된 블록 안에서만 접근할 수 있다. 호이스팅은 되지만 선언 전에 접근하면 `ReferenceError`가 발생한다(TDZ, Temporal Dead Zone).

`const`는 `let`과 같은 블록 스코프를 가지되, 재할당이 불가능하다. 단, 객체나 배열의 경우 내부 프로퍼티는 변경할 수 있다.

암묵적 타입 변환은 JavaScript의 대표적인 함정이다. `"5" + 3`은 `"53"`(문자열 연결)이 되고, `"5" - 3`은 `2`(숫자 연산)가 된다. 이런 동작은 의도하지 않은 버그의 원인이 된다. 비교 연산에서도 `==`는 타입 변환 후 비교하고, `===`는 타입까지 엄격하게 비교한다.

실행 환경에 따른 차이도 있다. 브라우저에서는 전역 객체가 `window`이고, Node.js에서는 `global`이다. `console.log`, `setTimeout` 같은 API는 양쪽에서 사용 가능하지만, `document`나 `require`는 환경에 따라 다르다.

## 4) 실무 해석 시나리오

### 시나리오 A
```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 출력: 3, 3, 3
```
- 해석:
  - `var`는 함수 스코프이므로 `i`는 루프 전체에서 하나의 변수다.
  - `setTimeout` 콜백이 실행될 때 루프는 이미 끝나 `i`는 3이다.
  - `let`으로 바꾸면 각 반복마다 별도의 `i`가 생겨 0, 1, 2가 출력된다.

### 시나리오 B
```javascript
console.log(x); // undefined (호이스팅)
console.log(y); // ReferenceError (TDZ)
var x = 10;
let y = 20;
```
- 해석:
  - `var x`는 호이스팅되어 선언은 올라가지만 값은 할당 전이므로 `undefined`다.
  - `let y`도 호이스팅되지만 TDZ에 의해 선언 전 접근 시 에러가 발생한다.

## 5) 자주 하는 실수

1. `var`와 `let`의 스코프 차이를 무시하고 교체한다.
단순히 `var`를 `let`으로 바꾸면 블록 스코프 때문에 기존에 접근 가능했던 변수에 접근할 수 없게 될 수 있다.

2. `==`와 `===`를 구분하지 않는다.
`0 == false`는 `true`이지만 `0 === false`는 `false`다. 실무에서는 `===`를 기본으로 사용해야 한다.

3. `const` 객체의 프로퍼티를 변경할 수 없다고 생각한다.
`const obj = {a: 1}`에서 `obj.a = 2`는 가능하다. `const`는 재할당만 막는다.

4. 암묵적 타입 변환을 의도적으로 활용한다.
`"5" + 3`이 `"53"`이 되는 것처럼 예측이 어려운 변환은 명시적 변환(`Number("5")`)으로 대체해야 한다.

3. `"5" + 3`과 `"5" - 3`의 결과가 다른 이유는 무엇인가?
4. `==`와 `===`의 차이는 무엇이고, 실무에서 어느 쪽을 기본으로 사용해야 하는가?
5. const로 선언한 객체의 프로퍼티를 변경할 수 있는 이유는 무엇인가?

## 7) 문항 발췌 메모

- 사실형 후보: var/let/const 스코프 규칙, 호이스팅 동작
- 판단형 후보: == vs === 사용 적절성, var→let 교체 시 주의점
- 시나리오형 후보: setTimeout + var 루프 출력 예측, 호이스팅으로 인한 undefined
- 오답 유도 포인트: const 재할당 불가를 프로퍼티 변경 불가로 오인, TDZ를 모르고 let 접근
