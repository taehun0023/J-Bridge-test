## 1) 학습 목표

- SELECT 문의 기본 절(SELECT, FROM, WHERE, ORDER BY, LIMIT)의 역할을 설명할 수 있다.
- 집계 함수(COUNT, SUM, AVG, MAX, MIN)와 GROUP BY의 관계를 설명할 수 있다.
- 주어진 쿼리와 샘플 데이터로 결과를 예측할 수 있다.
- WHERE와 HAVING의 차이를 설명할 수 있다.

## 2) 업무 맥락

실무에서 데이터베이스는 거의 모든 애플리케이션의 핵심이다. 서비스 장애 조사, 데이터 확인, 리포트 생성 등 다양한 상황에서 SQL 쿼리를 읽고 결과를 예측하는 능력이 필요하다. 복잡한 쿼리를 작성하는 것보다 다른 사람이 작성한 쿼리를 정확히 읽는 것이 먼저다.

## 3) 핵심 설명

SQL의 SELECT 문은 데이터를 조회하는 기본 명령이다. 실행 순서를 이해하는 것이 중요하다.

**논리적 실행 순서**: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. 이 순서를 알면 쿼리의 각 절이 어떤 데이터에 적용되는지 정확히 추적할 수 있다.

`FROM`은 대상 테이블을 지정한다. `WHERE`는 행을 필터링한다. `GROUP BY`는 남은 행을 그룹으로 묶는다. `HAVING`은 그룹을 필터링한다. `SELECT`는 출력할 컬럼을 결정한다. `ORDER BY`는 결과를 정렬하고, `LIMIT`는 출력 행 수를 제한한다.

**WHERE vs HAVING**: `WHERE`는 그룹화 전에 개별 행을 필터링하고, `HAVING`은 그룹화 후에 그룹을 필터링한다. `WHERE`에서는 집계 함수를 사용할 수 없지만, `HAVING`에서는 가능하다.

**집계 함수**: `COUNT(*)`는 행 수, `SUM(column)`은 합계, `AVG(column)`은 평균, `MAX`/`MIN`은 최대/최솟값을 반환한다. 집계 함수는 `GROUP BY`와 함께 사용하면 그룹별 결과를 계산한다.

**NULL 주의점**: 집계 함수는 `NULL`을 무시한다. `COUNT(*)`는 모든 행을 세지만, `COUNT(column)`은 해당 컬럼이 NULL이 아닌 행만 센다. 이 차이를 모르면 결과를 잘못 예측할 수 있다.

## 4) 실무 해석 시나리오

### 시나리오 A
```sql
SELECT department, COUNT(*) AS member_count
FROM employees
WHERE status = 'active'
GROUP BY department
HAVING COUNT(*) >= 5
ORDER BY member_count DESC;
```
- 읽기 순서:
  1. `employees` 테이블에서
  2. `status`가 `'active'`인 행만 필터링하고
  3. `department`별로 그룹화한 뒤
  4. 구성원이 5명 이상인 부서만 남기고
  5. 인원수 내림차순으로 정렬한다.
- 결과: 재직 중인 직원이 5명 이상인 부서와 그 인원수가 내림차순으로 출력된다.

### 시나리오 B
```sql
SELECT COUNT(*), COUNT(email)
FROM users;
```
- 해석:
  - `COUNT(*)`는 전체 행 수를 반환한다.
  - `COUNT(email)`은 `email`이 NULL이 아닌 행만 센다.
  - 만약 100명의 사용자 중 10명의 이메일이 NULL이면, 결과는 `100, 90`이다.

## 5) 자주 하는 실수

1. SELECT의 작성 순서를 실행 순서로 오해한다.
SELECT는 맨 앞에 쓰지만 실제로는 거의 마지막에 실행된다. 실행 순서를 모르면 WHERE와 HAVING의 차이를 이해할 수 없다.

2. WHERE 절에서 집계 함수를 사용한다.
`WHERE COUNT(*) > 5`는 에러다. 집계 결과로 필터링하려면 `HAVING`을 사용해야 한다.

3. COUNT(*)와 COUNT(column)을 같다고 생각한다.
NULL이 있는 컬럼에서는 결과가 다르다. 의도에 맞는 것을 선택해야 한다.

4. GROUP BY 없이 집계 함수와 일반 컬럼을 섞어 쓴다.
`SELECT name, COUNT(*) FROM users`는 대부분의 DBMS에서 에러가 된다.
