## 1) 학습 목표

- Next.js App Router의 핵심 파일 규칙(page.tsx, layout.tsx, loading.tsx, error.tsx)을 설명할 수 있다.
- 폴더 구조가 URL 경로에 매핑되는 방식을 설명할 수 있다.
- 동적 라우트([param])와 라우트 그룹((group))의 역할을 구분할 수 있다.
- layout.tsx의 중첩 구조가 렌더링에 미치는 영향을 설명할 수 있다.

## 2) 업무 맥락

Next.js 프로젝트에 투입되면 가장 먼저 `app/` 디렉토리의 폴더 구조를 읽어야 한다. App Router에서는 폴더 이름이 곧 URL 경로이고, 특정 이름의 파일(page.tsx, layout.tsx 등)이 각각 정해진 역할을 한다. 이 규칙을 모르면 "이 페이지가 어디에 있는지", "이 레이아웃이 어디까지 적용되는지"를 파악할 수 없다.

## 3) 핵심 설명

Next.js App Router는 **파일 시스템 기반 라우팅**을 사용한다. `app/` 디렉토리 안의 폴더 구조가 URL 구조와 1:1로 대응한다.

**핵심 파일 규칙**:
- `page.tsx`: 해당 경로의 UI를 정의한다. 이 파일이 있어야 URL로 접근할 수 있다.
- `layout.tsx`: 해당 경로와 하위 경로에 공통으로 적용되는 레이아웃이다. 페이지 이동 시에도 유지된다.
- `loading.tsx`: 비동기 로딩 중 표시되는 UI다. React Suspense와 연동된다.
- `error.tsx`: 에러 발생 시 표시되는 UI다. 에러 경계(Error Boundary)를 자동으로 생성한다.
- `not-found.tsx`: 404 페이지를 커스터마이징한다.

**폴더와 URL 매핑 예시**:
```
app/
├── page.tsx              → /
├── about/
│   └── page.tsx          → /about
├── blog/
│   ├── page.tsx          → /blog
│   └── [slug]/
│       └── page.tsx      → /blog/hello-world (동적)
├── (marketing)/
│   └── pricing/
│       └── page.tsx      → /pricing (그룹은 URL에 미포함)
```

**동적 라우트** `[param]`은 URL의 일부를 변수로 받는다. `/blog/[slug]`는 `/blog/hello-world`, `/blog/nextjs-guide` 등 모든 경로에 매칭되고, `slug` 값을 컴포넌트에서 사용할 수 있다.

**라우트 그룹** `(name)`은 URL에 영향을 주지 않으면서 파일을 논리적으로 묶는다. `(marketing)/pricing`의 URL은 `/pricing`이지 `/(marketing)/pricing`이 아니다.

**layout.tsx의 중첩**: 상위 폴더의 layout이 먼저 렌더링되고, 하위 폴더의 layout이 그 안에 중첩된다. 루트 layout(app/layout.tsx)은 모든 페이지에 적용된다.

## 4) 실무 해석 시나리오

### 시나리오 A
```
app/
├── layout.tsx          // 전역 네비게이션
├── (main)/
│   ├── layout.tsx      // 사이드바가 있는 레이아웃
│   ├── dashboard/
│   │   └── page.tsx    // /dashboard
│   └── settings/
│       └── page.tsx    // /settings
└── (auth)/
    ├── layout.tsx      // 로그인 전용 레이아웃 (사이드바 없음)
    ├── login/
    │   └── page.tsx    // /login
    └── register/
        └── page.tsx    // /register
```
- 읽기 포인트:
  - `(main)`과 `(auth)`는 라우트 그룹으로 URL에 나타나지 않는다.
  - `/dashboard`와 `/settings`는 사이드바가 있는 레이아웃을 공유한다.
  - `/login`과 `/register`는 사이드바 없는 별도 레이아웃을 사용한다.
  - 루트 layout.tsx는 모든 페이지에 적용된다.

### 시나리오 B
```
app/blog/[slug]/page.tsx
```
```tsx
export default async function BlogPost({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  // slug를 사용하여 데이터 조회
  return <article><h1>{slug}</h1></article>;
}
```
- 해석:
  - `/blog/nextjs-guide`로 접근하면 `slug`는 `"nextjs-guide"`가 된다.
  - 동적 세그먼트의 값은 `params` prop으로 전달된다.
  - 이 값으로 데이터베이스나 API에서 해당 게시글을 조회할 수 있다.

## 5) 자주 하는 실수

1. page.tsx 없이 폴더만 만들고 URL 접근을 기대한다.
폴더가 있어도 page.tsx가 없으면 그 경로는 접근할 수 없다(404).

2. 라우트 그룹이 URL에 포함된다고 생각한다.
`(group)` 형태의 폴더는 URL 구조에 영향을 주지 않는다. 순수히 파일 정리 목적이다.

3. layout.tsx의 중첩 구조를 이해하지 못한다.
하위 layout은 상위 layout 안에 렌더링된다. 이를 모르면 레이아웃이 이중으로 적용되는 것처럼 보일 수 있다.

4. 동적 라우트의 파라미터 이름을 폴더 이름과 다르게 사용한다.
`[slug]` 폴더의 파라미터는 반드시 `slug`라는 이름으로 접근해야 한다.
