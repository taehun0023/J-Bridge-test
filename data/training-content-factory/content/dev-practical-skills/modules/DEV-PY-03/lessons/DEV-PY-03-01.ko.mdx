## 1) 학습 목표

- `with` 문을 이용한 파일 입출력 구조와 리소스 관리를 설명할 수 있다.
- `try/except/else/finally` 각 블록의 역할과 실행 순서를 설명할 수 있다.
- 예외 계층 구조와 너무 넓은 예외 캐치의 위험성을 설명할 수 있다.
- 실무에서 자주 발생하는 파일 관련 에러(`FileNotFoundError`, `PermissionError`, 인코딩 에러)의 원인을 특정할 수 있다.

## 2) 업무 맥락

배치 처리나 데이터 연동에서 CSV나 JSON 파일 읽기/쓰기가 일상적으로 발생한다. 파일을 연 채로 예외가 발생하면 리소스 누수로 이어져 운영 환경에서 심각한 문제를 초래한다. `with` 문을 사용한 컨텍스트 매니저와 적절한 예외 처리는 견고한 스크립트를 작성하기 위한 기본 역량이다.

## 3) 핵심 설명

### with문과 컨텍스트 매니저

`with` 문은 리소스의 확보와 해제를 자동화한다. 파일의 경우, 블록을 빠져나오면 자동으로 `close()`가 호출된다.

```python
# with문: 블록 종료 시 자동 close
with open("data.csv", "r", encoding="utf-8") as f:
    lines = f.readlines()
# 여기서 f는 이미 close 완료

# with문 없이(비권장): close 누락 위험
f = open("data.csv", "r")
lines = f.readlines()
f.close()  # 예외 발생 시 여기에 도달하지 못할 수 있음
```

여러 파일을 동시에 다룰 때도 중첩 없이 작성할 수 있다.

```python
with open("input.txt", "r") as src, open("output.txt", "w") as dst:
    for line in src:
        dst.write(line.upper())
```

### 파일 읽기/쓰기 모드

| 모드 | 설명 |
|------|------|
| `"r"` | 읽기(기본값). 파일이 없으면 `FileNotFoundError` |
| `"w"` | 쓰기. 기존 내용을 덮어씀 |
| `"a"` | 추가. 기존 내용 끝에 추가 |
| `"x"` | 배타적 생성. 파일이 이미 존재하면 `FileExistsError` |

### try/except/else/finally

```python
try:
    with open("config.json", "r") as f:
        data = json.load(f)
except FileNotFoundError:
    print("설정 파일을 찾을 수 없습니다")
    data = {}
except json.JSONDecodeError as e:
    print(f"JSON 파싱 에러: {e}")
    data = {}
else:
    # 예외가 발생하지 않았을 때만 실행
    print(f"설정을 불러왔습니다: {len(data)}건")
finally:
    # 예외 유무와 관계없이 반드시 실행
    print("처리 완료")
```

**실행 순서 포인트:**
- `try` 블록에서 예외 발생 -> 해당 `except` -> `finally`
- `try` 블록이 정상 완료 -> `else` -> `finally`
- `finally`는 `return` 문이 있어도 반드시 실행된다

### 예외 계층과 적절한 캐치

```python
# 나쁜 예: 모든 예외를 캐치
try:
    result = process_file(path)
except Exception:  # KeyboardInterrupt 등도 숨겨버림
    pass

# 좋은 예: 구체적인 예외 지정
try:
    result = process_file(path)
except (FileNotFoundError, PermissionError) as e:
    logger.error(f"파일 접근 에러: {e}")
    raise
```

`except Exception`이나 맨 `except:`는 디버깅이 어려운 버그의 원인이 된다. 예상하는 예외를 구체적으로 캐치하고, 예상치 못한 예외는 상위로 전파시키는 것이 원칙이다.

### 인코딩 문제

```python
# Windows 환경에서의 흔한 문제
with open("data.csv", "r", encoding="utf-8") as f:  # 명시적으로 UTF-8
    content = f.read()

# BOM 포함 UTF-8 파일 처리
with open("data.csv", "r", encoding="utf-8-sig") as f:
    content = f.read()
```

`encoding`을 생략하면 OS의 기본 인코딩이 사용된다. Windows 환경에서는 `cp949`(EUC-KR 계열)가 되어 UTF-8 파일을 읽을 때 `UnicodeDecodeError`가 발생한다.

## 4) 실무 해석 시나리오

### 시나리오 A

```python
import csv
from pathlib import Path

def load_users(filepath: str) -> list[dict]:
    path = Path(filepath)
    if not path.exists():
        return []

    with open(path, "r", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        return [row for row in reader]
```

- 읽기 포인트:
  - `Path.exists()`로 사전 체크하고 있지만, 체크와 오픈 사이에 파일이 삭제될 수 있다(TOCTOU 문제).
  - 실무에서는 `try/except FileNotFoundError`가 더 견고하다.
  - `csv.DictReader`는 헤더 행을 키로 한 딕셔너리 리스트를 반환한다.

### 시나리오 B

```python
import json

def update_config(path: str, key: str, value: str) -> bool:
    try:
        with open(path, "r") as f:
            config = json.load(f)
    except FileNotFoundError:
        config = {}
    except json.JSONDecodeError:
        return False  # 깨진 파일은 덮어쓰지 않음

    config[key] = value

    with open(path, "w") as f:
        json.dump(config, f, indent=2, ensure_ascii=False)
    return True
```

- 해석:
  - 파일이 없는 경우 빈 딕셔너리부터 시작한다(새로 생성).
  - JSON이 깨진 경우 `False`를 반환하여 덮어쓰기를 방지한다(데이터 보호).
  - 쓰기 시 `ensure_ascii=False`는 일본어/한국어를 그대로 저장하기 위해 필요하다.

## 5) 자주 하는 실수

1. `with` 문을 사용하지 않고 파일을 열어 예외 발생 시 리소스 누수가 생긴다.
`finally`에서 `close()`하는 방법도 있지만, `with` 문이 가장 간단하고 안전하다.

2. `except Exception`으로 모든 예외를 삼켜버린다.
`KeyboardInterrupt`나 `SystemExit`까지 잡아버려 프로그램 종료조차 못하게 될 수 있다.

3. `encoding` 파라미터를 생략하여 OS 의존 동작이 된다.
특히 Windows 환경에서 UTF-8 파일을 읽을 때 명시적으로 `encoding="utf-8"`을 지정하지 않으면 `UnicodeDecodeError`가 발생한다.

4. `else` 블록의 실행 타이밍을 오해한다.
`else`는 `try`가 정상 완료된 경우에만 실행된다. `finally`와는 다르다.

5. 파일 존재 체크 후 오픈하는 방식(TOCTOU 문제).
`Path.exists()`로 확인하고 오픈할 때까지 사이에 파일이 변경/삭제될 수 있다. `try/except`로 오픈하는 편이 안전하다.
