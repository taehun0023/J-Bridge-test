## 1) 학습 목표

- 서버 컴포넌트와 클라이언트 컴포넌트의 실행 환경 차이를 설명할 수 있다.
- `'use client'` 지시문이 컴포넌트 경계를 설정하는 방식을 설명할 수 있다.
- 각 컴포넌트 유형에서 사용할 수 있는 API와 사용할 수 없는 API를 구분할 수 있다.
- 서버 컴포넌트와 클라이언트 컴포넌트를 조합하는 패턴을 설명할 수 있다.

## 2) 업무 맥락

Next.js App Router에서 모든 컴포넌트는 기본적으로 서버 컴포넌트다. 브라우저에서 상호작용이 필요한 컴포넌트만 `'use client'`를 선언하여 클라이언트 컴포넌트로 전환한다. 이 경계를 올바르게 설정하지 못하면 "서버에서만 실행되어야 할 코드가 클라이언트에 노출"되거나, "클라이언트에서만 동작하는 코드가 서버에서 실행되어 에러가 발생"하는 문제가 생긴다. 실무에서 가장 빈번하게 마주치는 혼란 지점이다.

## 3) 핵심 설명

### 서버 컴포넌트 (기본값)

App Router에서 `'use client'`를 선언하지 않은 모든 컴포넌트는 **서버 컴포넌트**다. 서버에서만 실행되며, 결과 HTML만 클라이언트에 전송된다.

**서버 컴포넌트에서 할 수 있는 것**:
- 데이터베이스 직접 조회
- 파일 시스템 접근
- 환경 변수(서버 전용) 사용
- async/await로 데이터 페칭

**서버 컴포넌트에서 할 수 없는 것**:
- `useState`, `useEffect` 등 React 훅 사용
- 브라우저 API(`window`, `document`) 접근
- 이벤트 핸들러(`onClick`, `onChange`) 등록

```tsx
// 서버 컴포넌트 (기본값 — 'use client' 없음)
import { createClient } from '@/lib/supabase/server';

export default async function UserList() {
  const supabase = await createClient();
  const { data: users } = await supabase.from('profiles').select('*');

  return (
    <ul>
      {users?.map(user => <li key={user.id}>{user.display_name}</li>)}
    </ul>
  );
}
```

### 클라이언트 컴포넌트

파일 최상단에 `'use client'`를 선언하면 **클라이언트 컴포넌트**가 된다. 서버에서 프리렌더링된 후, 클라이언트에서 하이드레이션되어 상호작용이 가능해진다.

**클라이언트 컴포넌트에서 할 수 있는 것**:
- React 훅(`useState`, `useEffect`, `useRef` 등)
- 이벤트 핸들러(`onClick`, `onSubmit` 등)
- 브라우저 API 접근

**클라이언트 컴포넌트에서 할 수 없는 것**:
- async 컴포넌트 (async function 형태 불가)
- 서버 전용 모듈 import (DB 클라이언트, fs 등)

```tsx
'use client';

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      클릭 횟수: {count}
    </button>
  );
}
```

### 경계 설정 규칙

`'use client'`는 **경계(boundary)**를 만든다. 이 파일에서 import하는 모든 하위 컴포넌트도 자동으로 클라이언트 컴포넌트로 취급된다. 따라서 `'use client'`는 가능한 한 컴포넌트 트리의 **말단(leaf)**에 배치하는 것이 좋다.

```
ServerComponent (기본)
├── ServerComponent (기본)
│   └── ClientComponent ('use client')  ← 경계
│       ├── 하위 컴포넌트 (자동으로 클라이언트)
│       └── 하위 컴포넌트 (자동으로 클라이언트)
└── ServerComponent (기본)
```

### 서버 컴포넌트를 클라이언트 컴포넌트에 전달하기

클라이언트 컴포넌트가 서버 컴포넌트를 **children** prop으로 받으면, 서버 컴포넌트는 서버에서 렌더링된 결과가 전달된다.

```tsx
// ClientWrapper.tsx
'use client';
export default function ClientWrapper({ children }: { children: React.ReactNode }) {
  const [isOpen, setIsOpen] = useState(true);
  return isOpen ? <div>{children}</div> : null;
}

// page.tsx (서버 컴포넌트)
import ClientWrapper from './ClientWrapper';
import ServerContent from './ServerContent'; // 서버 컴포넌트

export default function Page() {
  return (
    <ClientWrapper>
      <ServerContent />  {/* 서버에서 렌더링된 결과가 전달됨 */}
    </ClientWrapper>
  );
}
```

## 4) 실무 해석 시나리오

### 시나리오 A
```tsx
// app/dashboard/page.tsx (서버 컴포넌트)
import { createClient } from '@/lib/supabase/server';
import StatsChart from './StatsChart';

export default async function DashboardPage() {
  const supabase = await createClient();
  const { data: stats } = await supabase.from('user_stats').select('*');

  return (
    <div>
      <h1>대시보드</h1>
      <StatsChart data={stats ?? []} />
    </div>
  );
}
```
```tsx
// app/dashboard/StatsChart.tsx
'use client';
import { BarChart, Bar, XAxis, YAxis } from 'recharts';

export default function StatsChart({ data }: { data: Array<{ name: string; value: number }> }) {
  return (
    <BarChart width={600} height={300} data={data}>
      <XAxis dataKey="name" />
      <YAxis />
      <Bar dataKey="value" fill="#8884d8" />
    </BarChart>
  );
}
```
- 읽기 포인트:
  - `page.tsx`는 서버 컴포넌트로 DB에서 직접 데이터를 조회한다.
  - `StatsChart`는 Recharts(브라우저 렌더링)를 사용하므로 클라이언트 컴포넌트다.
  - 데이터 페칭은 서버에서, 차트 렌더링은 클라이언트에서 분리하는 전형적인 패턴이다.
  - `data`는 직렬화 가능한(serializable) 값이므로 서버→클라이언트 전달이 가능하다.

### 시나리오 B
```tsx
// 에러가 발생하는 코드
'use client';
import { createClient } from '@/lib/supabase/server';  // 서버 전용 모듈!

export default function UserProfile() {
  const supabase = createClient();  // 빌드 에러 발생
  // ...
}
```
- 해석:
  - 클라이언트 컴포넌트에서 서버 전용 모듈을 import하면 빌드 시 에러가 발생한다.
  - 서버 전용 supabase 클라이언트는 `cookies()`를 사용하는데, 이는 서버에서만 동작한다.
  - 클라이언트에서 Supabase를 사용하려면 `@/lib/supabase/client`의 브라우저용 클라이언트를 사용해야 한다.

## 5) 자주 하는 실수

1. 서버 컴포넌트에서 `useState`나 `useEffect`를 사용한다.
서버 컴포넌트는 React 훅을 사용할 수 없다. 훅이 필요하면 해당 부분만 클라이언트 컴포넌트로 분리해야 한다.

2. 클라이언트 컴포넌트에서 서버 전용 모듈(DB 클라이언트, fs 등)을 import한다.
`'use client'` 파일에서 서버 전용 코드를 import하면 빌드 에러가 발생한다. 데이터는 서버 컴포넌트에서 조회하여 props로 전달해야 한다.

3. `'use client'`를 페이지 최상위(page.tsx)에 무분별하게 선언한다.
page.tsx에 `'use client'`를 선언하면 그 하위 모든 컴포넌트가 클라이언트 번들에 포함된다. 상호작용이 필요한 부분만 별도 클라이언트 컴포넌트로 분리하는 것이 좋다.

4. 함수(function)를 서버 컴포넌트에서 클라이언트 컴포넌트로 props로 전달한다.
함수는 직렬화할 수 없으므로 서버→클라이언트 props로 전달할 수 없다. Server Actions를 사용하거나, 클라이언트 내부에서 함수를 정의해야 한다.

## 6) 확인 질문

1. App Router에서 컴포넌트의 기본 유형은 무엇이며, 클라이언트 컴포넌트로 전환하려면 어떻게 하는가?
2. 서버 컴포넌트에서 할 수 있지만 클라이언트 컴포넌트에서 할 수 없는 것은 무엇인가?
3. `'use client'` 경계가 하위 컴포넌트에 미치는 영향은 무엇인가?
4. 서버 컴포넌트의 데이터를 클라이언트 컴포넌트에서 사용하려면 어떤 패턴을 쓰는가?
5. 클라이언트 컴포넌트에서 서버 전용 모듈을 import하면 어떤 일이 발생하는가?
6. `'use client'`를 컴포넌트 트리의 말단에 배치하라는 권장 사항의 이유는 무엇인가?

## 7) 문항 발췌 메모

- 사실형 후보: 서버/클라이언트 컴포넌트에서 사용 가능한 API 목록, 'use client' 지시문의 역할
- 판단형 후보: 주어진 요구사항에서 서버/클라이언트 컴포넌트 구분 판단
- 시나리오형 후보: 코드를 보고 에러 원인 파악 (서버 모듈의 클라이언트 import 등)
- 오답 유도 포인트: 모든 컴포넌트에 'use client' 필요하다고 오인, 클라이언트 컴포넌트에서 async/await 사용 가능하다고 오인
