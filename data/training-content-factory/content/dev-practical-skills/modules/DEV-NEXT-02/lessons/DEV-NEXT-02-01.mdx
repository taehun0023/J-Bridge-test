## 1) 学習目標

- サーバーコンポーネントとクライアントコンポーネントの実行環境の違いを説明できる。
- `'use client'`ディレクティブがコンポーネント境界を設定する仕組みを説明できる。
- 各コンポーネントタイプで使用可能なAPIと使用不可なAPIを区別できる。
- サーバーコンポーネントとクライアントコンポーネントを組み合わせるパターンを説明できる。

## 2) 業務コンテキスト

Next.js App Routerでは、すべてのコンポーネントがデフォルトでサーバーコンポーネントである。ブラウザでのインタラクションが必要なコンポーネントのみ`'use client'`を宣言してクライアントコンポーネントに切り替える。この境界を正しく設定できないと、「サーバーでのみ実行されるべきコードがクライアントに露出する」、あるいは「クライアントでのみ動作するコードがサーバーで実行されてエラーが発生する」という問題が起きる。実務で最も頻繁に遭遇する混乱ポイントである。

## 3) 要点解説

### サーバーコンポーネント（デフォルト）

App Routerで`'use client'`を宣言していないすべてのコンポーネントは**サーバーコンポーネント**である。サーバーでのみ実行され、結果のHTMLのみがクライアントに送信される。

**サーバーコンポーネントでできること**：
- データベースへの直接クエリ
- ファイルシステムへのアクセス
- 環境変数（サーバー専用）の使用
- async/awaitによるデータフェッチ

**サーバーコンポーネントでできないこと**：
- `useState`、`useEffect`などのReactフックの使用
- ブラウザAPI（`window`、`document`）へのアクセス
- イベントハンドラ（`onClick`、`onChange`）の登録

```tsx
// サーバーコンポーネント（デフォルト — 'use client'なし）
import { createClient } from '@/lib/supabase/server';

export default async function UserList() {
  const supabase = await createClient();
  const { data: users } = await supabase.from('profiles').select('*');

  return (
    <ul>
      {users?.map(user => <li key={user.id}>{user.display_name}</li>)}
    </ul>
  );
}
```

### クライアントコンポーネント

ファイルの先頭に`'use client'`を宣言すると**クライアントコンポーネント**になる。サーバーでプリレンダリングされた後、クライアントでハイドレーションされてインタラクションが可能になる。

**クライアントコンポーネントでできること**：
- Reactフック（`useState`、`useEffect`、`useRef`など）
- イベントハンドラ（`onClick`、`onSubmit`など）
- ブラウザAPIへのアクセス

**クライアントコンポーネントでできないこと**：
- asyncコンポーネント（async function形式は不可）
- サーバー専用モジュールのimport（DBクライアント、fsなど）

```tsx
'use client';

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      クリック回数: {count}
    </button>
  );
}
```

### 境界設定のルール

`'use client'`は**境界（boundary）**を作る。このファイルからimportするすべての子コンポーネントも自動的にクライアントコンポーネントとして扱われる。そのため、`'use client'`はできるだけコンポーネントツリーの**末端（leaf）**に配置するのが望ましい。

```
ServerComponent（デフォルト）
├── ServerComponent（デフォルト）
│   └── ClientComponent（'use client'）  ← 境界
│       ├── 子コンポーネント（自動的にクライアント）
│       └── 子コンポーネント（自動的にクライアント）
└── ServerComponent（デフォルト）
```

### サーバーコンポーネントをクライアントコンポーネントに渡す

クライアントコンポーネントがサーバーコンポーネントを**children** propとして受け取ると、サーバーコンポーネントはサーバーでレンダリングされた結果が渡される。

```tsx
// ClientWrapper.tsx
'use client';
export default function ClientWrapper({ children }: { children: React.ReactNode }) {
  const [isOpen, setIsOpen] = useState(true);
  return isOpen ? <div>{children}</div> : null;
}

// page.tsx（サーバーコンポーネント）
import ClientWrapper from './ClientWrapper';
import ServerContent from './ServerContent'; // サーバーコンポーネント

export default function Page() {
  return (
    <ClientWrapper>
      <ServerContent />  {/* サーバーでレンダリングされた結果が渡される */}
    </ClientWrapper>
  );
}
```

## 4) 実務解釈シナリオ

### シナリオ A
```tsx
// app/dashboard/page.tsx（サーバーコンポーネント）
import { createClient } from '@/lib/supabase/server';
import StatsChart from './StatsChart';

export default async function DashboardPage() {
  const supabase = await createClient();
  const { data: stats } = await supabase.from('user_stats').select('*');

  return (
    <div>
      <h1>ダッシュボード</h1>
      <StatsChart data={stats ?? []} />
    </div>
  );
}
```
```tsx
// app/dashboard/StatsChart.tsx
'use client';
import { BarChart, Bar, XAxis, YAxis } from 'recharts';

export default function StatsChart({ data }: { data: Array<{ name: string; value: number }> }) {
  return (
    <BarChart width={600} height={300} data={data}>
      <XAxis dataKey="name" />
      <YAxis />
      <Bar dataKey="value" fill="#8884d8" />
    </BarChart>
  );
}
```
- 読み取りポイント：
  - `page.tsx`はサーバーコンポーネントとしてDBから直接データを取得している。
  - `StatsChart`はRecharts（ブラウザレンダリング）を使用するため、クライアントコンポーネントである。
  - データフェッチはサーバーで、チャートレンダリングはクライアントで分離する典型的なパターンである。
  - `data`はシリアライズ可能（serializable）な値であるため、サーバー→クライアントへの受け渡しが可能である。

### シナリオ B
```tsx
// エラーが発生するコード
'use client';
import { createClient } from '@/lib/supabase/server';  // サーバー専用モジュール！

export default function UserProfile() {
  const supabase = createClient();  // ビルドエラー発生
  // ...
}
```
- 解釈：
  - クライアントコンポーネントでサーバー専用モジュールをimportするとビルド時にエラーが発生する。
  - サーバー専用Supabaseクライアントは`cookies()`を使用するが、これはサーバーでのみ動作する。
  - クライアントでSupabaseを使用するには`@/lib/supabase/client`のブラウザ用クライアントを使用する必要がある。

## 5) よくあるミス

1. サーバーコンポーネントで`useState`や`useEffect`を使用する。
サーバーコンポーネントではReactフックを使用できない。フックが必要な場合は、その部分だけをクライアントコンポーネントとして分離する必要がある。

2. クライアントコンポーネントでサーバー専用モジュール（DBクライアント、fsなど）をimportする。
`'use client'`ファイルでサーバー専用コードをimportするとビルドエラーが発生する。データはサーバーコンポーネントで取得し、propsとして渡す必要がある。

3. `'use client'`をページの最上位（page.tsx）に無分別に宣言する。
page.tsxに`'use client'`を宣言すると、その配下のすべてのコンポーネントがクライアントバンドルに含まれる。インタラクションが必要な部分だけを別のクライアントコンポーネントとして分離するのが望ましい。

4. 関数（function）をサーバーコンポーネントからクライアントコンポーネントにpropsとして渡す。
関数はシリアライズできないため、サーバー→クライアントのpropsとして渡すことはできない。Server Actionsを使用するか、クライアント内部で関数を定義する必要がある。

## 7) 出題抽出メモ

- 事実型候補：サーバー/クライアントコンポーネントで使用可能なAPI一覧、'use client'ディレクティブの役割
- 判断型候補：与えられた要件でのサーバー/クライアントコンポーネントの区別判断
- シナリオ型候補：コードを見てエラー原因を特定する（サーバーモジュールのクライアントimportなど）
- 誤答誘導ポイント：すべてのコンポーネントに'use client'が必要と誤認、クライアントコンポーネントでasync/awaitが使用可能と誤認
