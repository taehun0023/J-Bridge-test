## 1) 학습 목표
- 물리 메모리와 가상 메모리의 차이를 설명할 수 있다
- 페이징의 구조와 페이지 폴트의 흐름을 이해한다
- 스왑이 발생하는 조건과 성능에 미치는 영향을 파악한다

## 2) 왜 중요한가
물리 메모리(RAM)는 용량에 한계가 있으며, 여러 프로세스가 동시에 실행되는 현대 OS에서는 각 프로세스에 충분한 메모리를 직접 할당하기 어렵습니다. 가상 메모리는 각 프로세스에 독립된 주소 공간을 제공하여 물리 메모리의 제약을 넘어 프로그램을 실행할 수 있게 하는 중요한 메커니즘입니다. 이 개념을 이해하면 메모리 부족이나 성능 저하의 원인을 정확하게 진단할 수 있습니다.

## 3) 핵심 설명
- **물리 메모리(RAM)** 는 하드웨어 상의 실제 메모리로, CPU가 직접 접근할 수 있는 고속 저장 영역이다. 용량이 고정되어 있어 탑재량을 초과하는 데이터는 보관할 수 없다
- **가상 메모리** 는 OS가 제공하는 추상화 계층으로, 각 프로세스에 독자적인 연속 주소 공간(가상 주소 공간)을 부여한다. 실제 물리 주소와의 대응은 OS와 MMU(Memory Management Unit)가 수행한다
- **페이징** 은 가상 메모리를 '페이지'(보통 4KB)라는 고정 크기 단위로 분할하고, 페이지 테이블을 사용하여 가상 주소를 물리 주소로 변환하는 방식이다. 필요한 페이지만 물리 메모리에 배치하여 효율적인 메모리 활용을 실현한다

## 4) 작동 방식 또는 판단 흐름
1. 프로세스가 가상 주소에 접근하면 MMU가 페이지 테이블을 참조하여 대응하는 물리 주소를 검색한다
2. 해당 페이지가 물리 메모리에 있으면(페이지 히트) 그대로 물리 주소에 접근한다
3. 해당 페이지가 물리 메모리에 없으면 **페이지 폴트** 가 발생하고, OS가 디스크(스왑 영역)에서 해당 페이지를 물리 메모리로 로드한다. 물리 메모리가 가득 찬 경우에는 사용 빈도가 낮은 페이지를 디스크로 내보낸(스왑 아웃) 후 새 페이지를 로드한다

## 5) 비슷한 개념과의 비교
- **페이징과 세그멘테이션**: 페이징은 고정 크기로 분할하는 반면, 세그멘테이션은 논리적 단위(코드, 데이터, 스택 등)로 가변 크기 분할한다. 현대 OS에서는 페이징이 주류이다
- **스왑과 캐시**: 스왑은 메모리 부족 시 디스크를 메모리 대체로 사용하는 구조이고, 캐시는 고속 접근을 위해 데이터를 임시 복사하는 구조이다. 방향이 반대이다

## 6) 자주 하는 오해
- "가상 메모리는 디스크 위의 메모리이다" → 가상 메모리는 주소 공간의 추상화이며, 디스크의 스왑 영역은 그 일부에 불과하다
- "가상 메모리를 늘리면 프로그램이 빨라진다" → 스왑 영역을 늘려도 디스크 I/O만 증가할 뿐, 오히려 성능은 저하된다
- "모든 페이지는 항상 물리 메모리에 있다" → 필요한 페이지만 로드된다(디맨드 페이징). 미사용 페이지는 디스크에 남아 있다

## 7) 확인 질문
1. 물리 메모리와 가상 메모리의 가장 큰 차이는 무엇인가요?
2. 페이지 폴트가 발생했을 때, OS는 어떤 절차로 페이지를 로드하나요?
3. 스왑이 빈번하게 발생하면(스래싱) 왜 성능이 크게 저하되나요?
4. 각 프로세스가 독립된 가상 주소 공간을 갖는 것이 보안 측면에서 어떤 이점이 있나요?

## 8) 문항 추출 메모
- 페이지 폴트 발생 시 처리 절차를 순서 배열 문제로 출제할 수 있다
- 물리 메모리, 가상 메모리, 스왑 영역의 관계를 그림으로 묻는 문제를 만들 수 있다
- 스래싱의 원인과 대책을 선택지 문제로 출제할 수 있다
