## 1) 학습 목표
- 실행 계획이란 무엇이며, 왜 확인이 필요한지 설명할 수 있다
- EXPLAIN 명령어의 기본적인 사용법을 이해한다
- 순차 스캔과 인덱스 스캔의 차이 및 옵티마이저의 판단 기준을 파악한다

## 2) 왜 중요한가
SQL을 작성하는 것만으로는 데이터베이스가 실제로 데이터를 어떻게 가져오는지 알 수 없습니다. 실행 계획을 읽을 수 있게 되면 쿼리가 느린 원인(풀 스캔, 부적절한 인덱스 사용 등)을 특정하고 적절한 개선 방안을 세울 수 있습니다. 성능 튜닝의 첫걸음이 되는 필수 스킬입니다.

## 3) 핵심 설명
- **실행 계획** 은 DBMS(데이터베이스 관리 시스템)가 SQL 쿼리를 실행할 때의 구체적인 처리 절차를 보여주는 것이다. 테이블 접근 방법, 조인 방식, 정렬 방식 등이 포함된다
- **EXPLAIN** 명령어는 실행 계획을 확인하기 위한 SQL 문이다. 실제로 쿼리를 실행하지 않고 옵티마이저가 선택한 처리 경로를 표시한다(PostgreSQL에서는 `EXPLAIN ANALYZE`로 실행 시간도 확인 가능)
- **옵티마이저** 는 SQL 쿼리를 받아 테이블의 통계 정보(행 수, 데이터 분포, 인덱스 유무)를 기반으로 가장 비용이 낮은 실행 계획을 자동으로 선택하는 DBMS 내부 컴포넌트이다

## 4) 작동 방식 또는 판단 흐름
1. 사용자가 SQL 쿼리를 실행하면, 옵티마이저가 테이블의 통계 정보를 참조하여 여러 실행 경로 후보를 생성한다
2. 각 후보의 비용(I/O 횟수, CPU 사용량 추정치)을 비교하고, 가장 비용이 낮은 경로를 실행 계획으로 채택한다
3. 실행 엔진이 선택된 계획에 따라 데이터를 가져온다. EXPLAIN을 사용하면 2단계에서 선택된 계획의 세부 사항(스캔 방식, 추정 행 수, 비용 값 등)을 사전에 확인할 수 있다

## 5) 비슷한 개념과의 비교
- **순차 스캔(풀 스캔)과 인덱스 스캔**: 순차 스캔은 테이블 전체를 처음부터 순서대로 읽는 방식으로, 작은 테이블이나 대부분의 행이 대상인 경우 유리하다. 인덱스 스캔은 인덱스를 사용하여 필요한 행만 가져오는 방식으로, 큰 테이블에서 소수의 행을 가져올 때 유리하다
- **논리적 실행 계획과 물리적 실행 계획**: 논리 계획은 SQL의 의미적 처리 절차(조인 순서 등)를, 물리 계획은 실제 접근 방법(어떤 인덱스를 사용할지 등)을 나타낸다. EXPLAIN으로 보이는 것은 주로 물리 계획이다

## 6) 자주 하는 오해
- "인덱스가 있으면 반드시 인덱스 스캔이 사용된다" → 옵티마이저는 통계 정보를 기반으로 판단하며, 대상 행이 많으면 풀 스캔이 더 빠르다고 판단할 수 있다
- "EXPLAIN 결과는 항상 실제 실행과 일치한다" → EXPLAIN은 추정치이며, 실제 실행 시간이나 행 수와 다를 수 있다. EXPLAIN ANALYZE를 사용하면 실측값도 얻을 수 있다
- "실행 계획은 한 번 확인하면 변하지 않는다" → 테이블의 통계 정보가 갱신되면 같은 쿼리라도 옵티마이저가 다른 계획을 선택할 수 있다

## 7) 확인 질문
1. 실행 계획을 확인하는 주요 목적은 무엇인가요?
2. 순차 스캔과 인덱스 스캔은 각각 어떤 경우에 유리한가요?
3. 옵티마이저가 실행 계획을 선택할 때 참조하는 주요 정보는 무엇인가요?
4. EXPLAIN과 EXPLAIN ANALYZE의 차이는 무엇인가요?
