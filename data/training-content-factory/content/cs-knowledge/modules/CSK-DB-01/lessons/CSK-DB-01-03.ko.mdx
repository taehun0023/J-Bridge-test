## 1) 학습 목표
- 트랜잭션의 개념과 ACID 속성을 설명할 수 있다
- 4가지 격리 수준의 차이와 각 수준에서 방지할 수 있는 이상 현상을 이해한다
- 격리 수준과 성능 간의 트레이드오프를 파악한다

## 2) 왜 중요한가
데이터베이스는 여러 사용자가 동시에 접근하는 것을 전제로 합니다. 트랜잭션은 데이터의 일관성을 유지하는 기본 단위이며, 격리 수준 설정은 '데이터 정확성'과 '처리 속도' 간의 균형을 결정합니다. 이 메커니즘을 올바르게 이해하지 못하면 운영 환경에서 원인 불명의 데이터 불일치나 성능 문제에 시달리게 됩니다.

## 3) 핵심 설명
- **트랜잭션** 은 여러 DB 작업을 '모두 성공' 또는 '모두 실패'로 처리하는 논리적 작업 단위이다. ACID 속성(**A**tomicity=원자성, **C**onsistency=일관성, **I**solation=격리성, **D**urability=지속성)으로 신뢰성이 보장된다
- **격리 수준** 은 동시에 실행되는 트랜잭션 간에 서로의 처리가 어느 정도 보이는지를 제어하는 설정이다. 낮은 순서대로 READ UNCOMMITTED → READ COMMITTED → REPEATABLE READ → SERIALIZABLE의 4단계가 있다
- **이상 현상** 으로는 더티 리드(미커밋 데이터 읽기), 논리피터블 리드(같은 행을 2번 읽었을 때 값이 달라짐), 팬텀 리드(같은 조건의 쿼리에서 행 수가 달라짐)가 있다. 격리 수준이 높을수록 이들을 방지할 수 있지만, 락 경합이 늘어나 성능은 저하된다

## 4) 작동 방식 또는 판단 흐름
1. READ UNCOMMITTED: 다른 트랜잭션의 미커밋 데이터도 읽을 수 있다. 더티 리드, 논리피터블 리드, 팬텀 리드 모두 발생할 수 있다
2. READ COMMITTED: 커밋된 데이터만 읽을 수 있다. 더티 리드는 방지되지만, 논리피터블 리드와 팬텀 리드는 발생할 수 있다
3. REPEATABLE READ: 트랜잭션 시작 시점의 스냅샷으로 읽는다. 더티 리드와 논리피터블 리드는 방지되지만, 팬텀 리드는 발생할 수 있다(DBMS에 따라 방지되는 경우도 있음). SERIALIZABLE은 모든 이상을 방지하지만 동시 실행성이 가장 낮다

## 5) 비슷한 개념과의 비교
- **낙관적 동시성 제어와 비관적 동시성 제어**: 비관적 제어는 락으로 배타를 수행하고, 낙관적 제어는 버전 번호로 충돌을 감지한다. 격리 수준은 DB 측 설정이고, 동시성 제어 방식은 애플리케이션 설계의 선택이다
- **트랜잭션과 배치 처리**: 트랜잭션은 ACID가 보장되는 논리 단위이고, 배치 처리는 대량 데이터를 일괄 처리하는 방식이다. 배치 내에서 여러 트랜잭션을 사용하는 경우가 많다

## 6) 자주 하는 오해
- "격리 수준을 항상 SERIALIZABLE로 설정하면 안전하다" → 안전하지만 락 경합이 급증하여 처리량이 크게 저하된다. 대부분의 시스템에서는 READ COMMITTED가 기본값으로 충분하다
- "트랜잭션을 사용하면 성능 문제가 발생하지 않는다" → 장시간 트랜잭션은 락을 오래 보유하여 다른 처리를 블로킹하는 원인이 된다
- "REPEATABLE READ라면 팬텀 리드도 방지된다" → SQL 표준에서는 팬텀 리드를 방지하지 않는다. 다만 MySQL의 InnoDB 등 갭 락으로 사실상 방지하는 구현도 있다

## 7) 확인 질문
1. ACID 속성의 4가지 요소를 나열하고, 각각 무엇을 보장하는지 설명해 주세요
2. 더티 리드, 논리피터블 리드, 팬텀 리드의 차이는 무엇인가요?
3. READ COMMITTED와 REPEATABLE READ는 어떤 상황에서 결과가 달라지나요?
4. 격리 수준을 높이면 성능이 저하되는 이유를 설명해 주세요

## 8) 문항 추출 메모

- 구체적 시나리오(계좌 이체 등)에서 어떤 격리 수준이 적절한지 묻는 문제를 만들 수 있다
- ACID 속성의 각 요소 설명을 올바르게 대응시키는 문제를 만들 수 있다
