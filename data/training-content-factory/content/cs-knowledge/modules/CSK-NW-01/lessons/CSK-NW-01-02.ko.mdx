## 1) 학습 목표

- DNS의 역할을 설명한다
- 라우팅의 역할을 설명한다
- 이름 해석과 경로 결정의 차이를 구분한다

## 2) 왜 중요한가

연결 실패를 말할 때 DNS 문제와 경로 문제를 섞으면 원인 분석이 흐려진다. 둘은 관련되지만 역할은 다르다.

## 3) 핵심 설명

- DNS는 도메인 이름을 IP 주소로 대응시켜 해석하는 구조다
- 라우팅은 목적지까지 패킷을 어떤 경로로 보낼지 결정하는 과정이다
- 이름 해석이 성공해도 전달 성공이 보장되는 것은 아니다

## 4) 작동 방식 또는 판단 흐름

1. 사용자는 도메인 이름으로 접속을 시도한다
2. DNS가 대응하는 IP 주소를 찾는다
3. 이후 네트워크 장비가 경로를 따라 패킷을 전달한다

## 5) 비슷한 개념과의 비교

- DNS는 목적지 주소를 찾는 단계에 가깝다
- 라우팅은 찾은 주소로 실제 이동시키는 단계에 가깝다

## 6) 자주 하는 오해

- DNS만 되면 통신은 자동으로 성공한다는 오해
- 라우팅은 통신사만 아는 내부 개념이라는 오해
- IP 주소를 알면 DNS는 완전히 불필요하다는 오해

## 7) 확인 질문

1. 도메인 이름을 IP로 바꾸는 역할은 무엇인가
2. 이름 해석 성공 후에도 통신 실패가 생기는 이유는 무엇인가
3. DNS 문제와 라우팅 문제를 어떻게 구분할 수 있는가
4. IP를 직접 입력해도 모든 문제가 사라지지 않는 이유는 무엇인가

## 8) 문항 추출 메모

- DNS와 라우팅의 역할 비교 문항을 만들 수 있다
- 통신 실패 원인을 단계별로 해석하는 시나리오형 문항 후보가 된다
- 이름 해석과 경로 결정을 분리하는 개념형 문항으로 전개할 수 있다
