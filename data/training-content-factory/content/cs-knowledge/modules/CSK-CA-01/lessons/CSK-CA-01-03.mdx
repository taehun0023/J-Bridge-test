## 1) 学習目標
- I/O デバイスと CPU の通信方法を理解する
- バスの役割と構成（データバス・アドレスバス・制御バス）を説明できる
- 割り込みとポーリングの違い、および割り込みの利点を述べられる

## 2) なぜ重要か
CPU は単独では外部とやり取りできず、キーボード・ディスク・ネットワークカードなどの I/O デバイスと通信する仕組みが不可欠である。バスはこの通信の共有経路であり、割り込みは CPU がデバイスの完了を待つ間も他の処理を続けるための仕組みである。これらを理解することで、デバイスドライバの挙動やシステムの応答性に関するトラブルシューティングが可能になる。

## 3) 中核説明
- **I/O デバイス通信**: CPU は I/O コントローラ（デバイスコントローラ）を介してデバイスとデータをやり取りする。デバイスごとにコントローラがあり、CPU はコントローラのレジスタに読み書きすることで制御する
- **バス（Bus）**: CPU・メモリ・I/O デバイスを接続する共有データ経路。データバス（データ転送）、アドレスバス（送り先の指定）、制御バス（読み書き命令の伝達）の 3 種類がある。バス幅が広いほど一度に多くのデータを転送できる
- **割り込み（Interrupt）vs ポーリング（Polling）**: ポーリングは CPU が定期的にデバイスの状態を確認する方式で、CPU 時間を無駄に消費する。割り込みはデバイス側から CPU に完了を通知する方式で、CPU は通知が来るまで他の処理を実行できるため効率が良い

## 4) 仕組みまたは判断の流れ
1. **I/O 要求の発行**: CPU が I/O コントローラのレジスタにコマンドを書き込む
2. **デバイスの処理**: デバイスが独立してデータ転送や処理を実行する
3. **完了通知**: 割り込み方式ではデバイスが割り込み信号を CPU に送信 → CPU は現在の処理を中断し、割り込みハンドラ（ISR）を実行 → 処理完了後に元のタスクに復帰する

## 5) 似ている概念との比較
- **割り込み vs ポーリング**: 割り込みはイベント駆動で CPU 効率が高いが、割り込みハンドラの実装が必要。ポーリングは実装が単純だが CPU を常に占有する
- **メモリマップド I/O vs ポートマップド I/O**: メモリマップドはメモリアドレス空間に I/O を配置し通常の命令で操作する。ポートマップドは専用命令（IN/OUT）で操作する

## 6) よくある誤解
- 「割り込みが発生すると現在の処理は失われる」→ CPU はコンテキスト（レジスタ値・プログラムカウンタ）を退避してから ISR を実行し、完了後に復帰するため処理は失われない
- 「バスは 1 本しかない」→ 現代のコンピュータはシステムバス・PCI バス・USB バスなど、階層的に複数のバスを持つ
- 「ポーリングは常に悪い方式である」→ デバイスの応答が極めて速い場合や、割り込みのオーバーヘッドが大きい場合にはポーリングのほうが効率的なケースもある

## 7) 確認質問
1. データバス・アドレスバス・制御バスの役割をそれぞれ 1 文で述べよ
2. 割り込み方式がポーリング方式より CPU 効率が良い理由を説明せよ
3. 割り込み発生時に CPU が行う処理の流れ（コンテキスト退避 → ISR 実行 → 復帰）を説明せよ
4. ポーリングが割り込みより適切な場面を 1 つ挙げよ
