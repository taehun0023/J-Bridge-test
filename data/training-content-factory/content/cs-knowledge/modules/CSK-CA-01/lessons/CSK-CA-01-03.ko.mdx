## 1) 학습 목표
- I/O 장치와 CPU의 통신 방법을 이해한다
- 버스의 역할과 구성(데이터 버스·주소 버스·제어 버스)을 설명할 수 있다
- 인터럽트와 폴링의 차이, 그리고 인터럽트의 장점을 서술할 수 있다

## 2) 왜 중요한가
CPU는 단독으로 외부와 통신할 수 없으며, 키보드·디스크·네트워크 카드 등 I/O 장치와 통신하는 구조가 필수적이다. 버스는 이 통신의 공유 경로이고, 인터럽트는 CPU가 장치의 완료를 기다리는 동안에도 다른 처리를 계속할 수 있게 하는 메커니즘이다. 이를 이해하면 디바이스 드라이버의 동작이나 시스템 응답성 관련 문제 해결이 가능해진다.

## 3) 핵심 설명
- **I/O 장치 통신**: CPU는 I/O 컨트롤러(디바이스 컨트롤러)를 통해 장치와 데이터를 주고받는다. 장치마다 컨트롤러가 있으며, CPU는 컨트롤러의 레지스터에 읽기/쓰기를 하여 제어한다
- **버스(Bus)**: CPU·메모리·I/O 장치를 연결하는 공유 데이터 경로이다. 데이터 버스(데이터 전송), 주소 버스(목적지 지정), 제어 버스(읽기/쓰기 명령 전달)의 3종류가 있다. 버스 폭이 넓을수록 한 번에 더 많은 데이터를 전송할 수 있다
- **인터럽트(Interrupt) vs 폴링(Polling)**: 폴링은 CPU가 주기적으로 장치 상태를 확인하는 방식으로, CPU 시간을 낭비한다. 인터럽트는 장치 쪽에서 CPU에 완료를 알리는 방식으로, CPU는 알림이 올 때까지 다른 처리를 할 수 있어 효율적이다

## 4) 작동 방식 또는 판단 흐름
1. **I/O 요청 발행**: CPU가 I/O 컨트롤러의 레지스터에 커맨드를 쓴다
2. **장치 처리**: 장치가 독립적으로 데이터 전송이나 처리를 수행한다
3. **완료 통지**: 인터럽트 방식에서는 장치가 인터럽트 신호를 CPU에 보냄 → CPU가 현재 처리를 중단하고 인터럽트 핸들러(ISR)를 실행 → 처리 완료 후 원래 작업으로 복귀한다

## 5) 비슷한 개념과의 비교
- **인터럽트 vs 폴링**: 인터럽트는 이벤트 구동 방식으로 CPU 효율이 높지만, 인터럽트 핸들러 구현이 필요하다. 폴링은 구현이 단순하지만 CPU를 항상 점유한다
- **메모리 맵드 I/O vs 포트 맵드 I/O**: 메모리 맵드는 메모리 주소 공간에 I/O를 배치하여 일반 명령으로 조작한다. 포트 맵드는 전용 명령(IN/OUT)으로 조작한다

## 6) 자주 하는 오해
- "인터럽트가 발생하면 현재 처리가 사라진다" → CPU는 컨텍스트(레지스터 값·프로그램 카운터)를 저장한 뒤 ISR을 실행하고, 완료 후 복귀하므로 처리가 사라지지 않는다
- "버스는 1개뿐이다" → 현대 컴퓨터는 시스템 버스·PCI 버스·USB 버스 등 계층적으로 여러 버스를 갖는다
- "폴링은 항상 나쁜 방식이다" → 장치의 응답이 매우 빠르거나 인터럽트 오버헤드가 큰 경우에는 폴링이 더 효율적인 경우도 있다

## 7) 확인 질문
1. 데이터 버스·주소 버스·제어 버스의 역할을 각각 한 문장으로 서술하라
2. 인터럽트 방식이 폴링 방식보다 CPU 효율이 좋은 이유를 설명하라
3. 인터럽트 발생 시 CPU가 수행하는 처리 흐름(컨텍스트 저장 → ISR 실행 → 복귀)을 설명하라
4. 폴링이 인터럽트보다 적절한 상황을 1가지 들어라
