## 1) 학습 목표
- 트리 구조의 기본 용어(루트·노드·리프·깊이·높이)를 올바르게 사용할 수 있다
- 이진 트리의 성질과 이진 탐색 트리(BST)의 탐색·삽입 원리를 설명할 수 있다
- 힙의 구조 조건과 순서 조건을 이해하고, 우선순위 큐와의 관계를 설명할 수 있다

## 2) 왜 중요한가
트리 구조는 파일 시스템, DOM, 데이터베이스 인덱스 등 다양한 곳에서 사용되는 가장 기본적인 비선형 데이터 구조이다. 특히 힙은 우선순위 큐의 효율적인 구현으로서, 태스크 스케줄링, 다익스트라 알고리즘, 정렬 알고리즘(힙 정렬) 등 많은 알고리즘의 기반이 된다. 트리 구조를 이해하지 못하면 이러한 구조를 올바르게 사용할 수 없다.

## 3) 핵심 설명
- **트리 구조의 기본**: 루트(root)를 꼭대기로 하여 부모-자식 관계로 연결된 노드의 집합. 각 노드는 0개 이상의 자식을 가진다. 자식이 없는 노드를 리프(leaf)라 한다
- **이진 트리와 이진 탐색 트리**: 이진 트리는 각 노드가 최대 2개의 자식을 갖는 트리. 이진 탐색 트리(BST)는 "왼쪽 자식 < 부모 < 오른쪽 자식"이라는 순서 조건을 만족하며, 평균 O(log n)으로 탐색할 수 있다
- **힙**: 완전 이진 트리의 형태 조건과, 부모 ≤ 자식(최소 힙) 또는 부모 ≥ 자식(최대 힙)의 순서 조건을 동시에 만족하는 데이터 구조. 배열로 효율적으로 구현할 수 있다

## 4) 작동 방식 또는 판단 흐름
1. 힙에 삽입: 배열 끝에 요소를 추가하고, 부모와 비교하면서 위 방향으로 교환(상향 힙화 / sift-up)
2. 힙에서 추출: 루트(최솟값/최댓값)를 꺼내고, 마지막 요소를 루트로 이동시킨 뒤, 자식과 비교하면서 아래 방향으로 교환(하향 힙화 / sift-down)
3. 삽입·삭제 모두 O(log n)으로 완료된다. 이를 통해 우선순위 큐의 연산을 효율적으로 수행할 수 있다
4. 배열 인덱스에서의 부모-자식 관계: 부모 = (i−1)/2, 왼쪽 자식 = 2i+1, 오른쪽 자식 = 2i+2 (0-indexed)

## 5) 비슷한 개념과의 비교
- **힙 vs 이진 탐색 트리**: 힙은 부모-자식 간 대소만 보장하며 형제 간 순서는 정해지지 않는다. BST는 좌우 부분 트리 전체에 대한 순서를 보장한다. 힙은 최솟값/최댓값 추출이 O(1), BST는 임의 값 검색이 O(log n)
- **완전 이진 트리 vs 정이진 트리**: 완전 이진 트리는 마지막 레벨을 제외한 모든 레벨이 채워져 있고 마지막 레벨은 왼쪽부터 채워진다. 정이진 트리(full binary tree)는 모든 노드가 0개 또는 2개의 자식을 갖는다

## 6) 자주 하는 오해
- "힙은 정렬된 배열과 같다" → 힙은 부모-자식 간 순서만 보장하며, 배열 전체가 정렬되어 있는 것은 아니다
- "이진 탐색 트리는 항상 O(log n)으로 검색할 수 있다" → 편향된 삽입으로 일직선이 되면 O(n)으로 퇴화한다. 균형을 유지하려면 AVL 트리나 레드-블랙 트리가 필요하다
- "힙 메모리 영역과 데이터 구조의 힙은 같은 것이다" → 메모리의 힙 영역(동적 할당용)과 데이터 구조의 힙은 완전히 다른 개념이다

## 7) 확인 질문
1. 깊이 3인 완전 이진 트리의 최대 노드 수는?
2. 최소 힙에 요소를 삽입하는 절차를 sift-up을 사용하여 설명하라
3. 힙과 이진 탐색 트리의 순서 조건 차이를 비교하라
4. 우선순위 큐 구현에 힙이 적합한 이유를 시간 복잡도 관점에서 설명하라

## 8) 문항 추출 메모
- 힙의 배열 표현에서 인덱스 계산(부모·왼쪽 자식·오른쪽 자식)을 출제할 수 있다
- BST에 삽입 순서와 트리 형태의 관계를 시나리오 문제로 만들 수 있다
- 힙과 BST의 사용 구분을 판단하게 하는 응용 문제로 만들 수 있다
