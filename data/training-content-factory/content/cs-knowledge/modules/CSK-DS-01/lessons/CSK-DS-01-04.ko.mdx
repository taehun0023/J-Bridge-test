## 1) 학습 목표
- 해시 함수의 개념과 키에서 인덱스를 계산하는 원리를 설명할 수 있다
- 해시 테이블의 구조와 평균 O(1)로 검색할 수 있는 이유를 이해한다
- 충돌(collision)의 발생 원인과 체이닝·개방 주소법에 의한 해결 방법을 설명할 수 있다

## 2) 왜 중요한가
해시 테이블은 프로그래밍에서 가장 자주 사용되는 데이터 구조 중 하나이다. Java의 HashMap, Python의 dict, JavaScript의 Object/Map은 모두 해시 테이블로 구현되어 있다. 평균 O(1)로 데이터의 삽입·검색·삭제가 가능하여 대량 데이터의 고속 처리에 필수적이다. 반면에 해시 함수의 선택이나 충돌 처리를 잘못하면 성능이 극적으로 저하되므로, 내부 구조를 이해하는 것이 중요하다.

## 3) 핵심 설명
- **해시 함수**: 임의의 키(문자열, 숫자 등)를 고정 크기의 정수 값(해시 값)으로 변환하는 함수. 이상적으로는 키가 균등하게 분산되어야 한다
- **해시 테이블**: 해시 값을 인덱스로 사용하여 배열에 데이터를 저장하는 구조. 키에서 직접 위치를 계산할 수 있어 평균 O(1)로 접근 가능
- **충돌(collision)**: 서로 다른 키가 같은 해시 값을 갖는 상황. 비둘기집 원리에 의해, 키의 종류가 배열 크기를 넘으면 반드시 발생한다

## 4) 작동 방식 또는 판단 흐름
1. 키를 해시 함수에 전달하여 해시 값을 계산한다 (예: hash("apple") → 3)
2. 해시 값을 배열 크기로 나눈 나머지(mod)를 인덱스로 사용한다
3. 충돌이 발생한 경우의 처리:
   - **체이닝**: 각 버킷에 연결 리스트를 두고, 같은 인덱스의 데이터를 리스트로 관리한다
   - **개방 주소법**: 충돌 시 다른 빈 슬롯을 찾는다 (선형 탐사, 이차 탐사, 이중 해싱 등)
4. 적재율(load factor = 요소 수 / 배열 크기)이 높아지면 리사이즈(리해싱)를 수행하여 성능을 유지한다

## 5) 비슷한 개념과의 비교
- **체이닝 vs 개방 주소법**: 체이닝은 추가 메모리 할당이 필요하지만 구현이 간단하다. 개방 주소법은 메모리 지역성이 좋지만 클러스터링(연속 충돌의 연쇄)이 발생하기 쉽다
- **해시 테이블 vs 이진 탐색 트리**: 해시 테이블은 평균 O(1)이지만 최악 O(n)이고 순서를 유지하지 않는다. BST는 균형 시 O(log n)이며 순서 있는 순회가 가능하다

## 6) 자주 하는 오해
- "해시 테이블은 항상 O(1)로 검색할 수 있다" → 충돌이 많이 발생하는 최악의 경우 O(n)으로 퇴화한다. 모든 키가 같은 버킷에 집중되는 경우 등
- "좋은 해시 함수라면 충돌이 일어나지 않는다" → 비둘기집 원리에 의해 키의 종류가 버킷 수를 넘으면 충돌은 반드시 발생한다
- "해시 테이블은 정렬된 데이터 조회에 적합하다" → 해시 테이블은 요소의 순서를 유지하지 않으므로 정렬된 순회에는 적합하지 않다

## 7) 확인 질문
1. 해시 함수가 갖추어야 할 "좋은 성질" 2가지를 들어라
2. 체이닝과 개방 주소법의 충돌 해결 방식을 각각 설명하라
3. 해시 테이블의 검색이 O(n)으로 퇴화하는 것은 어떤 경우인가
4. 적재율(load factor)과 리해싱의 관계를 설명하라

## 8) 문항 추출 메모
- 해시 값 계산과 mod 연산으로 인덱스를 구하는 계산 문제를 출제할 수 있다
- 체이닝과 개방 주소법의 비교를 선택 문제로 만들 수 있다
- 최악의 경우 시간 복잡도를 묻는 시나리오 문제로 만들 수 있다
