## 1) 학습 목표
- 보안에서 로그의 중요성과 기록해야 할 항목을 설명할 수 있다
- 인시던트 대응의 기본 흐름(탐지 → 봉쇄 → 복구 → 회고)을 이해한다
- 로그 보존 기간과 감사 요건의 관계를 파악한다

## 2) 왜 중요한가
보안 인시던트는 "일어날지 여부"가 아니라 "언제 일어날지"의 문제이다. 적절한 로그가 기록되어 있지 않으면 공격 탐지도 원인 규명도 할 수 없다. 또한 인시던트 발생 시 절차가 정해져 있지 않으면 피해는 계속 확대된다. 로그 관리와 인시던트 대응은 시스템을 지키는 마지막 방어선이다.

## 3) 핵심 설명
- **로그의 종류**: 접근 로그(누가 언제 무엇에 접근했는지), 오류 로그(이상 동작 기록), 감사 로그(권한 변경, 데이터 변경 등 중요 작업)의 3종류가 기본이다. 보안 관점에서는 특히 인증 실패, 권한 상승, 데이터 내보내기 기록이 중요하다
- **인시던트 대응의 4단계**: 탐지(Detection) → 봉쇄(Containment) → 복구(Recovery) → 회고(Post-Incident Review). 각 단계에서 관계자에게 보고하고 기록하며, 재발 방지책을 도출한다
- **로그 보존과 모니터링**: 로그를 일정 기간 보존하고, 실시간 모니터링이나 알림 설정으로 이상을 조기에 발견한다. 보존 기간은 법규나 컴플라이언스 요건에 따라 설정한다

## 4) 작동 방식 또는 판단 흐름
1. **탐지(Detection)**: 모니터링 시스템이나 로그 분석으로 이상을 감지한다. 예를 들어 짧은 시간에 대량의 로그인 실패, 평소와 다른 IP에서의 접속, 대량 데이터 다운로드 등이다. 알림 임계값을 적절히 설정하여 오탐을 줄이면서 놓치는 것을 방지한다
2. **봉쇄(Containment)**: 피해 확대를 막기 위해 영향 범위를 특정하고 격리한다. 감염된 단말의 네트워크 차단, 침해된 계정 비활성화, 해당 서비스 일시 중지 등의 조치를 취한다
3. **복구와 회고**: 시스템을 정상 상태로 되돌리고 백업 복원이나 패치 적용을 수행한다. 인시던트 완료 후 타임라인을 정리하고 근본 원인을 분석하여 재발 방지 대책을 문서화한다

## 5) 비슷한 개념과의 비교
- **모니터링 vs 로그 분석**: 모니터링은 실시간으로 시스템 상태를 확인하고 이상을 즉시 탐지한다. 로그 분석은 과거 데이터를 추적하여 조사한다. 둘을 결합하면 예방과 사후 대응 모두를 커버할 수 있다
- **접근 로그 vs 감사 로그**: 접근 로그는 모든 요청의 기록이고, 감사 로그는 중요한 작업(권한 변경, 데이터 삭제 등)에 한정한 기록이다. 감사 로그는 컴플라이언스 대응에서 특히 중요하다

## 6) 자주 하는 오해
- "로그는 문제가 생긴 후에 확인하면 된다" → 실시간 모니터링과 알림이 없으면 공격 탐지가 지연되어 피해가 확대된다. 사전에 로그 수집과 모니터링 체계를 구축해야 한다
- "로그는 많을수록 좋다" → 불필요한 로그가 너무 많으면 중요한 정보가 묻히고 스토리지 비용도 증가한다. 무엇을 기록할지 설계하는 것이 중요하다
- "인시던트 대응은 보안 팀만의 업무이다" → 개발 팀, 운영 팀, 경영진을 포함한 조직 전체의 협력이 필요하다. 역할과 연락 체계를 사전에 정해 두는 것이 중요하다

## 7) 확인 질문
1. 보안 관점에서 기록해야 할 로그의 종류를 3가지 들고 각각의 목적을 설명하세요
2. 인시던트 대응의 4단계를 순서대로 나열하고 각 단계의 주요 활동을 설명하세요
3. 로그 보존 기간을 결정할 때 고려해야 할 요소는 무엇인가요
4. 대량의 로그인 실패를 탐지한 경우 봉쇄 조치로 어떤 대응을 취하나요

## 8) 문항 추출 메모
- 인시던트 대응의 4단계 순서는 순서 문제에 최적이다
- 로그의 종류(접근, 오류, 감사)와 기록 내용의 대응은 객관식 문제에 적합하다
- "XX 이상을 탐지한 경우의 대응 절차"라는 시나리오 문제를 출제하기 쉽다
