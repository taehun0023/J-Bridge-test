# 컬렉션 -- List / Set / Map

## 1) 요점 정리 (5줄)

- **Collection 프레임워크**는 `Collection`과 `Map`의 2대 인터페이스를 정점으로 하며, List, Set, Map의 3가지 카테고리로 분류된다 (Evidence: E1)
- **List**는 순서 있음, 중복 허용 컬렉션이며, `ArrayList`(랜덤 액세스 O(1))와 `LinkedList`(삽입/삭제 O(1))를 구분하여 사용한다 (Evidence: E2)
- **Set**은 중복을 허용하지 않는 컬렉션이며, `HashSet`(O(1) 검색), `TreeSet`(정렬됨), `LinkedHashSet`(삽입 순서 유지)이 있다 (Evidence: E3)
- **Map**은 키와 값의 쌍을 저장하며, `HashMap`(O(1) 검색), `TreeMap`(키 정렬), `LinkedHashMap`(삽입 순서 유지)이 있다 (Evidence: E4)
- Set, Map의 키로 사용하는 객체는 **equals/hashCode 계약**을 올바르게 구현해야 한다 (Evidence: E5)

## 2) 개념

### 컬렉션 프레임워크 계층

```
Iterable
└── Collection
    ├── List       ← 순서 있음, 중복 허용
    │   ├── ArrayList
    │   └── LinkedList
    ├── Set        ← 중복 없음
    │   ├── HashSet
    │   ├── LinkedHashSet
    │   └── SortedSet
    │       └── TreeSet
    └── Queue / Deque
        └── LinkedList (Deque 구현)

Map                ← 키-값 쌍 (Collection을 상속하지 않음)
├── HashMap
├── LinkedHashMap
└── SortedMap
    └── TreeMap
```

`Map`은 `Collection` 인터페이스를 상속하지 않는다는 점에 주의. 단, `keySet()`, `values()`, `entrySet()`으로 `Collection` 뷰를 가져올 수 있다 (Evidence: E1).

### List -- ArrayList vs LinkedList

| 특성 | ArrayList | LinkedList |
|---|---|---|
| 내부 구조 | 가변 배열 | 양방향 연결 리스트 |
| 랜덤 액세스 (get) | O(1) | O(n) |
| 선두 삽입/삭제 | O(n) | O(1) |
| 끝에 추가 | 평균 O(1) | O(1) |
| 메모리 | 연속 영역 | 노드마다 포인터 |

대부분의 경우 **ArrayList**가 권장된다. LinkedList는 선두에 대한 빈번한 삽입/삭제가 있는 경우에만 검토한다 (Evidence: E2).

### Set -- HashSet / TreeSet / LinkedHashSet

| 특성 | HashSet | TreeSet | LinkedHashSet |
|---|---|---|---|
| 순서 | 없음 | 자연 순서/Comparator | 삽입 순서 |
| add/contains | O(1) | O(log n) | O(1) |
| null 요소 | 1개 허용 | 불가 (Comparator에 따라) | 1개 허용 |
| 용도 | 일반적 중복 제거 | 정렬된 셋 | 삽입 순서 유지한 중복 제거 |

HashSet은 내부적으로 HashMap을 사용하므로, 요소의 `hashCode()`와 `equals()`가 올바르게 구현되어 있어야 한다 (Evidence: E3).

### Map -- HashMap / TreeMap / LinkedHashMap

| 특성 | HashMap | TreeMap | LinkedHashMap |
|---|---|---|---|
| 순서 | 없음 | 키의 자연 순서/Comparator | 삽입 순서 |
| get/put | O(1) | O(log n) | O(1) |
| null 키 | 1개 허용 | 불가 | 1개 허용 |
| 용도 | 일반적 키-값 저장 | 정렬된 맵 | 삽입 순서 유지한 맵 |

HashMap의 키에는 `hashCode()`와 `equals()`가 올바르게 구현된 객체를 사용한다 (Evidence: E4).

### equals/hashCode 계약

HashSet, HashMap에서 요소나 키로 사용하는 객체는 다음 계약을 충족해야 한다 (Evidence: E5).

1. **`equals()`가 `true`이면, `hashCode()`도 같은 값을 반환해야 한다** (필수)
2. `hashCode()`가 같아도 `equals()`가 `false`인 경우는 있을 수 있다 (충돌)
3. `equals()`는 반사적, 대칭적, 추이적, 일관성이 있어야 한다

```java
public class Employee {
    private final String id;
    private final String name;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Employee e)) return false;
        return id.equals(e.id);
    }

    @Override
    public int hashCode() {
        return id.hashCode();
    }
}
```

### Collections 유틸리티 클래스

`java.util.Collections`는 컬렉션 조작을 위한 static 메서드를 제공한다 (Evidence: E6).

```java
Collections.sort(list);                    // 정렬
Collections.unmodifiableList(list);        // 불변 뷰
Collections.synchronizedList(list);        // 동기화 래퍼
Collections.emptyList();                   // 빈 불변 리스트
Collections.singletonList(item);           // 1요소 불변 리스트
```

### 불변 컬렉션 (Java 9 이후)

Java 9 이후, `List.of()`, `Set.of()`, `Map.of()`로 불변 컬렉션을 생성할 수 있다 (Evidence: E7).

```java
List<String> list = List.of("a", "b", "c");       // 불변 List
Set<Integer> set = Set.of(1, 2, 3);                // 불변 Set
Map<String, Integer> map = Map.of("a", 1, "b", 2); // 불변 Map
```

불변 컬렉션에 대한 `add()`, `remove()` 등의 변경 조작은 `UnsupportedOperationException`을 throw한다.

## 3) 예제 (2개)

### 예제 1: List, Set, Map의 기본 조작

각 컬렉션 타입의 기본적인 생성, 추가, 검색 조작을 보여준다 (Evidence: E2, E3, E4).

```java
import java.util.*;

public class CollectionBasics {

    public static void main(String[] args) {
        // === List: 순서 있음, 중복 허용 ===
        List<String> names = new ArrayList<>();
        names.add("Alice");
        names.add("Bob");
        names.add("Alice");  // 중복 OK
        System.out.println("List: " + names);       // [Alice, Bob, Alice]
        System.out.println("get(1): " + names.get(1)); // Bob

        // === Set: 중복 없음 ===
        Set<String> uniqueNames = new LinkedHashSet<>(names);
        System.out.println("Set: " + uniqueNames);  // [Alice, Bob] (삽입 순서 유지)

        // TreeSet으로 정렬
        Set<String> sorted = new TreeSet<>(names);
        System.out.println("TreeSet: " + sorted);   // [Alice, Bob]

        // === Map: 키-값 쌍 ===
        Map<String, Integer> scores = new HashMap<>();
        scores.put("Alice", 90);
        scores.put("Bob", 85);
        scores.put("Alice", 95);  // 키 중복 → 값 덮어쓰기
        System.out.println("Map: " + scores);        // {Alice=95, Bob=85}
        System.out.println("Alice: " + scores.get("Alice")); // 95

        // === 불변 컬렉션 ===
        List<String> immutable = List.of("x", "y", "z");
        // immutable.add("w");  // UnsupportedOperationException!
    }
}
```

List는 중복을 허용하고, Set은 중복을 제거한다. Map의 put으로 같은 키를 사용하면 값이 덮어써진다. `List.of()`로 생성한 불변 컬렉션은 변경 불가이다.

### 예제 2: equals/hashCode 계약의 중요성

`hashCode()`를 올바르게 구현하지 않으면 HashSet/HashMap에서 기대대로 동작하지 않음을 보여준다 (Evidence: E5).

```java
import java.util.*;

class Product {
    private final String code;
    private final String name;

    Product(String code, String name) {
        this.code = code;
        this.name = name;
    }

    // equals만 구현, hashCode를 구현하지 않은 경우의 문제를 보여줌
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Product p)) return false;
        return code.equals(p.code);
    }

    // hashCode를 구현하지 않으면 HashSet에서 같은 요소가 중복됨
    // @Override
    // public int hashCode() { return code.hashCode(); }
}

class ProductFixed {
    private final String code;
    private final String name;

    ProductFixed(String code, String name) {
        this.code = code;
        this.name = name;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof ProductFixed p)) return false;
        return code.equals(p.code);
    }

    @Override
    public int hashCode() {
        return code.hashCode();  // equals와 정합적
    }
}

public class EqualsHashCodeDemo {
    public static void main(String[] args) {
        // hashCode 미구현 → 같은 code인데 Set에 2개 들어감
        Set<Product> broken = new HashSet<>();
        broken.add(new Product("A001", "Widget"));
        broken.add(new Product("A001", "Widget"));
        System.out.println("깨진 Set size: " + broken.size()); // 2 (기대는 1)

        // hashCode 구현 완료 → 올바르게 중복 제거
        Set<ProductFixed> fixed = new HashSet<>();
        fixed.add(new ProductFixed("A001", "Widget"));
        fixed.add(new ProductFixed("A001", "Widget"));
        System.out.println("올바른 Set size: " + fixed.size());  // 1
    }
}
```

`Product`는 `equals()`만 구현하고 `hashCode()`를 구현하지 않았기 때문에, HashSet이 같은 객체를 중복으로 검출하지 못한다. `ProductFixed`에서는 양쪽을 올바르게 구현하고 있어 기대대로 동작한다.

## 4) 흔한 실수 / 함정 (5개)

### 1. equals()만 구현하고 hashCode()를 구현하지 않음

```java
// NG: hashCode가 Object.hashCode() 그대로
class Item {
    String id;
    @Override public boolean equals(Object o) { ... }
    // hashCode()가 없다!
}
```

HashSet, HashMap은 먼저 hashCode로 버킷을 결정하고, 다음으로 equals로 비교한다. hashCode가 다르면 equals가 호출되지 않으므로, 중복 검출이 기능하지 않는다 (Evidence: E5).

### 2. 불변 컬렉션에 대한 변경 조작

```java
// NG: UnsupportedOperationException
List<String> list = List.of("a", "b");
list.add("c");  // 실행 시 에러!
list.set(0, "x");  // 실행 시 에러!

// OK: 변경 가능한 리스트로 변환
List<String> mutable = new ArrayList<>(List.of("a", "b"));
mutable.add("c");  // OK
```

`List.of()` 등으로 생성한 불변 컬렉션은 변경 조작에서 `UnsupportedOperationException`을 throw한다 (Evidence: E7).

### 3. TreeSet에 Comparable이 아닌 객체를 추가

```java
// NG: ClassCastException
Set<Object> set = new TreeSet<>();
set.add(new Object());  // Object는 Comparable을 구현하지 않음

// OK: Comparator를 지정하거나 Comparable을 구현
Set<String> set = new TreeSet<>();  // String은 Comparable
set.add("hello");
```

TreeSet은 요소의 자연 순서(Comparable) 또는 Comparator로 정렬하므로, 어느 쪽도 제공하지 않으면 ClassCastException이 발생한다 (Evidence: E3).

### 4. 이터레이션 중 컬렉션 변경

```java
// NG: ConcurrentModificationException
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
for (String s : list) {
    if (s.equals("b")) {
        list.remove(s);  // 실행 시 에러!
    }
}

// OK: Iterator의 remove 사용
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().equals("b")) {
        it.remove();  // 안전
    }
}
```

확장 for문에서의 이터레이션 중에 컬렉션을 직접 변경하면 `ConcurrentModificationException`이 발생한다 (Evidence: E2).

### 5. Map.of()에서 키 중복

```java
// NG: IllegalArgumentException — 키 중복
Map<String, Integer> map = Map.of("a", 1, "a", 2);

// OK: 중복 키가 없음
Map<String, Integer> map = Map.of("a", 1, "b", 2);
```

`Map.of()`에서 키가 중복되면 컴파일 시가 아닌 실행 시에 `IllegalArgumentException`이 throw된다 (Evidence: E7).
