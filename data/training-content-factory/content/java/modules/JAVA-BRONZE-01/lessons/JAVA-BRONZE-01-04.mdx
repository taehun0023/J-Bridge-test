## 1) 要点まとめ（5行）

- `if/else if/else` は最も基本的な条件分岐であり、boolean式に基づいて実行パスを決定する。(Evidence: E1)
- 三項演算子 `条件 ? 値A : 値B` は単純な if/else を1行で書ける便利な記法だが、可読性を損なわない範囲で使用すべきである。(Evidence: E2)
- `switch` 文は1つの値を複数の定数と比較する場合に適しており、使用可能な型は `byte`, `short`, `char`, `int`, `String`, `enum` である。(Evidence: E3)
- `switch` 文では `break` を省略するとフォールスルー（次のcaseへの落下）が発生するため注意が必要である。(Evidence: E4)
- Java 14以降の `switch` 式（アロー構文 `->` + `yield`）はフォールスルーが発生せず、値を返すことができる。(Evidence: E5)

## 2) 概念

### if / else if / else

✅ 結論: boolean条件に基づいて処理を分岐する最も基本的な制御構文。

```java
if (条件1) {
    // 条件1がtrueの場合
} else if (条件2) {
    // 条件1がfalse かつ 条件2がtrueの場合
} else {
    // すべての条件がfalseの場合
}
```

(Evidence: E1)

```java
int score = 85;
if (score >= 90) {
    System.out.println("優秀");
} else if (score >= 70) {
    System.out.println("合格");   // ← これが出力される
} else {
    System.out.println("不合格");
}
```

⚠️ 条件式の評価は上から順に行われ、最初にtrueになった分岐のみが実行される。

### if文の注意点: ブレースの省略

✅ 結論: ブレースは省略可能だが、必ず付けるのが実務の推奨。

```java
// ブレースなし（1文のみの場合は文法的に有効）
if (x > 0)
    System.out.println("positive");

// 危険なパターン: 2文目はif文に属さない
if (x > 0)
    System.out.println("positive");
    System.out.println("always executed");  // インデントに騙される！常に実行される
```

💡 実務ルール: たとえ1文でもブレース `{}` を付ける。バグ防止のベストプラクティス。

### 三項演算子（条件演算子）

✅ 結論: 単純な if/else を1つの式で書ける。

```java
// 構文: 条件 ? trueの場合の値 : falseの場合の値
String result = (score >= 60) ? "合格" : "不合格";
```

(Evidence: E2)

三項演算子は**式**であるため、変数の初期化やメソッドの引数に直接使用できる。

```java
System.out.println("結果: " + ((score >= 60) ? "合格" : "不合格"));
```

⚠️ ネストした三項演算子は可読性が著しく低下するため避ける。

```java
// 悪い例（読みにくい）
String grade = (s >= 90) ? "A" : (s >= 80) ? "B" : (s >= 70) ? "C" : "D";

// 良い例: if/else if を使う
```

### switch文

✅ 結論: 1つの値を複数の定数と比較するときに使用する。

```java
switch (式) {
    case 定数1:
        // 処理1
        break;
    case 定数2:
        // 処理2
        break;
    default:
        // どのcaseにも一致しない場合
        break;
}
```

(Evidence: E3)

使用可能な型: `byte`, `short`, `char`, `int`, `String`（Java 7以降）, `enum`

```java
String day = "MON";
switch (day) {
    case "MON":
    case "TUE":
    case "WED":
    case "THU":
    case "FRI":
        System.out.println("平日");
        break;
    case "SAT":
    case "SUN":
        System.out.println("休日");
        break;
    default:
        System.out.println("不明");
        break;
}
```

### フォールスルー

✅ 結論: breakを省略すると次のcaseに「落ちて」しまう。

```java
int num = 1;
switch (num) {
    case 1:
        System.out.println("One");
        // break がない！フォールスルー発生
    case 2:
        System.out.println("Two");
        break;
    case 3:
        System.out.println("Three");
        break;
}
```

出力: `One` と `Two` の両方が表示される。(Evidence: E4)

💡 覚え方: `break` = 脱出。なければ下に落ちる。

### switch式（Java 14以降）

✅ 結論: アロー構文でフォールスルーを防止し、値を返せる。

```java
String day = "MON";
String type = switch (day) {
    case "MON", "TUE", "WED", "THU", "FRI" -> "平日";
    case "SAT", "SUN" -> "休日";
    default -> "不明";
};
System.out.println(type);  // 平日
```

(Evidence: E5)

アロー構文 `->` の特徴:
- `break` 不要（フォールスルーが発生しない）
- カンマ `,` で複数の値をまとめられる
- 式全体が**値を返す**ことができる

複数行の処理が必要な場合は `yield` で値を返す:

```java
int score = 85;
String grade = switch (score / 10) {
    case 10, 9 -> "A";
    case 8 -> "B";
    case 7 -> "C";
    default -> {
        System.out.println("60点未満も含む");
        yield "D";
    }
};
```

### パターンマッチング（プレビュー機能）

✅ 結論: Java 17以降、switchでの型判定が簡潔に書ける（プレビュー）。

```java
// Java 17+ (プレビュー機能)
Object obj = "Hello";
String result = switch (obj) {
    case Integer i -> "整数: " + i;
    case String s  -> "文字列: " + s;
    case null      -> "null";
    default        -> "その他";
};
```

⚠️ プレビュー機能はJavaのバージョンによって利用可能かどうかが異なる。Bronze試験では従来のswitch文・switch式が中心となる。

### if vs switch の使い分け

✅ 結論: 単一値の等値比較にはswitch、範囲・複合条件にはif。

| 場面 | 推奨 |
|---|---|
| 単一の値と複数の定数を比較 | `switch` |
| 範囲による条件（`score >= 90`） | `if/else if` |
| 複合条件（`&&`, `\|\|`） | `if/else if` |
| 値を返す分岐 | `switch` 式 (Java 14+) |

## 3) 例（2つ）

### 例1: 月の日数を判定する

switch文を使って月の日数を返す例。フォールスルーの活用も示す。

```java
public class MonthDays {
    public static int getDays(int month, boolean isLeapYear) {
        return switch (month) {
            case 1, 3, 5, 7, 8, 10, 12 -> 31;
            case 4, 6, 9, 11 -> 30;
            case 2 -> isLeapYear ? 29 : 28;
            default -> throw new IllegalArgumentException("無効な月: " + month);
        };
    }

    public static void main(String[] args) {
        System.out.println("1月: " + getDays(1, false) + "日");
        System.out.println("2月(通常): " + getDays(2, false) + "日");
        System.out.println("2月(閏年): " + getDays(2, true) + "日");
        System.out.println("4月: " + getDays(4, false) + "日");
    }
}
```

出力結果:

```
1月: 31日
2月(通常): 28日
2月(閏年): 29日
4月: 30日
```

ポイント:
- switch式（Java 14+）のアロー構文により、`break` が不要でフォールスルーも発生しない
- カンマ `,` で複数のcaseラベルをまとめることで、コードが簡潔になる
- 三項演算子と組み合わせて、2月の閏年判定も1行で記述できる

### 例2: 年齢に応じた料金判定（if/else if）

複数の範囲条件で料金を判定する例。switch文ではなくif/else ifが適切なケース。

```java
public class FareCalculator {
    public static String getFareCategory(int age) {
        if (age < 0) {
            return "エラー: 無効な年齢";
        } else if (age < 6) {
            return "無料";
        } else if (age < 12) {
            return "子供料金";
        } else if (age < 65) {
            return "大人料金";
        } else {
            return "シニア料金";
        }
    }

    public static void main(String[] args) {
        int[] ages = {3, 8, 30, 70};
        for (int age : ages) {
            System.out.println(age + "歳: " + getFareCategory(age));
        }
    }
}
```

出力結果:

```
3歳: 無料
8歳: 子供料金
30歳: 大人料金
70歳: シニア料金
```

ポイント:
- 範囲による条件判定では `if/else if` が適切（switchは定数との等値比較に使う）
- 条件は上から順に評価されるため、`age < 12` の時点で `age < 6` は既にfalseであることが保証される
- `return` を使うことで `break` や余計なネストを避けられる（早期リターンパターン）

## 4) よくあるミス／落とし穴（5つ）

⚠️ ミス: switch文で `break` を書き忘れてフォールスルーする → 対策: switch式（アロー構文）を使うか、各caseに必ず `break` を書く

⚠️ ミス: if文のブレースを省略して2文目がif外になる → 対策: たとえ1文でも必ずブレース `{}` を付ける

⚠️ ミス: `==` で String を比較する（`if (str == "hello")`） → 対策: String の比較には `.equals()` を使う。`if (str.equals("hello"))` または `if ("hello".equals(str))` で null安全に

⚠️ ミス: switch文で `long` や `boolean` を使おうとする → 対策: switch文で使用可能な型は `byte`, `short`, `char`, `int`, `String`, `enum` のみ

⚠️ ミス: else if の条件を網羅できず、想定外の入力でどの分岐にも入らない → 対策: 最後に `else` / `default` を必ず書く。防御的プログラミングを心がける
