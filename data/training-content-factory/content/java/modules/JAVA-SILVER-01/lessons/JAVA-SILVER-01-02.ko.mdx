## 1) 요점 정리 (5줄)

- 생성자는 클래스명과 동일한 이름의 메서드이며, 반환 타입을 가지지 않는다. `new` 시에 자동으로 호출되어 객체 초기화를 수행한다. (Evidence: E1)
- 명시적으로 생성자를 하나도 정의하지 않으면 컴파일러가 인수 없는 **디폴트 생성자**를 자동 생성한다. 하나라도 정의하면 자동 생성되지 않는다. (Evidence: E2)
- 생성자 오버로딩으로 서로 다른 인수 패턴의 유연한 초기화를 제공할 수 있다. (Evidence: E3)
- `this` 키워드는 "자기 자신의 인스턴스"에 대한 참조이다. 필드와 파라미터 이름이 같을 때의 구분이나 생성자 체이닝에 사용한다. (Evidence: E4)
- `this()`에 의한 생성자 체이닝은 **생성자의 첫 번째 줄**에서만 호출 가능하다. 초기화 블록은 생성자보다 먼저 실행된다. (Evidence: E5)

## 2) 개념

### 생성자의 기본

✅ 결론: 생성자는 객체 생성 시 자동 호출되는 초기화 처리이다.

생성자는 클래스명과 동일하며, 반환 타입(`void` 포함)을 기술하지 않는다. `new` 연산자에 의한 인스턴스 생성 시 자동으로 호출된다. (Evidence: E1)

```java
public class Employee {
    private String name;
    private int age;

    // 생성자 (클래스명과 동일, 반환 타입 없음)
    public Employee(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

⚠️ 주의: 생성자에 반환 타입을 적으면 **일반 메서드**로 취급된다. `void Employee()`는 생성자가 아니라 메서드이다.

### 디폴트 생성자

✅ 결론: 명시적 생성자가 0개인 경우에만 자동 생성된다.

클래스에 생성자를 하나도 정의하지 않으면 컴파일러가 인수 없는, 처리 없는 디폴트 생성자를 자동 생성한다. 단, 하나라도 명시적으로 정의하면 디폴트 생성자는 생성되지 않는다. (Evidence: E2)

```java
// 디폴트 생성자가 자동 생성됨
public class A {
    // 생성자 없음 -> 컴파일러가 A()를 생성
}

// 디폴트 생성자는 생성되지 않음
public class B {
    public B(String s) { }
    // new B()는 컴파일 에러
}
```

### 생성자 오버로딩

✅ 결론: 인수 리스트가 다른 복수의 생성자를 정의할 수 있다.

메서드 오버로딩과 마찬가지로, 인수의 수나 타입이 다른 생성자를 여러 개 정의할 수 있다. 용도에 맞는 유연한 초기화가 가능해진다. (Evidence: E3)

```java
public class Employee {
    private String name;
    private int age;
    private String department;

    // 전체 인수 생성자
    public Employee(String name, int age, String department) {
        this.name = name;
        this.age = age;
        this.department = department;
    }

    // 이름만의 생성자
    public Employee(String name) {
        this(name, 0, "未配属");  // 생성자 체이닝
    }

    // 인수 없는 생성자
    public Employee() {
        this("未設定");  // 생성자 체이닝
    }
}
```

### this 키워드

✅ 결론: this는 "현재 인스턴스"에 대한 참조이다.

`this`는 주로 다음 2가지 용도로 사용한다. (Evidence: E4)

**용도 1: 필드와 파라미터 구분**

파라미터명이 필드명과 같을 때, `this.필드명`으로 필드를 참조한다.

```java
public void setName(String name) {
    this.name = name;  // this.name = 필드, name = 파라미터
}
```

**용도 2: 생성자 체이닝**

`this(인수)`로 동일 클래스의 다른 생성자를 호출한다. 초기화 로직의 중복을 피하기 위해 사용한다.

```java
public Employee(String name) {
    this(name, 0, "未配属");  // 3인수 생성자를 호출
}
```

### this()의 제약

✅ 결론: this()는 생성자의 첫 번째 줄에서만 사용 가능하다.

`this()` 호출은 생성자의 **첫 번째 문장**이어야 한다. 첫 번째 줄 이외에서 호출하면 컴파일 에러가 된다. 또한 `this()`와 `super()`를 동일 생성자 내에서 동시에 호출할 수 없다. (Evidence: E5)

### 초기화 블록

✅ 결론: 인스턴스 초기화 블록은 생성자보다 먼저 실행된다.

인스턴스 초기화 블록(`{ }`으로 둘러싼 블록)은 생성자가 호출되기 전에 실행된다. 여러 생성자에서 공통적인 초기화 처리를 기술하는 데 사용할 수 있다. (Evidence: E5)

```java
public class Config {
    private List<String> settings;

    // 인스턴스 초기화 블록
    {
        settings = new ArrayList<>();
        settings.add("default");
    }

    public Config() {
        // settings는 이미 초기화 완료
    }
}
```

실행 순서: (1) 필드 초기화식 -> (2) 인스턴스 초기화 블록 (기술 순) -> (3) 생성자

### 복사 생성자 패턴

✅ 결론: 기존 인스턴스의 필드 값을 복제하는 전용 생성자이다.

복사 생성자는 같은 클래스의 인스턴스를 인수로 받아 그 필드 값을 복사하여 새 인스턴스를 생성하는 패턴이다. (Evidence: E3)

```java
public class Employee {
    private String name;
    private int age;

    // 복사 생성자
    public Employee(Employee other) {
        this.name = other.name;
        this.age = other.age;
    }
}
```

## 3) 예제 (2개)

### 예제 1: 생성자 오버로딩과 this 체이닝

```java
public class Book {
    private String title;
    private String author;
    private int price;
    private String isbn;

    // 메인 생성자 (모든 필드 초기화)
    public Book(String title, String author, int price, String isbn) {
        this.title = title;
        this.author = author;
        this.price = price;
        this.isbn = isbn;
    }

    // 제목과 저자만 (가격 0, ISBN 없음)
    public Book(String title, String author) {
        this(title, author, 0, "N/A");
    }

    // 제목만
    public Book(String title) {
        this(title, "不明");
    }

    public String getInfo() {
        return title + " / " + author + " / " + price + "円";
    }
}
```

```java
public class Main {
    public static void main(String[] args) {
        Book b1 = new Book("Java入門", "山田太郎", 2800, "978-4-xxx");
        Book b2 = new Book("Python入門", "鈴木花子");
        Book b3 = new Book("C言語の基礎");

        System.out.println(b1.getInfo());  // Java入門 / 山田太郎 / 2800円
        System.out.println(b2.getInfo());  // Python入門 / 鈴木花子 / 0円
        System.out.println(b3.getInfo());  // C言語の基礎 / 不明 / 0円
    }
}
```

포인트:
- `this()`를 사용한 체이닝으로 초기화 로직이 메인 생성자에 집약된다.
- 오버로딩으로 필요한 인수의 수에 맞는 유연한 인스턴스 생성이 가능하다.

### 예제 2: 디폴트 생성자가 생성되지 않는 케이스

```java
public class Sensor {
    private String type;
    private double value;

    // 파라미터 있는 생성자만 정의
    public Sensor(String type) {
        this.type = type;
        this.value = 0.0;
    }

    public String getType() { return type; }
    public double getValue() { return value; }
}
```

```java
public class Main {
    public static void main(String[] args) {
        Sensor s1 = new Sensor("温度");   // OK
        // Sensor s2 = new Sensor();      // 컴파일 에러!

        // 디폴트 생성자는 자동 생성되지 않음
        // 인수 없이도 인스턴스화하려면 명시적 정의가 필요:
        // public Sensor() { this("不明"); }
    }
}
```

포인트:
- `Sensor(String type)`을 정의했으므로 컴파일러는 디폴트 생성자를 생성하지 않는다.
- `new Sensor()`로 호출하면 컴파일 에러가 된다. 인수 없는 생성자가 필요하면 명시적으로 정의해야 한다.

## 4) 흔한 실수 / 함정 (5개)

⚠️ 실수: 생성자에 반환 타입(`void` 포함)을 기술하여 일반 메서드가 되어버린다 → 대책: 생성자는 반환 타입을 절대 쓰지 않는다. `void Employee()`는 생성자가 아님 (Evidence: E1)

⚠️ 실수: 파라미터 있는 생성자를 정의한 후 `new ClassName()`을 사용할 수 없게 되는 것을 모른다 → 대책: 인수 없는 생성자가 필요하면 명시적으로 정의한다 (Evidence: E2)

⚠️ 실수: `this()`를 생성자의 첫 번째 줄 이외에서 호출한다 → 대책: `this()`는 반드시 생성자의 첫 번째 문장에 기술한다 (Evidence: E5)

⚠️ 실수: `this`를 붙이지 않고 필드와 파라미터의 동명 변수를 사용하여 파라미터가 우선되어 의도하지 않은 동작이 된다 → 대책: 동명인 경우 반드시 `this.필드명`으로 명시적으로 필드를 참조한다 (Evidence: E4)

⚠️ 실수: 생성자 체이닝에서 순환 호출을 만든다 → 대책: `this()` 호출이 순환하지 않도록, 최종적으로 `this()`를 포함하지 않는 생성자에 도달하게 한다 (순환은 컴파일 에러) (Evidence: E5)
